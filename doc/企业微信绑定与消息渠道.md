# 企业微信绑定与消息渠道

## 企业微信后台配置

自建应用使用企业 ID（CorpId）、AgentId 和应用 Secret。网页授权 URL 中的 `appid` 参数填写 CorpId，不需要另外申请应用 AppID。

- 系统入口：`https://sxxt.cdjcc.edu.cn/`
- 网页授权回调：`https://sxxt.cdjcc.edu.cn/api/wechat/oauth/callback`
- 应用接收消息回调：`https://sxxt.cdjcc.edu.cn/api/wechat/callback`
- 网页授权可信域名：`sxxt.cdjcc.edu.cn`

网页授权可信域名与接收消息 URL 是不同配置。请在自建应用的网页授权设置中配置可信域名，并保证老师、学生处于应用可见范围。外部联系人或未加入企业的访问者可能仅返回 OpenId，不能作为企业成员接收应用消息，本系统对此拒绝绑定。

## 绑定入口

企业微信内登录老师或学生账号后，系统自动进行网页授权，读取企业成员 UserId。未绑定时显示当前系统账号和确认按钮，确认绑定后继续使用；已经绑定且身份一致时直接进入。管理员跳过绑定要求。普通浏览器和桌面客户端可以正常登录，在企业微信中完成绑定后即可接收推送。

每个系统用户最多绑定一个企业成员，每个企业成员最多绑定一个系统用户。同一个用户的多个登录角色共用绑定；通知开关和接收时段按登录账号分别保存。

OAuth state 有效期 10 分钟，只能使用一次，并核对学校、当前浏览器和企业配置。确认绑定凭证有效期 10 分钟，只能使用一次；当前浏览器的企业身份有效期 1 小时。凭证使用 HttpOnly Cookie，URL 不包含绑定凭证、UserId、Secret 或 access_token。

用户管理列表的“企业微信”列直接显示绑定状态，点击可打开绑定详情；也可从“操作 → 企业微信绑定 / 解绑”进入。超级管理员、学校管理员在该详情内解除绑定。解绑会删除当前关联并写入操作日志；不会删除用户、账号或历史消息。需要换角色验证绑定时，先解绑，再在企业微信内退出当前系统账号、登录目标老师或学生账号，重新获取企业身份并确认绑定。若多个角色属于同一系统用户，解绑对这些角色同时生效。

## 消息渠道

消息中心手动发送、消息中心模板编辑和模板库的流程模板编辑均可勾选企业微信。站内消息始终保留，默认仅发送站内消息；已有模板不会自动开启企业微信。

只有账号和用户启用、绑定有效、绑定企业与当前配置一致、企业微信通知开关开启时，才投递企业微信。应用访问凭证按学校与企业应用配置缓存。Secret 变更后不会继续复用旧配置的缓存。

应用消息使用文本格式，超过企业微信 2048 字节限制时截取 UTF-8 文本并提示查看站内完整内容。合法 HTTP/HTTPS 完整链接会附在正文；站内页面片段提示从系统消息中心查看。

## 接收时段

PC 个人设置、H5“我的”可以设置企业微信通知开关和允许接收时间。

- 默认全天：`00:00–24:00`。
- 日间示例：`08:00–22:00`，22:00 后的消息顺延至次日 08:00。
- 跨午夜示例：`22:00–07:00`，07:00 后的消息顺延至当天 22:00。

使用服务器 `Asia/Shanghai` 时区，包含开始时间、不包含结束时间。时间段外的企业微信消息保留待发送状态，到允许时间后投递；站内消息立即显示。每次实际投递前重新读取绑定和偏好。关闭企业微信通知或已解除绑定时，尚未发送的消息记为跳过。

待发送消息保存了原定下一投递时间。修改时段不会主动扫描并提前全部待发送任务；任务到达原定时间后按最新设置重新判断。

## 部署

1. 更新代码和已构建的 `server/public/pc`、`server/public/h5`。
2. 在每个学校业务库执行 `server/database/updates/20260922-wechat-message.sql`。脚本可重复执行。完整数据库初始化流程也已包含相同字段升级。
3. 重启 Webman，加载新增 `wechat_message_relay` 进程和 `wechat-message` 队列消费者。仅刷新网页不足以加载新后台进程。
4. 在应用后台配置网页授权可信域名和应用可见范围。

企业微信渠道日志使用 `message_channel_log`：

| 状态 | 含义 |
| --- | --- |
| pending | 待分发、等待允许时间或等待重试 |
| sent | 企业微信接口确认接受 |
| skipped | 未绑定、通知关闭、账号停用或企业配置不匹配 |
| failed | 无效成员、无应用许可或不可重试的参数错误 |

`error_message` 保存错误原因或企业微信错误码，`available_at` 表示下一次允许处理时间。`sent` 表示接口接受，不表示手机已展示或用户已读。

## 队列运行

站内消息与企业微信待发送记录在同一数据库事务提交。后台每 5 秒分批将已提交且到期的记录送入现有 RedisQueue，队列只携带学校库和投递记录 ID。Redis 不可用时记录保留，恢复后继续分发；临时接口错误按退避时间重试。队列重复消费时，已完成记录不会再次发送。

远端接口已接受、本地成功状态落库前进程崩溃时，恢复后可能重复投递。这是至少一次投递的边界。

当前继续使用 RedisQueue，无需新增 MQ。关注 Redis 内存、淘汰次数、队列积压、最老待发送记录时间和渠道错误码；导出队列保存任务标识而非文件内容。若导出与消息任务互相抢占消费者，可先拆分 Redis 实例和消费者进程，独立分配并发；有稳定高吞吐、多系统订阅或严格消息回放需求时再评估独立 MQ。
