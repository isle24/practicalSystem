# H5 原生应用重构设计

## 1. 目标

将 H5 前端重构为平台中性的高校实践业务 App，并采用接近 iPhone 的操作反馈和页面转场。

本次重构目标：

- 降低 `App.vue` 的职责和代码体积。
- 统一按钮、状态、列表、弹层、表单和反馈方式。
- 保持学生、教师、管理员的角色差异。
- 保持现有接口、权限判断和业务流程不变。
- 实习、实训、实验模块复用公共能力，避免重复实现。
- 达到低冗余、低耦合、高内聚的维护目标。

## 2. 设计原则

1. 业务状态与视觉表现分离，状态名称和语义颜色由中央配置维护。
2. 页面组件不直接拼装 API 请求，数据请求和状态管理放入对应 composable。
3. 公共组件只处理底层展示和交互，不包含具体业务规则。
4. 一个页面只负责一个明确层级，列表、详情和长表单不混在同一视图中。
5. 每个操作区域只突出一个主要动作，危险操作必须与普通操作区分。
6. 不新增自定义边缘滑动手势，使用浏览器和系统已有返回操作。
7. 不修改 Webman 框架、后端默认路由和现有 API 契约。

## 3. 前端分层

### 3.1 应用入口

`fontend/h5/src/App.vue` 只保留：

- 登录态初始化。
- 全局页面容器。
- 一级导航状态。
- 全局错误入口。
- 页面转场容器。
- 底部导航。

入口组件不得继续包含实习、实训、实验的表单和列表实现。

### 3.2 页面层

新增 `fontend/h5/src/pages/`：

```text
pages/
├── LoginPage.vue
├── HomePage.vue
├── MessagePage.vue
├── ProfilePage.vue
├── DocumentPage.vue
├── TemplatePage.vue
├── InternshipPage.vue
└── PracticePage.vue
```

`PracticePage.vue` 同时承载实训和实验，通过 `moduleType` 读取对应配置，不复制两套页面。

### 3.3 业务功能层

新增 `fontend/h5/src/features/`：

```text
features/
├── internship/
│   ├── InternshipOverview.vue
│   ├── InternshipTaskList.vue

```

业务功能组件只消费对应 composable 提供的数据和方法，不读取其他模块的内部状态。

### 3.4 公共组件层

新增 `fontend/h5/src/components/ui/`：

```text
components/ui/
├── AppButton.vue
├── AppIconButton.vue
├── AppStatusBadge.vue

```

公共组件只公开视觉、布局和基础交互能力，不包含提交、审核、签到等业务逻辑。

### 3.5 状态与请求层

新增或拆分以下 composable：

```text
composables/
├── useAuthSession.js
├── useMobileNavigation.js
├── useMessageCenter.js
├── useInternship.js
└── usePracticeModule.js
```

职责要求：

- `useAuthSession`：登录、退出、身份切换、权限上下文。
- `useMobileNavigation`：一级 Tab、二级页面栈、转场方向、系统返回。
- `useMessageCenter`：消息列表、未读数量、筛选、已读操作。
- `useInternship`：实习状态、列表、表单和现有业务请求。
- `usePracticeModule`：实验和实训的公共状态、列表、执行和审核请求。

API 文件保持为请求边界，页面和展示组件不得直接调用 `fetch`。

## 4. 页面层级

### 4.1 一级页面

底部导航固定承载：

- 首页。
- 实习。
- 实训。
- 实验。
- 我的。

模块是否可见继续由角色权限控制。

### 4.2 模块内部导航

实习模块根据角色显示：

- 学生：概况、任务、提交、成绩。
- 教师：概况、审核、成绩。
- 管理员：概况、审核、数据。

实验和实训继续按现有角色权限显示对应面板。同级面板统一使用 `AppSegmented`，不再由各模块分别定义 Tab 样式。

### 4.3 二级页面

以下内容进入独立二级页面：

- 列表详情。
- 日志和报告编辑。
- 长表单提交。
- 成绩录入。
- 流程记录。
- 文档详情。

筛选、简短确认和审核意见使用底部弹层。列表页面不得常驻长表单。

## 5. 按钮规范

`AppButton` 只提供以下类型：

| 类型 | 用途 | 视觉 |
|---|---|---|
| primary | 当前区域唯一主要动作 | 主色实底 |
| secondary | 保存草稿、取消、次要提交 | 浅色或描边 |
| quiet | 查看、记录、辅助操作 | 文字或弱背景 |
| danger | 删除、作废、拒绝等危险操作 | 危险色 |
| icon | 返回、关闭、搜索等熟悉操作 | 仅图标并带可访问名称 |

统一规则：

- 可点击区域不小于 `44px`。
- 圆角统一为 `8px`。
- 加载时显示统一进度反馈并禁止重复点击。
- 禁用态不响应按压动画。
- 同一操作区最多一个 `primary`。
- 熟悉操作优先使用 Lucide 图标，不重复绘制 SVG。
- 危险操作必须二次确认。

## 6. 状态规范

新增 `fontend/h5/src/constants/status.js`，输出状态名称、语义和显示顺序。

| 语义 | 状态代码 | 颜色用途 |
|---|---|---|
| neutral | draft、disabled、removed、skipped、not_required | 未提交、停用或无须处理 |
| info | wait、pending、changing | 等待处理或处理中 |
| warning | modify、incomplete、missing | 需要用户继续处理 |
| success | accept、enabled、active、signed、published、confirmed、completed、changed、complete、archived、pass | 已完成或有效 |
| danger | refuse、fail | 已退回、不通过或失败 |

`AppStatusBadge` 根据状态代码读取中央配置。页面不得自行维护状态名称、颜色或重复映射。

状态在列表卡片标题区域显示，操作按钮不得替代状态展示。未知状态显示原始值并使用 `neutral`，避免页面渲染失败。

## 7. 列表与表单

### 7.1 列表

`AppListCard` 固定结构：

1. 标题和状态。
2. 一至三条关键信息。
3. 时间、人员等次要信息。
4. 底部操作区。

学生、教师和管理员使用同一组件，通过字段配置和操作配置呈现不同内容。列表操作由业务模块计算后传入，公共组件不判断角色。

### 7.2 表单

- 字段标签、必填标记、帮助文本和错误文本使用统一布局。
- 字段错误显示在字段附近。
- 长表单使用二级全屏页面。
- 表单底部使用 `AppActionBar` 固定操作区。
- 提交、审核等关键操作等待服务端结果，不做可能产生错误状态的乐观更新。
- 页面离开或弹层关闭时清理临时表单和请求状态。

## 8. 动效规范

动效保持平台中性，节奏接近 iPhone，不增加自定义滑动手势。

| 场景 | 时长 | 方式 |
|---|---:|---|
| 一级 Tab 切换 | 180ms | 淡入并轻微上移 |
| 进入详情或表单 | 280ms | 从右侧推入 |
| 返回上一级 | 240ms | 反向退出 |
| 底部弹层 | 300ms | 遮罩渐入，内容克制弹性上移 |
| 按钮按下 | 90ms | 缩放到 0.97 |
| 按钮恢复 | 160ms | 平滑恢复到 1 |
| 状态变化 | 180ms | 颜色和透明度过渡 |

统一缓动变量放入 `styles/motion.css`。禁止闪烁、抖动、持续弹跳和滚动期间的大量卡片动画。

系统启用 `prefers-reduced-motion` 时：

- 关闭推入和缩放动画。
- 保留必要的透明度切换。
- 将过渡时长缩短到接近即时反馈。

## 9. 视觉样式

样式拆分为：

```text
styles/
├── tokens.css
├── base.css
├── motion.css
├── forms.css
└── utilities.css
```

- `tokens.css`：颜色、字号、间距、圆角、阴影、层级。
- `base.css`：页面、字体、安全区域和基础控件。
- `motion.css`：转场、按压和减少动态效果。
- `forms.css`：字段、校验和固定操作栏。
- `utilities.css`：少量通用布局类。

页面和公共组件使用局部样式。禁止继续依赖大范围后代选择器覆盖其他组件。

视觉约束：

- 卡片圆角不超过 `8px`。
- 页面使用白色、浅灰、主色、成功色、警告色和危险色形成明确层级。
- 不使用单一色系覆盖全部状态。
- 紧凑业务页面使用适当字号，不使用营销页面式大标题。
- 固定导航、操作栏和弹层必须处理安全区域。
- 文本和操作不得发生遮挡或横向溢出。

## 10. 反馈与异常

- 普通成功结果使用轻量 Toast。
- 字段校验失败显示在对应字段附近。
- 页面加载失败显示可重试的 `AppErrorState`。
- 初次加载显示 `AppLoadingState`。
- 下拉刷新保留当前页面结构，不切换为整页加载。
- 增量加载在列表底部显示加载和结束状态。
- 请求失败后恢复按钮可用状态，并保留用户已填写内容。
- 身份切换或退出时清理所有角色相关页面状态，避免数据串用。

## 11. 迁移顺序

1. 建立视觉变量、状态配置和公共交互组件。
2. 拆分应用外壳、认证、导航和页面转场。
3. 拆分首页、消息、我的、文档和模板页面。
4. 拆分实习页面、表单、审核、成绩和流程记录。
5. 抽取实验与实训公共 `Practice` 页面和 composable。
6. 删除旧的重复模板、状态映射和全局覆盖样式。
7. 重新构建 H5 生产产物到 `server/public/h5`。

迁移过程中保持现有页面可构建，不同时修改后端业务实现。

## 12. 非目标

- 不修改后端接口和数据库结构。
- 不新增业务流程和业务状态。
- 不新增自定义手势系统。
- 不引入新的状态管理框架。
- 不重写 Vant 的基础弹层、表单和安全区域能力。
- 不修改 PC 端视觉和交互。
