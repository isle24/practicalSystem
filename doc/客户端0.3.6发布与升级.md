# 客户端 0.3.6 发布与升级

## 版本文件

- 更新说明：`fontend/desktop/releases/0.3.6.md`。
- 学校系统更新说明：`server/releases/0.3.6.json`，管理员打开“版本与更新”时按现有流程导入草稿。
- 客户端版本：package.json、package-lock.json、Cargo.toml、Cargo.lock、tauri.conf.json 均为 `0.3.6`。
- 功能范围：0.3.5 之后至完整项目提交 `1d5b98f`。

## 服务端部署

1. 更新 Gitea `master`，包含服务端代码、PC/H5 发布产物、结构基准和更新说明。
2. 在 `server` 目录按锁文件安装 PHP 依赖：`composer install --no-dev --prefer-dist --optimize-autoloader`，加载新增企业微信 SDK。
3. 管理员打开“系统配置 → 数据库结构”，选择学校业务库，检查并下载升级 SQL。维护人员审核并执行后，再次检查结构。
4. 本版结构涉及 `data_cleanup_task`、企业微信通知时段与投递字段、`base_visit_plan` 和 `base_visit_record`。完整比对已包含这些结构；已通过比对补齐的部分不需要重复执行独立脚本。
5. 重启 Webman HTTP、Redis 队列和企业微信消息分发进程。仅刷新网页不会加载新增后台进程。
6. 在“系统配置 → 版本与更新”核对系统 0.3.6 草稿。使用完整比对完成升级后，按实际处理结果登记关联 SQL，确认发布系统更新说明。
7. 从 GitHub 导入客户端 0.3.6，等待安装包下载和校验完成，再发布客户端版本。

升级 SQL 仅登记执行情况，不会通过版本页面在线执行。GitHub 客户端发布和学校内版本发布分别控制，未发布学校版本前不会向学校用户推送更新。

## 客户端构建

沿用 GitHub 独立前端仓库，只同步 `fontend/desktop`、`fontend/pc`、`fontend/shared` 和构建工作流；完整服务端及 SQL 保留在 Gitea。

GitHub Actions 构建 macOS 通用 DMG 和升级包、Windows x64 NSIS 安装器、Linux x64 AppImage 和 deb。三个平台完成后统一校验版本、签名文件及资产哈希，并发布 `v0.3.6`。
