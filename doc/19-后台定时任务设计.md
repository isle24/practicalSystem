# 后台定时任务设计

## 1. 调度边界

`CronTask` 仅注册执行时间并遍历启用的学校业务库。查询和持久化由 Model 提供，跨表事务、文件删除和消息发送由 Service 处理。

多实例部署时，每项任务使用 Redis 分布式锁。锁键包含任务编码、学校数据库 ID 和执行周期，防止同一学校同一周期重复执行。

## 2. 任务清单

| 任务 | 默认时间 | 处理规则 |
|---|---|---|
| 导出任务补投 | 每分钟 | 补投创建超过 1 分钟仍为 `pending` 的任务 |
| 导出任务超时 | 每 5 分钟 | `processing` 且 `started_at` 超过 30 分钟的任务标记为 `timeout` |
| 临时文件清理 | 每日 02:00 | 清理 `is_temporary=1` 且创建时间超过 `file_retention_days` 的文件，默认保留 7 天 |
| recording 归档 | 7 月、12 月每日 02:30 | 当前年级或毕业届次及其上一周期保留在线，其他审核时间线按实际业务归属分批归档到本学校库年度归档表 |
| 实习周报生成 | 每周一 06:30 | 生成上一自然周实习简报并通知相关管理员 |
| 保险到期提醒 | 每日 09:00 | 对未来 7 天内到期且未按当前到期日提醒的有效保险发送或补发续保通知 |

## 3. 临时文件清理

临时文件只按 `file.is_temporary=1` 判断。目录、扩展名和文件名称不参与判断。

清理在事务内执行：

1. 锁定待清理的 `file` 记录。
2. 软删除相关 `file_relation` 和 `file` 记录。
3. 将对应 `file_blob.ref_count` 减一。
4. 当 `ref_count=0` 且不存在有效文件关系时，软删除 `file_blob` 并记录磁盘路径。
5. 事务提交后删除磁盘文件。

同一 `file_blob` 被永久文件或其他有效文件记录复用时，只删除过期临时引用，不删除物理文件。

## 4. recording 归档

年级归属的数据不使用学期作为归档口径。当前年级和上一年级对应的数据保留在业务表，其他年级的实习 recording 表族及实验实训 `practice_recording` 分批写入本学校业务库 `recording_archive_YYYY`。毕业实习按毕业届次归属，不得以年级字段替代。7 月和 12 月每天执行一批，避免单次归档长时间占用数据库连接。

归档记录保存来源表、来源记录 ID、主表、主表 ID、实际归属类型与 ID、业务类型、状态变化、操作人、内容、原始快照、关联审核意见、原创建时间和归档时间。年度归档表通过来源表和来源 ID 唯一约束保证幂等。

只有归档记录写入成功后，才删除来源 recording 和已进入快照的 `review_opinion`。没有明确年级或毕业届次归属的记录不自动归档。

## 5. 实习简报

简报按自然周生成，`week_key` 唯一。简报保存统计周期、标题、结构化内容和生成时间，重复执行时不重复生成。

内容包括参与学生与任务概况、签到统计、异常签到、未提交日志、逾期报告和指导教师工作概览。学校管理员生成全校简报，学院管理员生成本学院简报，专业管理员生成本专业简报，消息只发送给对应数据范围账号。

## 6. 保险提醒

保险到期提醒以 `insurance.end_date` 为准。系统记录本次已提醒的到期日；保险续期或修改到期日后，可针对新的到期日再次提醒。

接收人包括学生、任务指导老师，以及学生所属学院和专业的管理员。消息通过统一消息模板发送。
