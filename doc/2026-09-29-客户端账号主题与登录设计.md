## 4. A：角色与组织归属校验

### 4.1 现状

账号的角色与组织范围编辑界面在 `fontend/pc/src/App.vue`，没有独立组件。`sys_organization` 已按 `account_id + role_id` 保存 `dep_id`、`profession_id`、`class_id`、`company_id`、`cate_id`，且这些列是字符串类型，并带生成列 `scope_key`、`enabled_flag` 与唯一键 `uk_scope(account_id, role_id, scope_key, enabled_flag)`。角色类型全集为 `super_admin`、`school_admin`、`college_admin`、`profession_admin`、`teacher`、`student`、`enterprise`。

### 4.2 目标

按目标角色要求组织归属：

| 角色 | 组织归属 |
| --- | --- |
| 超级管理员 | 不绑定学院 |
| 学校管理员 | 不绑定学院 |
| 学院管理员 | 必须绑定学院 |
| 专业管理员 | 必须绑定学院和专业，且专业属于该学院 |
| 老师 | 按现有规则维护学院和专业 |
| 学生 | 按现有规则维护年级、学院、专业和班级 |
| 企业导师 | 沿用现有企业或基地归属规则 |

### 4.3 实施边界

- 角色变更后立即展示目标角色所需的组织字段；必填组织范围为空或不匹配时禁止保存并返回明确提示。
- 学院管理员默认至少绑定一个学院；专业管理员默认绑定一个学院和一个专业。需要跨多个学院或专业时通过现有数据权限范围配置，不扩大角色字段的单值含义。
- 从需要组织范围的角色改为不需要的角色时，停用不适用范围并提示管理员；不物理删除历史范围行。
- 组织选项限制在操作者可管理范围内；角色和组织范围由服务端校验，不依赖前端字段。
- 专业属于学院的校验使用现有专业与学院关系数据，不使用名称比对。
- 角色与组织范围变更写入操作审计。

## 5. B：账号关联与角色切换

### 5.1 现状

切换列表按同一用户或同一已验证手机号自动聚合，个人设置和用户管理中没有自助关联入口。

### 5.2 目标

入口放在“个人设置 → 账号与角色切换”。

- 显示当前账号、已关联账号、角色、学院/专业范围和账号状态。
- 支持添加账号、切换账号、解除关联。
- 添加时验证待关联账号凭据，并要求当前账号再次确认。
- 关联后刷新切换列表、权限、菜单和数据范围；解除后立即从切换列表移除。
- 提示切换不合并两个账号的业务数据、消息和文件。

### 5.3 实施边界

- 账号关联与企业微信绑定是不同功能：前者用于切换同一用户持有的多个系统账号，后者用于把某个系统账号映射到企业微信成员。手机号相同不能代替双方账号验证。
- 关联只允许发生在同一学校；两端账号均须有效；操作者只能管理自己的关联。
- 不通过客户端传入账号 ID 即授予切换能力。
- 保留现有同一用户账号的兼容行为；已验证手机号自动聚合的范围在实施前核实，不能让手机号单独成为绕过双方验证的入口。
- 关联与解除均写审计日志。

## 6. C：消息发送者默认排除

### 6.1 现状

消息服务的 `include_sender` 默认值为 true，会把发送者加入最终收件人，站内和企业微信渠道都可能收到自己发送的消息。

### 6.2 目标

- 指定人员、按角色、发送给全部账号三种方式默认均排除发送者。
- 增加“发送一份给自己”选项，默认关闭；发送者明确勾选后才收到。
- 前端收件人预览与服务端最终名单一致；站内、企业微信、短信使用同一收件人集合。
- 发送者被明确选中时只保留一个收件人记录。
- 发送结果中的人数按最终收件人计算。
- 保留消息发起者的审计信息，即使发起者不是收件人。

### 6.3 实施边界

- 企业微信渠道不得自行追加发送者；排除逻辑放在收件人集合计算阶段，而非各渠道内。
- 模板消息与直接发送走同一收件人规则。

## 7. D：客户端启动与企业微信扫码登录

### 7.1 消除网页版登录框闪现

现状为客户端连接成功后先显示 PC 网页登录框，再完成客户端登录。改为明确的启动流程：

1. 客户端显示自身连接页或启动状态。
2. 完成本地连接信息、自动登录和会话 bootstrap。
3. 已有有效会话时直接进入桌面，不挂载网页版登录表单。
4. 未登录时显示客户端登录页。
5. 必须绑定企业微信时进入绑定或扫码页面。
6. 连接失败时显示错误和重试操作。

退出登录、切换学校或连接失败时清理旧会话状态。现有约束保持：JWT 只保存在 Rust cookie jar，不进入 webview；网关只放行同源跳转，跨域 302 会返回 502。因此登录与绑定流程不得依赖跨域跳转。

### 7.2 企业微信扫码登录

登录页提供账号密码和企业微信扫码两种方式：

- 仅已绑定企业微信的系统账号可通过扫码直接登录。
- 二维码使用短时、一次性随机票据，不含账号密码、JWT 或个人身份信息。
- 服务端校验学校、CorpId、企业微信成员、绑定关系和账号状态。
- 未绑定的成员扫码时不创建系统登录会话；提示先用账号密码登录并完成绑定。
- 账号密码登录后，如学校启用强制绑定，进入现有绑定流程。
- 绑定成功后刷新会话、权限和菜单再进入桌面。
- 取消、过期、退出、切换学校时令扫码会话失效。
- 扫码登录不能绕过学校现有企业微信强制绑定策略。
- 一个企业微信成员关联多个系统账号时，登录时明确选择目标角色账号，选择范围只限经验证关联的账号。

### 7.3 实施边界

- 现有 `WechatBindingService::begin()` 的 `inWechat()` 前置校验会直接拒绝非企业微信浏览器，扫码登录与客户端绑定不得复用该校验，须为扫码票据路径单独放行。
- 票据沿用现有一次性凭据模式：随机票据明文只出现一次，服务端按 `sha256` 存储，带 TTL，消费使用原子 `GET` + `DEL`。
- 现有 `AuthMiddleware` 绑定白名单需要扩展以覆盖扫码轮询接口；扫码轮询接口本身须要求已建立的本地会话或独立票据，不能成为匿名信息出口。
- 二维码渲染需要新增前端依赖或由服务端生成图片；两种方案在实施时择一，并确认构建产物与离线可用性。

## 8. E：标题栏信息布局

将桌面右下角的个人中心、头像、在线状态、下载、退出登录和时间移动到最上方标题栏：

- 与关闭、最大化、最小化按钮处于同一水平区域。
- 用户信息和操作放在标题栏右侧。
- Windows 风格系统按钮靠右，用户信息位于其左侧。
- macOS 保留红黄绿窗口按钮的左侧习惯，用户信息位于标题栏右侧。
- 标题栏可拖动区域不能覆盖头像、按钮、菜单和可点击信息。
- 小窗口、登录页及移动布局隐藏桌面专用信息。
- 关闭、最大化、还原、退出登录时正确收起菜单和浮层。

实施边界：拖动区域与可点击区域的划分必须在两套平台样式下分别验证；收起浮层逻辑与现有窗口最小化、关闭、退出流程共用同一清理入口。

## 9. F：主题、暗黑模式与文字对比度

### 9.1 桌面文字可读性

- 桌面模块标题和快捷方式文字默认使用白色。
- 对文字增加阴影或其他对比度处理，确保浅色壁纸上仍可辨认。
- 任务栏、窗口标题栏、表单、弹窗文字分别按主题配置，不把整个应用文字强制设为白色。
- 颜色通过统一主题变量管理。

### 9.2 暗黑模式

支持亮色、暗色和跟随系统三种模式，应用于登录页、桌面、任务栏、窗口、表格、输入框、按钮、菜单、弹窗、通知、扫码绑定、错误提示和客户端设置页。

### 9.3 主题模块

把客户端桌面壁纸设置升级为“主题”模块：

- 提供多款预置配色和明暗主题。
- 可选择本地壁纸并调整桌面文字颜色、强调色、窗口颜色、透明度和图标布局密度。
- 支持预览、应用、恢复默认和删除自定义主题。
- 本地壁纸及主题设置只保存在当前客户端，不上传学校或个人服务器。
- 按学校与本机用户隔离本地主题，避免切换学校后误用另一学校的桌面设置。
- 与服务器已有的个人壁纸、共享壁纸、学校默认壁纸分开；本地主题不能修改或覆盖服务器上的设置。

实施边界：主题只本地生效，不改变学校默认壁纸、个人壁纸或共享壁纸；暗黑模式首次安装默认值待确认。

## 10. G：外部地址当前页打开

为收藏、插件及外部地址增加“当前页打开”：

- 当前页打开：在当前模块或弹窗内容区域内显示目标页面。
- 客户端窗口：在新的客户端窗口打开。
- 外部浏览器：交给系统默认浏览器。
- 新增选项不改变已有链接的打开方式。
- 页面需要返回、关闭、显示加载失败状态。
- 跨域地址不得带入学校系统 Cookie、JWT 或内部凭据。
- 仅对经过现有安全策略允许的地址开放内嵌显示。

实施边界：草案默认只用于外部地址，内部模块是否也能替换当前内容区待确认。内嵌页面运行在无学校凭据的独立上下文中，不能通过网关注入会话。

## 11. H：本地凭据库与云同步

### 11.1 本地保存

- 默认只保存在本机。
- 优先使用 macOS Keychain、Windows Credential Manager、Linux Secret Service 等系统安全凭据存储。
- 禁止明文写入普通配置文件、日志、URL、崩溃报告或普通同步设置。
- 按学校、当前系统账号和外部站点来源隔离凭据。
- 个人设置提供凭据列表、删除单条和清空全部。
- 自动填充只作用于用户明确保存的站点和表单，不在页面上明文展示密码。
- 退出学校系统时清除当前会话；是否同时删除本地凭据由单独操作控制。

### 11.2 云同步

已确认：云端采用服务器密钥加密，优先跨设备同步便利。

- 个人设置新增“云同步密码”开关，默认关闭。
- 开启前说明服务器密钥加密的边界：服务器具备解密能力，不能表述为端到端加密。
- 服务端使用独立保险库表，按学校、用户、账号和外部站点隔离。
- 数据库仅存密文、nonce、密钥版本及必要的加密元数据。
- 加密密钥由服务端密钥管理机制保管，不存入同一数据库表。
- 日志、消息、导出和普通 API 响应不得泄露明文密码。
- 管理界面不提供管理员查看他人密码的能力。
- 只有凭据所有者的受认证会话可同步相应密文。
- 关闭同步时明确区分“停止同步”与“删除服务器副本”，删除服务器密文须经用户确认。
- 密钥轮换、备份恢复和密钥丢失对历史密文的影响需纳入部署方案。
- 外部站点密码变更后，允许更新本地副本并按设置重新同步。

## 12. 权限、安全与审计边界

- 角色与学院、专业范围在服务端共同校验。
- 账号关联须验证双方身份并限制在同一学校。
- 企业微信扫码登录不能绕过未绑定策略。
- 消息发送默认排除发送者，企业微信渠道不得自行追加发送者。
- 本地密码使用系统安全存储。
- 云同步密码按用户隔离并由独立服务端密钥加密；服务器有解密能力这一点必须在界面告知。
- 外部网页不得自动获得学校系统身份凭据。
- 账号关联、角色变更、密码同步开关、消息发送及扫码登录操作均记录必要审计信息。
