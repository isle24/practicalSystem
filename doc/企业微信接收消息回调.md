# 企业微信接收消息回调

## 接口约定

- URL：`https://sxxt.cdjcc.edu.cn/api/wechat/callback`。
- Webman 显式注册 GET、POST 路由；控制器禁用默认路由。
- 沿用学校域名解析和学校配置库；免 JWT 登录，由企业微信消息签名认证。
- GET：校验 `msg_signature`、`timestamp`、`nonce`、`echostr`，解密并验证 CorpId，原样返回明文，不包装 JSON、不追加换行。
- POST：读取 XML 中的 `Encrypt`，验签、解密、校验 CorpId 和已配置的 AgentId，解析消息 XML，返回 HTTP 200 空响应。
- 原始请求和解密消息不写入接口操作日志；异常只记录异常类型，不记录凭证或消息内容。
- POST 解密成功后通过现有 Webman Event 派发 `wechat.callback.received`，不提供默认业务监听器、自动回复或账号绑定。
- 不依赖应用 Secret、access_token 或出站代理；使用 `w7corp/easywechat:^6.20`，不新增数据库表。

## 配置顺序

1. 在实践系统 PC 端“系统配置 → 企业微信应用”保存企业 ID（CorpId）、回调 Token、EncodingAESKey，建议同时保存 AgentId。
2. Token 和 EncodingAESKey 使用企业微信“接收消息”页面的相同值；EncodingAESKey 为 43 位，不能填写应用 Secret。
3. 部署后端文件及 Composer 锁定文件，在 `server` 目录执行 `composer install --no-dev --prefer-dist --optimize-autoloader`，再执行 `php start.php reload`；确认 Nginx 的 `/api/` 请求转发到 Webman，保留 Host、查询参数和请求体。
4. 在企业微信应用“接收消息 → 设置 API 接收”填写上述 URL、Token、EncodingAESKey，消息格式选择 XML，然后保存。
5. GET 验证只需要 CorpId、Token、EncodingAESKey；直接在浏览器打开不带签名的 URL 不会返回成功。

## 底层事件

`wechat.callback.received` 通过 `Webman\Event\Event::dispatch` 同步派发，数据字段：

| 字段 | 类型 | 内容 |
|---|---|---|
| school_database_id | int / null | 当前学校数据库 ID |
| xml | string | 已验签、解密、验证接收者的原始消息 XML |

监听器可在 `server/config/event.php` 注册，应快速入队并完成幂等处理。有 MsgId 时按 MsgId 去重；事件按官方建议结合 FromUserName、CreateTime 去重。监听器异常返回 500，交由企业微信重试。默认无监听器，仅确认接收，不持久化消息。

## 错误响应

| HTTP 状态 | 含义 |
|---|---|
| 400 | 缺少参数、参数格式或 XML 无效 |
| 403 | 签名、密文或接收者校验失败 |
| 405 | 不是 GET / POST |
| 413 | POST XML 请求包超过 1 MiB |
| 503 | 回调配置缺失或 EncodingAESKey 无效 |
| 500 | 配置读取或事件派发异常 |

XML 禁止 DTD 和外部实体；签名比较及 AES 解密交由 EasyWeChat 完成。显式传入 Encryptor 的 `receiveId=CorpId`，启用解密后的接收者校验。Webman 已解码查询参数，不重复执行 `urldecode`，避免破坏 Base64 中的 `+`。
