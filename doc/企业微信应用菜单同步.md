# 企业微信应用菜单同步

## 操作约定

- 原有“保存配置”仅写入学校配置库，不发布企业微信菜单，也没有定时同步任务。
- “立即同步菜单”先保存当前表单，再调用 `POST /api/wechat/sync-menu`，发布已保存的菜单。
- 沿用 `wechat:proxy:save` 权限；同步接口需要登录、学校上下文和 POST 请求。
- 同步覆盖当前 AgentId 的完整菜单；普通保存不影响企业微信端菜单。
- 配置保存成功而发布失败时，保留本地配置，显示企业微信错误；只有 `errcode=0` 才提示同步成功。
- 至少配置一个一级菜单。一级最多 3 个、二级最多 5 个；主菜单名称最多 16 字节，子菜单名称最多 40 字节，点击 Key 最多 128 字节，网页 URL 最多 1024 字节。
- 同步只使用 CorpId、AgentId、应用 Secret；应用 AppID、回调 Token 和 EncodingAESKey 不参与发布。
- 小程序菜单的 AppID 指目标小程序，并要求该小程序已与企业绑定。

## 接口适配

- 复用 `WechatClient` 获取 access_token，并调用 `POST /cgi-bin/menu/create?access_token=...&agentid=...`。
- 菜单请求体为 `{"button": [...]}`；本地 `children` 转成 `sub_button`，`miniprogram` 转成 `view_miniprogram`。
- 返回 `agent_id`、`menu_count`、`synced_at`；不返回或记录 access_token 和 Secret。
- 沿用现有出站代理开关；停用时直接请求企业微信。代理地址禁止项使用逐项 OR 判断。
- 客户端显示可能存在刷新延迟；接口成功表示企业微信已接受菜单，可重新进入应用查看。
