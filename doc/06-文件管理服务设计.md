# 文件管理服务设计

## 0. 技术实现

物理上传层使用 `tinywan/storage`（webman 插件），FileService 封装业务逻辑。

```
┌──────────────────────────────────────────────────────┐
│  FileService（app/server/file/FileService.php）       │
│  业务层：秒传判断 / file_blob+file 双表 / ref_count   │
│  签名 URL / 清理策略 / 上传频率控制                     │
├──────────────────────────────────────────────────────┤
│  tinywan/storage（物理上传层）                          │
│  Storage::disk('public')->uploadFile()                │
│  功能：多文件上传 / 分片合并 / 多驱动切换 /             │
│  内置校验（扩展名白名单 + 大小限制 + 数量限制）          │
└──────────────────────────────────────────────────────┘
```

| | tinywan/storage 负责 | FileService 自建 |
|---|---|---|
| 文件接收/分片合并 | Y | — |
| 扩展名白名单 | Y（`include`/`exclude` 配置） | — |
| 大小/数量校验 | Y（`single_limit`/`total_limit`/`nums`） | — |
| 本地路径生成 | Y（日期分目录 + SHA1 文件名） | — |
| 云存储切换 | Y（`disk()` 换驱动） | — |
| MD5 预计算 + 秒传 | — | Y |
| file_blob + file 双表 | — | Y |
| ref_count 引用计数 | — | Y |
| MIME 魔数校验 | — | Y（不信任 Content-Type） |
| 签名 URL（secure_link） | — | Y（Nginx 层） |
| `?n=` 改名下载 | — | Y（Nginx 层） |
| 上传频率限制 | — | Y（Redis 令牌桶） |
| 过期清理 | — | Y |

**配置**（`config/plugin/tinywan/storage/app.php`）：

```php
return [
    'enable' => true,
    'storage' => [
        'default' => 'local',  // local / oss / cos / qiniu / s3
        'single_limit' => 100 * 1024 * 1024,  // 单文件 100MB
        'total_limit' => 100 * 1024 * 1024,
        'nums' => 10,
        'include' => ['jpg','jpeg','png','gif','webp','pdf','doc','docx','xls','xlsx','ppt','pptx','zip','rar','txt','csv'],
        'exclude' => ['exe','sh','php','js','html'],
        'local' => [
            'root' => public_path() . '/files/b1',  // 必须和 file.block 一致
        ],
    ],
];
```

## 1. 数据模型

物理存储与用户记录分离：`file_blob` 存物理文件（一份），`file` 存用户上传记录（每人一条）。

```
file_blob（物理文件，相同 MD5 只存一份）
  - id
  - md5（文件 MD5，唯一索引）
  - path（存储路径）
  - ext（扩展名）
  - size（文件大小，字节）
  - mime_type
  - disk: public / oss / cos（本地统一用 public）
  - ref_count（引用计数：有多少条 file 记录指向此 blob）
  - created_at, updated_at

file（用户文件记录，每次上传/秒传各创建一条）
  - id
  - blob_id（关联 file_blob.id）
  - name（用户上传时的原始文件名）
  - download_name（下载时浏览器显示的文件名，默认为 name）
  - url（实际访问 URL，不带改名参数）
  - is_temporary（0=永久文件，1=临时文件可自动清理）
  - uploader_id（上传人 account.id）
  - created_at, updated_at, deleted_at
```

**模型关系：**

```
用户 A 上传 report.docx（MD5=abc123）
  → file_blob: {id:1, md5:"abc123", path:".../abc123.docx", ref_count:1}
  → file:      {id:10, blob_id:1, name:"实习报告_张三.docx", uploader_id:5}

用户 B 上传同一文件（MD5=abc123，秒传命中）
  → file_blob: {id:1, md5:"abc123", ref_count:2}  ← ref_count +1
  → file:      {id:11, blob_id:1, name:"实训报告_李四.docx", uploader_id:8}

两个用户看到各自上传的文件名，物理磁盘只存一份。
```

## 2. 秒传逻辑

```
上传流程：
  1. 前端计算文件 MD5（WebAssembly / spark-md5）
  2. 调 POST /api/file/check { md5, name }
  3. FileService 检查配置：file.instant_upload_enabled
     ├── false（默认）→ 直接返回 { action: "upload_required" }，不查 file_blob
     └── true → 查 file_blob 表：
         ├── 命中（md5 已存在）
         │   → file_blob.ref_count + 1
         │   → INSERT file（blob_id=命中 blob.id, name=用户文件名, uploader_id）
         │   → 返回 { action: "instant", file_id, url }，秒传完成
         │
         └── 未命中 → 返回 { action: "upload_required", upload_token }
  4. 前端调 POST /api/file/upload（multipart，header 带 X-File-MD5: abc123）
  5. FileService::upload()：
     → Storage::disk('public')->uploadFile()  ← 插件写入磁盘
     → 后端 md5_file($path) 校验，与 X-File-MD5 对比
       ├── 一致 → 信任前端 MD5，直接写入 file_blob.md5 = $request->md5
       │         → INSERT file_blob + INSERT file
       └── 不一致 → 删除文件 + 返回 422 "文件校验失败，请重新上传"
     → 返回 { file_id, url }
```

**核心原则：** 前端计算的 MD5 是唯一权威值。后端只做「校验」不重新「计算」——`md5_file()` 仅用于对比前端传入值是否匹配，匹配后 `file_blob.md5` 直接写入前端传入的值。这样后续其他用户 `check` 同一 MD5 时，秒传命中率 100%。

**秒传开关：** 配置项 `file.instant_upload_enabled`（默认 false），管理员在 PC 端「系统管理 → 配置管理」中开启。关闭时 `/api/file/check` 直接返回 `upload_required`，全部走实际上传，不查 `file_blob` 表。

**FileService 校验链（uploadFile 返回后执行）：**

```
Storage::uploadFile() 返回后：
  1. 文件头魔数校验（finfo，不信任 Content-Type）→ 不匹配 → 删除 + 拒绝
  2. 图片：getimagesize() 验证真实图片 → 不通过 → 删除 + 拒绝
  3. 压缩包：检查内部文件类型，禁止可执行文件
  4. 以上通过 → md5_file($path) 与 X-File-MD5 对比
     → 一致 → INSERT file_blob + file，md5 = $request->md5
     → 不一致 → 删除 + 422 "文件校验失败，请重新上传"
```

**并发安全：** `file_blob.md5` 唯一索引。并发上传同一新文件时：先 INSERT file_blob 成功，后者触发唯一约束冲突 → 降级为秒传（ref_count+1，新建 file 记录）。Redis 锁 `file_md5_lock:{md5}` TTL 30 秒减少 DB 冲突概率。

## 3. 文件关联

文件与业务实体通过 `file.id` 关联：

```
file_relation
  - id, file_id（关联 file.id，非 file_blob.id）
  - entity_type: internship_application / journal / report / training_material / ...
  - entity_id
  - tag: 材料附件 / 日志图片 / 报告附件（前端展示用）
  - created_at
```

## 4. 清理策略

- 软删除 file 记录（deleted_at）不删物理文件，同时 `file_blob.ref_count - 1`
- `file_blob.ref_count = 0` 时方可物理删除磁盘文件 + file_blob 记录
- `is_temporary=1` 的 file 记录过期后自动软删除，ref_count 同步递减
- `is_temporary=0` 的文件（学生/教师上传、归档资料等）不被自动清理
- ref_count = 0 且无有效 file_relation 时方可物理删除

### is_temporary 标记规则

| 来源 | is_temporary | 说明 |
|---|---|---|
| 学生/教师/管理员上传 | 0 | 永久文件，归档资料 |
| 报表导出（report） | 1 | 临时文件，7 天后清理 |
| 文件打包（export_file） | 1 | 临时文件，7 天后清理 |
| 文档生成（export_doc） | 1 | 临时文件，7 天后清理 |

### 4.1 上传安全校验

**文件类型白名单（两层防线）：**

| 防线 | 负责方 | 位置 |
|---|---|---|
| 扩展名白名单 + 大小限制 | tinywan/storage | `config/plugin/tinywan/storage/app.php` 的 `include`/`exclude`/`single_limit` |
| MIME 魔数校验 + 图片真实性 | FileService | `upload()` 方法中 `Storage::uploadFile()` 返回后执行 |

**插件内置校验（拒绝即抛异常，不进入 FileService）：**

| 类别 | 允许扩展名 | 最大大小 |
|---|---|---|
| 图片 | jpg, jpeg, png, gif, webp | 10 MB |
| 文档 | pdf, doc, docx, xls, xlsx, ppt, pptx | 50 MB |
| 压缩包 | zip, rar | 100 MB |
| 文本 | txt, csv | 10 MB |

**FileService 补充校验流程：**

```
Storage::uploadFile() 返回后：
  1. MIME type 校验（finfo 检查文件头魔数，不信任 Content-Type）→ 不匹配 → 删除文件 + 抛异常
  2. 图片文件：getimagesize() 验证真实图片 → 不通过 → 删除文件 + 抛异常
  3. 归档文件：检查压缩包内文件类型，禁止包含可执行文件
  4. 通过后进入 MD5 校验 + 写 DB 流程
```

**上传频率限制：** 同一用户每分钟最多 20 次上传请求，超过返回 429。

## 5. public 磁盘与 Nginx 直链下载

### 5.1 存储路径

Storage 插件将文件写入 `${root}/{yyyymmdd}/{sha1}.{ext}`。

插件的 `root` 和我们的 `file.block` 通过配置联动，实现一致的 `{block}/{school_code}/{category}` 分层：

```
插件 config:  'local.root' => public_path() . '/files/b1'
FileService:  调用 uploadFile() 前，动态设 root → public_path() . "/files/{block}/{school_code}/{category}"
              每次请求从 Context 获取 database_id → school_code

最终路径：
public/files/b1/school_a/student/20260527/a3f2b8c1.jpg
public/files/b1/school_a/report/20260527/c5d4e6f3.xlsx
```

`block` 为存储块标识（配置项 `file.block`），默认值为 `b1`，多盘扩容时修改。

### 5.2 多盘扩容

当单个磁盘满时，增加新挂载盘，修改 block 配置即可分流：

```
磁盘 A: /mnt/disk1/public/files/b1/   ← 旧数据
磁盘 B: /mnt/disk2/public/files/b2/   ← 新盘

配置 file.block = b2   → 新文件写入磁盘 B
```

Nginx 同时映射两个磁盘路径：

```nginx
location /files/ {
    alias /mnt/disk1/public/files/;
    # 如果 disk1 找不到，try_files 到 disk2
    try_files $uri @disk2;
}
location @disk2 {
    alias /mnt/disk2/public/files/;
    expires 1h;
}
```

旧文件仍可通过原路径访问，新文件自动写入新盘，无缝扩容。

分层的好处：按学校隔离、按来源/类型分类、按日期归档清理。

### 5.3 直接 URL 访问（默认方式）

文件存储即 URL，直接通过域名访问：

```
https://aaa.com/files/2184/report/20260526/aaa.docx
```

无需经过 PHP，nginx 直接返回文件内容。安全性依赖 UUID 不可猜测。

### 5.4 改名下载（?n= 参数）

通过 `?n=` 查询参数指定浏览器下载时的文件名：

```
https://aaa.com/files/2184/report/20260526/aaa.docx?n=实习成绩_2026-05-27.docx
```

Nginx 配置：

```nginx
map $arg_n $content_disposition {
    ""      "";
    default "attachment; filename*=UTF-8''$arg_n";
}

location /files/ {
    alias /path/to/project/public/files/;
    add_header Content-Disposition $content_disposition;
    expires 1h;
}
```

- 不带 `?n=` 时，浏览器按默认行为（图片/PDF 预览，xlsx/zip 下载）
- 带 `?n=xxx` 时，强制下载并显示指定文件名

### 5.5 文件访问安全

**默认方式（直接 URL）：** 依赖 UUID 不可猜测性，适合低敏感文件。风险：URL 一旦泄露（浏览器历史、Referer 头、分享链接），任何持有 URL 的人均可访问。

**安全方式（签名 URL）：** 敏感文件（成绩单、包含个人信息的导出文件）使用签名 URL：

```
GET /files/{uuid}?sign={hmac_sha256}&expires={timestamp}
```

Nginx 配合 `ngx_http_secure_link_module` 校验签名和过期时间，不通过返回 403。签名由 FileService 在返回 URL 前生成，密钥不暴露给前端。

```nginx
location /files/ {
    secure_link $arg_sign,$arg_expires;
    secure_link_md5 "$secure_link_expires$uri $file_secure_link_secret";
    if ($secure_link = "") { return 403; }
    if ($secure_link = "0") { return 410; }  # 过期
    # ... 正常返回文件
}
```

**鉴权方式（API 下载）：** 需登录校验或追踪下载记录时走 API，PHP 校验 JWT 后设置 `X-Accel-Redirect`，nginx 接管传输。

```
GET /api/file/download/{uuid}
```

### 5.6 URL 存储规则

file 表的 `url` 字段存储不带改名参数的原始路径：

```
url: /files/2184/report/20260526/aaa.docx
```

前端根据场景自行拼接 `?n=` 参数：

```js
// 预览
const url = file.url

// 改名下载
const url = `${file.url}?n=${encodeURIComponent('实习成绩_2026-05-27.docx')}`
```
