# 企业微信接入设计

## 1. 接入流程

```
用户点击企业微信工作台菜单
  → 后端生成 state 参数（Redis 存储，TTL 300s）→ 构造 OAuth 授权 URL
  → 企业微信 OAuth 回调 → code + state
  → 校验 state 有效性（防 CSRF），state 仅使用一次即销毁
  → 后端用 code 换 userid
  → 查当前学校库 users 表是否已绑定
     ├── 已绑定 → 查出当前学校库 accounts/roles → 返回给前端选择身份
     └── 未绑定 → 跳转绑定页面
           → 用户输入学号/工号 + 姓名
           → 后端调用外部校验接口/第三方数据库核验
           → 校验通过 → 创建 users + account + students/teacher_list
           → 校验不通过 → 提示"信息不匹配，请联系管理员"
  → 选择当前身份 → 签发 JWT → 进入主页
```

## 2. 多入口登录策略

| 入口 | 登录方式 | 说明 |
|---|---|---|
| 企业微信工作台 | OAuth 静默授权 | 自动获取 userid，无感登录 |
| 手机浏览器 | 企业微信 OAuth 弹窗授权 | 分享链接场景，需手动授权 |
| PC 浏览器 | 企业微信扫码 + 账号密码 + 教务系统 SSO | 全角色（管理员/教师/学生） |

### 2.1 账号密码登录

- 管理员：可设置账号密码登录
- 教师/学生：默认企业微信扫码或教务系统 SSO 登录，也可由管理员设置密码

### 2.2 企业微信扫码登录

```
用户访问 PC 端登录页
  → 页面展示企业微信二维码（后端调用 /cgi-bin/login/qrcode 生成）
  → 用户打开企业微信扫描二维码
  → 企业微信回调 → 后端获取 userid → 查 users 绑定
     ├→ 已绑定 → 签发 JWT → 登录成功
     └→ 未绑定 → 提示"请先在企业微信工作台完成首次绑定"
  → 二维码 5 分钟过期，过期自动刷新
```

- 登录验证通过签发 JWT

### 2.3 验证码策略

密码登录时不默认展示验证码，仅在失败后触发：

```
第一次 → 账号 + 密码（无验证码）
  失败 → 第二次起 → 账号 + 密码 + 图形验证码
  连续 5 次失败 → 触发登录限流（参见 02-用户服务设计.md 第 7 节），锁定 5 分钟
```

同一 IP+账号下，首次登录成功或 10 分钟无失败记录后重置验证码状态。

## 3. 用户同步

每次通过企业微信 OAuth 登录时，拉取最新用户信息写入 `user_wechat` 表：

- wechat_userid（企业微信用户 ID，唯一）
- wechat_name（企业微信姓名）
- wechat_avatar（企业微信头像 URL）
- department（JSON，企业微信部门 ID 列表，用于自动匹配学院）
- position（职务）
- mobile（企业微信绑定手机）
- email（企业微信绑定邮箱）
- raw_data（JSON，完整原始数据，用于排查）
- last_synced_at（同步时间）

users 表的 name / avatar 在首次绑定时从企业微信同步，后续可通过管理端手动修改。

## 4. 企业微信应用菜单配置

### 4.1 可视化配置（PC 端）

超级管理员在 PC 端"企业微信 → 菜单配置"页面，以所见即所得方式配置各角色菜单，支持预览后同步。

**配置界面：**

```
┌─────────────────────────────────────────────────┐
│  角色选择：[教师 ▼]                              │
│                                                   │
│  一级菜单 ┌─────────────────────────┐  [+ 新增]   │
│  ├─ 待办审核  →  实习申请审核          │  [编辑]    │
│  │              日志点评              │  [删除]    │
│  │              报告评阅              │            │
│  ├─ 我的学生  →  学生列表             │            │
│  │              签到记录             │            │
│  │              成绩录入             │            │
│  └─ 个人中心  →  消息中心             │            │
│                  我的资料             │            │
│                                                   │
│  已用: 3/3 一级菜单, 7/15 二级菜单（每级最多5）     │
│                                                   │
│  [预览教师端效果]    [同步到企业微信]               │
└─────────────────────────────────────────────────┘
```

**操作流程：**

```
1. 选择角色 → 拖拽排序菜单项
2. 从系统菜单池中选取要展示的页面（仅显示该角色有权限的页面）
3. 配置完成后点击"预览"——模拟手机端企业微信工作台效果
4. 确认无误 → 点击"同步到企业微信"
5. 后端调用企业微信 API 更新该角色的工作台菜单
```

### 4.2 菜单池

菜单项来源于系统菜单表（menu），配置时仅可选当前角色有权限的页面。菜单项信息包括：

- 名称（企业微信菜单显示文字，不超过 5 个汉字）
- 图标（从预设图标库选择）
- 跳转路径（自动拼接完整 URL）
- 排序（拖拽调整）

### 4.3 企业微信 API 限制处理

| 限制 | 处理方式 |
|---|---|
| 最多 3 个一级菜单 | 界面实时计数，超出禁止保存 |
| 每级最多 5 个二级 | 界面实时计数，超出禁止保存 |
| 菜单名字不超过 8 字节（4 汉字） | 输入时校验，超长截断提示 |

### 4.4 同步机制

```
点击"同步到企业微信"
  → 后端生成该角色的菜单 JSON（符合企业微信 API 格式）
  → 对比上次同步的 hash，无变化则跳过
  → 调用 POST /cgi-bin/menu/create?access_token=...&agentid=...
  → 成功 → 记录同步日志 + 更新时间
  → 失败 → 返回错误信息，保留上次有效菜单
  → 多个角色需逐一同步（企业微信 API 按 agentid 设置菜单）
```

### 4.5 配置存储

企业微信菜单配置存储在 `wechat_menu_config` 表（学校库内）：

```
wechat_menu_config
  - id
  - role_id（角色）
  - menu_json（菜单结构 JSON）
  - hash（菜单 hash，用于对比是否变更）
  - last_synced_at（最后同步时间）
  - status: draft / synced / failed
  - created_at, updated_at, deleted_at
```
