## 3. 多租户架构

### 3.1 数据库隔离

每学校独立数据库，物理隔离。数据库名由 `databases.database_db` 字段指定，`authorizations` 表绑定域名→学校→数据库。命名建议使用 `practical_{school_code}` 便于识别，但不强制。

```
practical_school_a    A 大学的所有数据
practical_school_b    B 学院的所有数据
practical_template    模板库（建库时复制表结构 + 种子数据）
```

每个学校库包含完整表结构：users、account、students、teacher_list、role、user_role、sys_organization、所有业务表、菜单权限表、配置表等。主库仅保存租户元信息，不保存学校业务用户、角色或权限数据。

### 3.2 域名路由

学校通过子域名或路径标识，中间件自动切换数据库连接：

```
school-a.practical.com  →  practical_school_a
school-b.practical.com  →  practical_school_b
practical.com/school-a  →  practical_school_a
```

### 3.3 数据库切换中间件

`app/server/tenant/TenantMiddleware.php`，全局中间件，职责仅为域名解析 + 写入 Context：

```
请求进入
  → 从域名提取 school_code
  → 查 Redis tenant:domain:{domain} 获取 database_id
  → 未命中 → 查主库 authorizations → 写入 Redis
  → 查 Redis tenant:db:{database_id} 获取连接配置（host/port/user/pwd/db）
  → 未命中 → 查主库 databases → 写入 Redis
  → Context::set('tenant_database', database_db)
  → Context::set('tenant_database_id', database_id)
  → Context::set('tenant_config', {host, port, user, pwd, db, charset})
```

中间件不直接操作 PDO，仅解析租户并注册当前 worker 的租户连接名。Model 通过 `getConnectionName()` 使用 Context 中的 `tenant_connection`。

中间件执行顺序：`TenantMiddleware → UuidMiddleware → webman/limiter → IdempotentMiddleware → AuthMiddleware → CsrfMiddleware → PermissionMiddleware → DataScopeMiddleware → 业务`

**IdempotentMiddleware**：业务类 POST/PUT/DELETE 请求需携带 `X-Request-Token` 头。认证回调、验证码、文件上传分片等特殊接口可在路由配置中豁免。前端每次表单打开时生成唯一 token，提交后服务端 Redis 记录 `idempotent:{database_id}:{token}`，TTL 60 秒。重复 token 返回 409，前端恢复按钮。配合前端 `v-prevent-duplicate` 指令，双重防重。

### 3.4 租户连接管理

**与 webman/database 内置池的关系：**

实际 PDO 连接由 `webman/database` 与 Illuminate `DatabaseManager` 管理，主库和租户库都不由 Model 直接借还 PDO。`TenantConnectionManager` 只负责按租户动态注册连接配置、选择连接名、控制每个 worker 中保留的租户连接数量。

```
config/database.php:
  'master'          => 主库连接，webman/database 内置池管理
  'tenant_template' => 租户连接模板，仅提供 charset、pool 等公共配置
```

请求进入后，`TenantMiddleware` 从主库解析 `database_id` 和连接配置，调用 `TenantConnectionManager::ensureConnection()` 注册当前 worker 内的连接名：

```
tenant_{database_id}
```

然后写入 Context：

```
tenant_database_id
tenant_database
tenant_config
tenant_connection
```

**核心流程：**

```php
class TenantConnectionManager
{
    public function ensureConnection(int $databaseId, array $config): string
    {
        $name = "tenant_{$databaseId}";

        if ($this->needsRegister($name, $config)) {
            $this->purgeIfChanged($name);
            config(["database.connections.{$name}" => $this->buildConfig($config)]);
            $this->markActive($name, $config['version'] ?? null);
        }

        $this->touch($name);
        $this->evictIfNeeded();

        return $name;
    }
}
```

`databases` 表建议增加 `config_version` 或 `updated_at` 作为连接配置版本。版本变化时，当前 worker 调用 `DB::purge($connectionName)` 后重新注册，避免继续使用旧密码、旧库名或旧主机。

**容量控制：**

```
每个 worker 保留的租户连接名上限：globalMaxSize
每个连接名内部连接池上限：使用 tenant_template.pool.max_connections
```

`globalMaxSize` 不硬编码，由公式从 MySQL 容量和 worker 数推导：

```
globalMaxSize = max(3, floor(mysql_max_connections × 0.7 / worker_count) - 1)

其中 -1 是给主库连接留的位置（每 worker 一个 master 连接）
系数 0.7 预留 30% 给管理连接、临时查询等
下限 3 保证低 worker 数时每进程至少能服务 3 个不同租户
```

`TenantConnectionManager` 仅驱逐当前 worker 内最久未使用的租户连接名，驱逐动作使用 `DB::purge($connectionName)` 关闭底层连接并移除运行时配置。正在当前请求中使用的 `tenant_connection` 不参与驱逐。

**容量估算：**

```
场景 A：MySQL max_connections=200, 4 worker
  → globalMaxSize = max(3, floor(140/4) - 1) = 34
  → 总连接上限约 4 × (1 + 34) = 140

场景 B：MySQL max_connections=500, 64 worker
  → globalMaxSize = max(3, floor(350/64) - 1) = 4
  → 总连接上限约 64 × (1 + 4) = 320
```

配置项 `system.pool_global_max_size` 可手动覆盖公式默认值：

```
system:
  ├── pool_global_max_size   租户连接名全局上限（0=自动计算，>0=手动指定）
  └── pool_max_per_tenant    每个租户连接池上限（写入 tenant_template.pool.max_connections）
```

### 3.5 BaseModel 与租户连接集成

Model 只返回连接名，由 Illuminate 统一创建连接、处理事务、复用连接池。不得在 Model 中直接覆盖 `getConnection()` 返回自定义连接对象，也不需要在请求结束时手动归还连接。

```php
// app/model/channel/BaseModel.php
class BaseModel extends \Illuminate\Database\Eloquent\Model
{
    protected $connection = 'tenant_template';
    use SoftDeletes;

    public function getConnectionName()
    {
        return \Webman\Context::get('tenant_connection') ?: $this->connection;
    }
}
```

**事务约定：** 同一业务事务内只使用当前 `tenant_connection`，不得在一个事务中同时写多个学校库。确需跨租户操作时，只允许通过异步任务拆分为多个独立事务。

**并发安全：** webman worker 内请求通常串行处理。若启用协程并发，`TenantConnectionManager` 的注册、驱逐、版本更新操作需加进程级锁，避免同一 worker 内重复注册或驱逐正在注册的连接名。

**与直接覆盖 config() 方案对比：**

| | 每请求覆盖同一 tenant 配置 | 动态连接名方案 |
|---|---|---|
| 连接隔离 | 依赖请求时机，易受常驻进程影响 | `tenant_{database_id}` 独立连接名 |
| Eloquent 事务 | 容易与连接生命周期冲突 | 由 DatabaseManager 统一管理 |
| 配置变更 | 需手动清理旧连接 | 通过版本号 purge 后重建 |
| 多租户容量 | 难控制 | worker 内 LRU 控制连接名数量 |

### 3.6 主库（Master Database）

主库 `practical_master` 存储租户元信息，不与学校业务数据混合。

#### 表结构

**schools（学校信息）**

```
schools
  - school_id（PK）
  - school_name（学校名称）
  - school_code（唯一标识，用于子域名和库名）
  - school_domain（访问域名）
  - school_contact（联系人）
  - school_scale: small / medium / large
  - status: enabled / disabled
  - created_at, updated_at
```

**databases（数据库连接配置）**

```
databases
  - database_id（PK）
  - database_host（主机）
  - database_port（端口，默认 3306）
  - database_user（用户名）
  - database_pwd（密码，AES-256-GCM 加密存储，仅在注册租户连接时解密）
  - database_db（库名，如 practical_school_a）
  - database_charset（默认 utf8mb4）
  - database_prefix（表前缀，可选）
  - config_version（连接配置版本，配置变更时递增）
  - status: enabled / disabled
  - created_at, updated_at
```

**authorizations（域名-学校-数据库绑定）**

```
authorizations
  - authorization_id（PK）
  - authorization_domain（唯一，如 school-a.practical.com）
  - school_id（关联 schools）
  - database_id（关联 databases）
  - status: enabled / disabled
  - created_at, updated_at
```

#### 启动预加载策略

`app/server/tenant/TenantBootstrap.php`，在 webman `onWorkerStart` 时执行：

```
1. 查询主库 COUNT(*) FROM authorizations WHERE status='enabled'
2. ≤ 3 个租户：
   → 全部预加载到 Redis Hash
   → 预注册租户连接名，连接由 DatabaseManager 按需建立
3. > 3 个租户：
   → 仅加载域名→ID 映射到 Redis
   → 请求时懒加载连接配置 + 动态注册连接名
   → 超出 globalMaxSize 时 LRU purge
```

连接数控制：

| 租户数 | 连接策略 | 单 worker 连接数 |
|---|---|---|
| ≤ 3 | 全量长连接 | 3 |
| 4-20 | 按需建立 + 空闲回收 | 动态 |
| > 20 | 动态连接名（按 globalMaxSize 限制） | ≤ globalMaxSize |

### 3.7 新建学校流程

```
超级管理员操作：
  1. 填写学校信息 → 写入主库 schools 表
  2. 添加数据库配置 → 写入主库 databases 表
  3. CREATE DATABASE {database_db}（库名由 databases 表配置决定）
  4. 从 practical_template 导出结构与种子数据后导入新库，或执行租户 migration + seed
  5. 校验表结构版本、默认角色、默认菜单、默认配置项完整
  6. 添加域名绑定 → 写入主库 authorizations 表
  7. 清除 Redis tenant:domain:{domain} 缓存
```

### 3.8 Redis 缓存命名空间

共享 Redis 中，所有缓存 key 必须包含 database_id 前缀（非 school_id）避免跨租户冲突。同一学校可能有多个数据库（生产库/测试库），database_id 唯一：

```
# 域名→数据库映射
tenant:domain:{domain}  →  database_id
tenant:db:{database_id}  →  {host, port, user, pwd, db}

# UUID 双向映射
tenant:{database_id}:uuid:{table}:{uuid}  →  id（TTL 3600）
tenant:{database_id}:uuid_rev:{table}:{id}  →  uuid（TTL 3600）

# 配置缓存（按上下文）
config:ctx:{database_id}:{college_id}:{user_id}  →  Hash（TTL 3600）

# 幂等请求
idempotent:{database_id}:{token}  →  1（TTL 60s）

# CSRF token（浏览器 Cookie JWT 写接口）
csrf:{database_id}:{jti}  →  token（TTL 与 JWT 一致）

# 模拟登录
impersonate:{token}  →  JSON {database_id, account_id, role_id, operator_user_id}（TTL 300s，一次性消费后 DEL）

# JWT 黑名单（设备远程下线）
jwt_blacklist:{jti}  →  1（TTL = JWT 剩余有效时间）

# 登录限流
login_attempt:{ip}:{account}  →  count（TTL 300）
login_attempt:{ip}:*  →  count（TTL 60）
login_attempt:*:{account}  →  count（TTL 300）

# 角色权限
rbac:role:{database_id}:{role_id}:permissions  →  Set（变更时清除）
```

### 3.9 全局上下文辅助类

`app/server/CurrentContext.php`，封装 `Context` 读取，提供全项目统一的当前请求信息访问入口。所有 Service、Controller、Middleware 均通过此类获取上下文，不直接调用 `Context::get()`。

```php
class CurrentContext
{
    // ========== 基础标识（从 JWT + TenantMiddleware 注入，O(1) 零开销）==========

    /** 当前登录用户 ID（users.id），未登录返回 0 */
    public static function userId(): int

    /** 当前账号 ID（account.id），未登录返回 0 */
    public static function accountId(): int

    /** 当前角色 ID（role.id），未登录返回 0 */
    public static function roleId(): int

    /** 当前角色类型 */
    public static function roleType(): string
    // 返回值：super_admin / school_admin / college_admin / profession_admin / teacher / student / enterprise

    /** 当前请求对应的 database_id（主库 databases 表），未解析返回 0 */
    public static function databaseId(): int

    /** 当前请求对应的数据库名 */
    public static function databaseName(): string

    // ========== 角色上下文 ID（从 sys_organization 表 + 档案表注入，O(1)）==========

    /**
     * 当前角色绑定的学院 ID（sys_organization.dep_id）
     * college_admin 角色：其管辖的学院 ID，可有多个组织范围
     * teacher 角色：teacher_list.dep_id
     * student 角色：students.dep_id
     * 无学院上下文返回 0
     */
    public static function collegeId(): int

    /**
     * 当前角色绑定的专业 ID
     * profession_admin 角色：管辖的专业 ID，可有多个组织范围
     * student 角色：students.profession_id
     * 无专业上下文返回 0
     */
    public static function professionId(): int

    /**
     * 当前角色绑定的班级 ID
     * student 角色：students.class_id
     * 无班级上下文返回 0
     */
    public static function classId(): int

    /**
     * 当前角色关联的企业 ID（companies.company_id）
     * enterprise 角色：sys_organization.company_id，可有多个企业范围
     * 非企业用户返回 0
     */
    public static function enterpriseId(): int

    /**
     * 当前管理员角色的数据范围。
     * 返回 sys_organization 中当前 account/role 下未禁用的组织/企业范围列表。
     * 非管理员角色返回空数组。
     */
    public static function organizationScopes(): array

    // ========== 完整实体（首次调用查 DB/Redis，同请求内 Context 缓存）==========

    /** 当前 users 行 */
    public static function user(): ?array

    /** 当前 account 行 */
    public static function account(): ?array

    /** 当前学校信息（主库 schools 行） */
    public static function school(): ?array

    /** 当前学生档案（students 行），非学生角色返回 null */
    public static function student(): ?array

    /** 当前教师档案（teacher_list 行），非教师角色返回 null */
    public static function teacher(): ?array

    // ========== 角色判断 ==========

    public static function isAuthenticated(): bool   // 是否已登录
    public static function isSuperAdmin(): bool      // 超级管理员（当前学校库内最高权限）
    public static function isSchoolAdmin(): bool     // 学校管理员（管理本校基础数据）
    public static function isCollegeAdmin(): bool    // 学院管理员（管本院数据）
    public static function isProfessionAdmin(): bool // 专业管理员（管指定专业数据）
    public static function isTeacher(): bool         // 教师
    public static function isStudent(): bool         // 学生
    public static function isEnterprise(): bool      // 企业用户
}
```

**实现要点：**

- `userId()/accountId()/roleId()/collegeId()/databaseId()` 直接从 Context 读取，O(1) 零开销，可高频调用
- `organizationScopes()` 从 `sys_organization` 读取当前角色的数据范围，支持一个账号管理多个学院、多个专业或多个企业
- `user()/account()/school()/student()/teacher()` 首次调用查 Redis → DB，结果写入 Context 缓存，同请求内后续调用直接返回，避免重复查询
- 所有方法返回简单类型（int/string/array），不返回 Model 实例，避免跨服务耦合
- `isSuperAdmin()` 等角色判断基于 `roleType()`，不查 DB

**使用示例：**

```php
// 业务代码中
$databaseId = CurrentContext::databaseId();
$studentId = CurrentContext::userId();

// 权限判断
if (CurrentContext::isTeacher()) {
    $guidedStudents = PairService::getStudents(CurrentContext::teacher()['teacher_id']);
}

// 日志记录
LogService::write(
    userId: CurrentContext::userId(),
    databaseId: CurrentContext::databaseId(),
    module: 'internship',
    action: 'approve',
);
```

## 4. 设计原则

- 服务层（app/server）只暴露 service 类和中间件，不注册独立路由
- 所有路由统一在 app 下注册，权限中间件全局覆盖
- 通用业务逻辑封装为服务类，业务模块按需调用
- 租户业务主表默认包含 `created_at`、`updated_at`、`deleted_at`，支持软删除；主库元数据、日志分表、归档表和纯关联表按表定义处理
- 工作流主状态优先使用：`draft` / `wait` / `accept` / `modify`；登录、设备、启用禁用、签署、归档等特殊状态按各表定义
- 数据库即租户边界，表中不设 school_id 字段
- 字段命名约定：`dep_id` 与 `college_id` 等价，均指向院系/部门实体。组织权限表 `sys_organization` 与业务表（students、teacher_list、pair、grade_teacher_guide）使用 `dep_id`，配置表 `config_item` 使用 `college_id`，语义相同但按上下文选用

## 5. 关键决策

| 决策项 | 选择 | 理由 |
|---|---|---|
| 多租户 | 独立数据库，域名 → school_code → 动态切换连接 | 物理隔离，无须 school_id 字段，查询无额外过滤开销 |
| ORM | illuminate/database (Laravel Eloquent) | 严格 MVC，生态成熟 |
| RBAC 模型 | RBAC + sys_organization 组织范围 + 业务关系 | 数据可见性由组织范围和业务关系动态推导 |
| 前端架构 | H5 和 PC 两个独立项目 | 各自体验最优 |
| 用户体系 | users + account + students/teacher_list | 身份层与档案层分离 |
| 数据范围 | 数据隔离由库边界保证，库内按学院/指导关系过滤 | 物理隔离 + 逻辑过滤双层保障 |
| 指导关系 | pair 统一表 | 实习/实训/实验三模块复用 |
| 签到日志 | sign_in / journal 多态表 | 三模块复用 |
| 关系存储 | 关系型数据一律使用中间表，禁用 JSON 字段存储关联 ID；表单结构、配置、快照可使用 JSON | 保证索引查询和数据完整性 |
| ID 混淆 | UUID 对外暴露 + 内部 ID 转换，Redis 缓存 | 防止 ID 枚举攻击 |
| 文件存储 | public/files/{block}/{school_code}/{category}/{yyyymmdd}/{uuid}.{ext} | block 支持多盘扩容 |
| 文件下载 | 直接 URL 访问（默认），?n= 参数改名，API 备选 | nginx 直接返回，零 PHP 开销 |
| 消息通道 | 渠道驱动架构，模板配置 channels 数组 | 新增渠道只需新增驱动类 |
| Agent 就绪 | 查询服务统一接口 + 能力清单 | 后续可直接封装 Agent Skill |
| 防重复提交 | 前端指令 + 后端幂等中间件 + 请求 token | 高并发下双重保障，Redis 校验 60 秒窗口 |

## 6. UUID 混淆层

### 6.1 设计目的

所有对外 API 使用 UUID 替代自增 ID，防止攻击者通过递增 ID 枚举数据。

### 6.2 适用范围

需对外暴露 ID 的实体均添加 `uuid` 字段：

| 实体 | 所在表 | UUID 字段 |
|---|---|---|
| 学生/教师/管理员 | account | uuid |
| 实习安排 | arrangement | uuid |
| 实训项目 | training_project | uuid |
| 实验项目 | lab_project | uuid |
| 实习申请/日志/报告/成绩 | application / journal / report / score | uuid |
| 基础档案 | department / grade_list / profession / profession_direction / class / companies | uuid |
| 企业、基地、导师 | companies / base / enterprise_mentor | uuid |
| 文档/模板/消息/文件 | doc_article / template / message / file | uuid |
| 导出任务 | export_task | uuid |

表结构简表未逐项列出的，开发 migration 时按本规则补充 `uuid` 字段。论文系统兼容字段如 `student_id`、`teacher_id`、`dep_id` 仅作为内部业务主键，不直接暴露给前端路径参数。

### 6.3 UuidService

位置：`app/server/uuid/UuidService.php`

```
encode(string $table, int $id): string
  1. 查 Redis: tenant:{database_id}:uuid_rev:{table}:{id}
  2. 命中直接返回
  3. 未命中 → 查 DB → 写入 Redis → 返回

decode(string $table, string $uuid): int
  1. 查 Redis: tenant:{database_id}:uuid:{table}:{uuid}
  2. 命中直接返回
  3. 未命中 → 查 DB → 写入 Redis → 返回
  4. 查不到抛 NotFoundException
```

### 6.4 Redis 缓存策略

```
Key:  tenant:{database_id}:uuid:{table}:{uuid}       → id        TTL: 3600
Key:  tenant:{database_id}:uuid_rev:{table}:{id}     → uuid      TTL: 3600
```

### 6.5 请求转换

推荐路由中间件方式，UUID 自动转换为内部 ID：

```php
Route::get('/api/internship/students/{studentUuid}/journals', [...])
    ->resolveUuid('studentUuid', 'students', 'student_id');
```
