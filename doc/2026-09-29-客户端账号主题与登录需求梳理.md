## 3. 角色与组织归属

### 3.1 角色字段联动

目前用户编辑页仅对学生和老师显示学院字段，管理员角色没有相应选择。修改角色后，界面应根据目标角色展示并校验所需的组织字段。

| 角色 | 组织归属要求 |
| --- | --- |
| 超级管理员 | 不绑定学院 |
| 学校管理员 | 不绑定学院 |
| 学院管理员 | 必须绑定学院 |
| 专业管理员 | 必须绑定学院和专业，且专业属于该学院 |
| 老师 | 按现有规则维护学院和专业 |
| 学生 | 按现有规则维护年级、学院、专业和班级 |
| 企业导师 | 沿用现有企业或基地归属规则 |

规则：

- 改变角色后立即显示角色需要的组织字段。
- 必填组织范围为空或不匹配时，禁止保存并给出明确提示。
- 从需要组织范围的角色改为不需要的角色时，清理不适用的字段，并提示管理员。
- 从老师改为学院管理员时，已有学院可以作为候选值，但必须确认其仍有效。
- 角色变更和组织范围变更均由服务端校验，不能只依赖前端字段。
- 组织选项必须限制在操作者可管理范围内。
- 角色和组织变更记录进入操作审计。

### 3.2 组织范围数量

学院管理员默认至少绑定一个学院；专业管理员默认绑定一个学院和一个专业。若账号需要跨多个学院或专业，应通过现有数据权限范围配置，不扩大角色字段的单值含义。

## 4. 账号关联与角色切换

### 4.1 当前能力

现有系统已有切换账号入口。切换列表会聚合同一用户的账号，以及使用同一已验证手机号的账号。个人设置和用户管理中目前没有清晰的“添加关联账号”流程。

账号关联与企业微信绑定必须区分：

- 账号关联用于切换同一用户持有的不同系统账号或角色。
- 企业微信绑定用于把某一个系统账号映射到企业微信成员。
- 手机号相同不能代替关联流程中的双方账号验证。

### 4.2 已确认入口

账号关联入口放在“个人设置 → 账号与角色切换”。新增关联时须验证当前账号与待关联账号双方身份，然后才加入切换列表。

交互包括：

- 显示当前账号和已关联账号、角色、学院/专业范围及账号状态。
- 添加账号、切换账号、解除关联。
- 添加时验证待关联账号凭据，并要求当前账号再次确认。
- 关联后刷新切换列表、权限、菜单和数据范围。
- 解除后立即从当前账号的切换列表移除关联账号。
- 提示切换不会合并两个账号的业务数据、消息或文件。

服务端要求：

- 关联只允许发生在同一学校。
- 两端账号均须有效，当前操作者只能管理自己的关联。
- 关联和解除均写审计日志。
- 不通过客户端传入账号 ID 就授予账号切换能力。
- 保留现有同一用户账号的兼容行为；已验证手机号自动聚合的保留范围需在实施前核实，不能让手机号单独成为绕过双方验证的入口。

## 5. 指定人员消息不自收

### 5.1 当前原因

当前消息服务的 include_sender 默认值为 true，会将消息发送者加入最终收件人，因此站内和企业微信渠道都可能收到自己发送的消息。

### 5.2 目标

- 指定人员、按角色、发送给全部账号三种方式默认均排除发送者。
- 增加“发送一份给自己”选项，默认关闭。
- 发送者明确勾选后可收到自己发出的消息。
- 前端收件人预览和服务端最终名单保持一致。
- 站内、企业微信和短信都使用相同的收件人集合。
- 发送者被明确选中时只保留一个收件人记录。
- 发送结果中的人数按最终收件人计算。
- 保留消息发起者的审计信息，即使发起者不是收件人。

## 6. 客户端启动与企业微信登录

### 6.1 消除网页版登录框闪现

客户端连接成功后，当前会先显示 PC 网页登录框，再完成客户端登录。应调整为有明确加载态的启动流程：

1. 客户端显示自身连接页或启动状态。
2. 完成本地连接信息、自动登录和会话 bootstrap。
3. 已有有效会话时直接进入桌面，不挂载网页版登录表单。
4. 未登录时显示客户端登录页。
5. 必须绑定企业微信时进入绑定或扫码页面。
6. 连接失败时显示错误和重试操作。

退出登录、切换学校或连接失败时清理旧会话状态，避免先显示不属于当前学校/账号的登录页面。

### 6.2 企业微信扫码登录

登录页提供账号密码和企业微信扫码两种方式：

- 仅已绑定企业微信的系统账号可以通过扫码直接登录。
- 二维码使用短时、一次性随机票据，不含账号密码、JWT 或个人身份信息。
- 服务端校验学校、CorpId、企业微信成员、绑定关系和账号状态。
- 未绑定的成员扫码时不创建系统登录会话；提示先用账号密码登录并完成绑定。
- 账号密码登录后，如学校启用强制绑定，应进入现有绑定流程。
- 绑定成功后刷新会话、权限和菜单再进入桌面。
- 取消、过期、退出、切换学校时令扫码会话失效。
- 扫码登录不能绕过学校现有企业微信强制绑定策略。
- 若一个企业微信成员关联多个系统账号，登录时必须明确选择目标角色账号；账号选择范围只限经验证关联的账号。

## 7. 桌面主题、字体和暗黑模式

### 7.1 桌面文字可读性

- 桌面模块标题和快捷方式文字默认使用白色。
- 对文字增加阴影或其他对比度处理，确保浅色壁纸上仍可辨认。
- 任务栏、窗口标题栏、表单、弹窗文字分别按主题配置，不把整个应用文字强制设为白色。
- 颜色通过统一主题变量管理。

### 7.2 暗黑模式

支持亮色、暗色和跟随系统三种模式。应用于：

- 登录页、桌面、任务栏和窗口。
- 表格、输入框、按钮、菜单、弹窗和通知。
- 扫码绑定、错误提示和客户端设置页。

模式默认值仍待确认。主题选择仅本地生效，不改变学校默认壁纸、个人壁纸或共享壁纸。

### 7.3 主题模块

把客户端的桌面壁纸设置升级为“主题”模块，提供预置主题和本地自定义：

- 提供多款预置配色和明暗主题。
- 可选择本地壁纸并调整桌面文字颜色、强调色、窗口颜色、透明度和图标布局密度。
- 可以预览、应用、恢复默认和删除自定义主题。
- 本地壁纸及主题设置只保存在当前客户端，不上传学校或个人服务器。
- 按学校与本机用户隔离本地主题，避免切换学校后误用另一学校的桌面设置。
- 与服务器已有的个人壁纸、共享壁纸、学校默认壁纸分开；本地主题不能修改或覆盖服务器上的设置。

## 8. 外部地址打开方式

为收藏、插件及外部地址增加“当前页打开”：

- 当前页打开：在当前模块或弹窗内容区域内显示目标页面。
- 客户端窗口：在新的客户端窗口打开。
- 外部浏览器：交给系统默认浏览器。
- 新增选项不改变已有链接的打开方式。
- 页面需要返回、关闭、显示加载失败状态。
- 跨域地址不得带入学校系统 Cookie、JWT 或内部凭据。
- 仅对经过现有安全策略允许的地址开放内嵌显示。
- 内部模块是否也能替换当前内容区，待确认；草案默认只用于外部地址。

## 9. 本地密码保存与云同步

### 9.1 本地保存

客户端保存账号密码，主要用于外部站点的登录辅助：

- 默认只保存在本机。
- 优先使用 macOS Keychain、Windows Credential Manager、Linux Secret Service 等系统安全凭据存储。
- 禁止明文写入普通配置文件、日志、URL、崩溃报告或普通同步设置。
- 按学校、当前系统账号和外部站点来源隔离凭据。
- 个人设置提供凭据列表、删除单条和清空全部。
- 自动填充只作用于用户明确保存的站点和表单，不在页面上明文展示密码。
- 退出学校系统时清除当前会话；是否同时删除本地凭据由单独操作控制。

### 9.2 云同步

用户已确认：云端采用服务器密钥加密，优先跨设备同步便利。

- 个人设置新增“云同步密码”开关，默认关闭。
- 开启前说明服务器密钥加密的边界：服务器具备解密能力，不能表述为端到端加密。
- 服务端使用独立保险库表，按学校、用户、账号和外部站点隔离。
- 数据库仅存密文、nonce、密钥版本及必要的加密元数据。
- 加密密钥由服务端密钥管理机制保管，不存入同一数据库表。
- 日志、消息、导出和普通 API 响应不得泄露明文密码。
- 管理界面不提供管理员查看他人密码的能力。
- 只有凭据所有者的受认证会话可同步相应密文。
- 关闭同步时明确区分“停止同步”与“删除服务器副本”，删除服务器密文须经用户确认。
- 密钥轮换、备份恢复和密钥丢失对历史密文的影响需纳入部署方案。
- 外部站点密码变更后，允许更新本地副本并按设置重新同步。

## 10. 顶部标题栏

将桌面右下角的个人中心、头像、在线状态、下载、退出登录和时间移动到最上方标题栏：

- 与关闭、最大化、最小化系统按钮处于同一水平区域。
- 用户信息和操作放在标题栏右侧。
- Windows 风格系统按钮靠右，用户信息位于其左侧。
- macOS 保留红黄绿窗口按钮的左侧习惯，用户信息位于标题栏右侧。
- 标题栏可拖动区域不能覆盖头像、按钮、菜单和可点击信息。
- 小窗口、登录页及移动布局隐藏桌面专用信息。
- 关闭、最大化、还原、退出登录时正确收起菜单和浮层。

## 12. 权限、安全与审计边界

- 角色与学院、专业范围在服务端共同校验。
- 账号关联须验证双方身份并限制在同一学校。
- 企业微信扫码登录不能绕过未绑定策略。
- 消息发送默认排除发送者，企业微信渠道不得自行追加发送者。
- 本地密码使用系统安全存储。
- 云同步密码按用户隔离并由独立服务端密钥加密；服务器有解密能力这一点必须在界面告知。
- 外部网页不得自动获得学校系统身份凭据。
- 账号关联、角色变更、密码同步开关、消息发送及扫码登录操作均记录必要审计信息。
