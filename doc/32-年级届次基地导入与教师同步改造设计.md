# 年级届次、基地导入与教师同步改造设计

## 1. 业务口径

- 年级指学生入学年级，例如 `2024级`。
- 毕业届次指学生计划或实际毕业届次，例如 `2028届`。
- 毕业实习按毕业届次组织和查询。
- 认识实习、生产实习、岗位实习、课程实习、其他实习按年级组织和查询。
- 实验、实训和社会实践按年级组织和查询。
- 基地申报年份是基地建设历史字段，不属于年级或毕业届次。
- 本文件中的教师同步只维护教师档案，不创建登录账号。教师或学生与用户绑定后才能登录。教学计划主动拉取及待接收确认规则见《实习基地、计划、任务与实施改造设计》。

## 2. 年级与毕业届次

### 2.1 数据表

现有 `grade_list` 恢复为年级表，继续供学生、专业、班级、实验实训和非毕业实习使用。

新增 `graduation_cohort`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| cohort_id | BIGINT UNSIGNED | 主键 |
| cohort_uuid | CHAR(36) | 业务 UUID |
| cohort_name | VARCHAR(80) | 届次名称，例如 2028届 |
| cohort_year | SMALLINT UNSIGNED | 毕业年份 |
| is_current | ENUM('true','false') | 是否当前毕业届次 |
| sort | INT | 排序 |
| flag | ENUM('on','off') | 是否启用 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |
| deleted_at | DATETIME | 软删除时间 |

`cohort_year` 在未软删除记录中唯一。只允许一个启用记录标记为当前毕业届次。

`students` 增加：

- `graduation_cohort_id`：毕业届次，可为空。
- 教务同步、Excel 导入和后台编辑均可维护该字段。
- 不根据入学年级自动推算毕业届次。

### 2.2 实习类别

新增 `internship_category`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT UNSIGNED | 主键 |
| uuid | CHAR(36) | 业务 UUID |
| code | VARCHAR(80) | 唯一代码 |
| name | VARCHAR(80) | 类别名称 |
| scope_type | ENUM('grade','cohort') | 年级或毕业届次 |
| sort | INT | 排序 |
| status | ENUM('enabled','disabled') | 状态 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |
| deleted_at | DATETIME | 软删除时间 |

预置类别：

| 代码 | 名称 | 归属维度 |
| --- | --- | --- |
| graduation | 毕业实习 | cohort |
| cognition | 认识实习 | grade |
| production | 生产实习 | grade |
| position | 岗位实习 | grade |
| course | 课程实习 | grade |
| other | 其他实习 | grade |

超级管理员可维护类别。已被业务数据引用的类别不允许修改 `scope_type`，只允许修改名称、排序和启用状态。

### 2.3 实习计划

`internship_plan` 增加：

- `category_id`：实习类别，必填。
- `graduation_cohort_id`：毕业届次。
- 保留 `grade_id` 作为入学年级。

保存规则：

- 类别为 `scope_type=grade` 时，必须填写 `grade_id`，`graduation_cohort_id` 必须为空。
- 类别为 `scope_type=cohort` 时，必须填写 `graduation_cohort_id`，`grade_id` 必须为空。
- 后端统一校验归属维度，前端不提供人工切换维度的控件。
- 实习任务、任务绑定、实施表和过程记录通过实习计划继承归属维度，不重复维护两套口径。

### 2.4 数据迁移

- 现有 `grade_list` 数据保留，管理名称由“届次”恢复为“年级”。
- 名称符合 `YYYY级` 的记录直接作为年级使用。
- 现有实习计划名称或课程名称明确包含“毕业实习”的，迁移为毕业实习类别；未维护毕业届次时降为草稿并提示补充。
- 其余现有实习计划迁移为其他实习类别并保留原 `grade_id`。
- 实验实训现有 `grade_id` 数据保持不变，只将界面和文案恢复为年级。
- 不从年级推算或批量生成学生毕业届次。

### 2.5 管理入口

- 现有“届次管理”改名为“年级管理”。
- 新增“毕业届次管理”。
- 两者放在数据管理模块，可从启动台添加到桌面，不作为不可移除的默认桌面模块。
- 年级筛选默认选择当前年级；毕业实习筛选默认选择当前毕业届次。

## 3. 实习基地 Excel 导入

### 3.1 导入流程

1. 上传 `.xlsx` 文件。
2. 校验文件大小、工作表、表头和最大行数。
3. 解析并显示导入预览、重复记录和错误明细。
4. 校验学院、专业、年份、数字字段和必填字段。
5. 任一学院或专业不存在时，整批禁止导入。
6. 用户确认后在单个数据库事务中写入。
7. 任一写入失败时整批回滚。
8. 返回新增、跳过和失败统计及对应行号。

正式导入不自动创建学院和专业。合作单位属于基地业务数据，可按单位名称复用或创建 `companies` 记录。

### 3.2 唯一规则

- 基地主档案：`基地名称 + 依托学院 + 合作或依托单位`。
- 年度申报：`基地 + 申报年份`。
- 年度接纳快照：`年度申报 + 统计年份`。
- 重复上传时跳过已有数据，不覆盖后台人工修改的数据。

### 3.3 数据表

新增 `base_declaration`：

| 字段 | 说明 |
| --- | --- |
| id、uuid、base_id | 主键及基地关联 |
| declaration_year | 申报年份 |
| base_category | 文科实践教育基地、工程实践教育中心、理科实践教育基地 |
| base_level | 核心基地、骨干基地、特色基地 |
| project_status | 是否立项 |
| approved_amount | 立项经费 |
| industry_cobuilt | 是否与行业企业共建 |
| service_profession_count | 服务校内专业个数快照 |
| curriculum_in_plan | 课程是否列入培养方案 |
| unit_type | 单位类型 |
| enterprise_level | 世界 500 强、中国 100 强或其他分类 |
| teacher_count | 基地指导教师总数 |
| external_teacher_count | 校外教师数 |
| planned_content | 计划实习内容 |
| expected_student_visits | 年预计接纳学生人次数 |
| expected_student_days | 年接纳学生生天数 |
| has_signboard | 是否挂牌 |
| has_agreement | 是否签订协议 |
| remark | 备注 |
| source_edited_at、source_editor、source_admin | 原表编辑信息 |
| created_at、updated_at、deleted_at | 通用字段 |

新增 `base_reception_stat`：

- `declaration_id`：年度申报记录。
- `stat_year`：统计年份。
- `student_count`：实际接纳人数。
- 唯一约束为 `declaration_id + stat_year`，保留不同申报年度对历史人数的快照差异。

`base_budget` 增加 `declaration_id`，七类经费预算和立项经费按年度申报记录保存。原有非年度预算允许该字段为空。

`base` 和关联表保存稳定资料：

- 基地名称、长期基地、学院、地址、所在市区县。
- 基地负责人、联系电话。
- 合作单位及联系人、联系电话。
- 服务课程和服务专业关系。
- 所有本次 Excel 数据的 `base_type` 固定为 `long_term`。

Excel 中“核心基地、骨干基地、特色基地”保存到 `base_declaration.base_level`，不写入 `base.base_type`。

### 3.4 本次测试数据

- 从 Excel 创建缺失的 11 个学院。
- 按“学院 + 专业名称”创建缺失专业。
- 学院临时代码使用 `IMPORT_DEP_三位序号`，专业临时代码使用 `IMPORT_PRO_三位序号`，均先按名称检查后再创建，保证重复执行不新增重复档案。
- 新建专业关联当前年级，并关联 Excel 对应学院。
- 后续教务同步按学院和专业名称匹配后更新正式代码。
- 基础档案准备完成后调用正式导入服务，不另写一次性数据库脚本。
- 预计写入约 130 个基地主档案和 135 条年度申报记录，最终数量以事务返回结果为准。

## 4. 校内指导教师同步

### 4.1 教师档案

`teacher_list` 增加：

- `external_id`：教务系统教师唯一 ID。
- `gender`、`birth_date`、`title`、`education`、`phone`、`email`。
- `employment_type`：任职类型。
- `sync_source`：同步来源。
- `source_updated_at`：来源系统更新时间。
- `last_synced_at`：本系统最后同步时间。

幂等匹配优先使用 `external_id`，其次使用 `teacher_num`。未出现在同步批次中的教师不自动停用，只有明确传入 `status=disabled` 时停用。

`base_person` 增加 `teacher_id`。校内指导教师保存教师关联和资料快照；企业指导教师继续手工填写，不关联教师档案。

新增 `open_sync_app` 保存学校业务库的开放应用凭据、状态和密钥更新时间；新增 `teacher_sync_batch` 保存 `request_id`、来源、接收数量、处理结果和错误摘要。Controller 不直接访问这两张表。

### 4.2 推送字段

必填字段：

- `external_id`
- `teacher_num`
- `teacher_name`
- `department_code`
- `status`
- `source_updated_at`

可选字段：

- `profession_code`
- `gender`
- `birth_date`
- `title`
- `education`
- `phone`
- `email`
- `employment_type`

学院和专业只按代码匹配。不存在时该条同步失败并返回明细，不自动创建基础档案。

### 4.3 推送接口

使用 Webman 默认路由：

```http
POST /api/open-teacher-sync/push
X-App-Id: {app_id}
X-Timestamp: {unix_timestamp}
X-Nonce: {random_string}
X-Signature: {signature}
Content-Type: application/json
```

请求体：

```json
{
  "request_id": "sync-20260730-001",
  "teachers": [
    {
      "external_id": "teacher-10001",
      "teacher_num": "T10001",
      "teacher_name": "张三",
      "department_code": "08",
      "profession_code": "080701",
      "gender": "male",
      "birth_date": "1985-06-12",
      "title": "副教授",
      "education": "硕士",
      "phone": "13800000000",
      "email": "teacher@example.com",
      "employment_type": "full_time",
      "status": "enabled",
      "source_updated_at": "2026-07-30 10:00:00"
    }
  ]
}
```

单次最多 500 条。`request_id` 在同一学校业务库中唯一。

### 4.4 签名

签名原文：

```text
app_id\ntimestamp\nnonce\nsha256(raw_body)
```

使用分配的 `app_secret` 计算 `HMAC-SHA256`，输出小写十六进制字符串。服务端要求：

- 时间戳与服务器时间相差不超过 300 秒。
- `nonce` 在 Redis 中保存 300 秒，同一 `app_id + nonce` 不允许重复使用。
- 使用恒定时间比较签名。
- 使用 `request_id` 防止业务重复写入。

开放应用凭据保存在学校业务库，密钥使用应用密钥加密保存。应用可停用和轮换密钥。主动拉取地址、对方应用编号和密钥由系统配置维护，敏感字段不返回明文。

### 4.5 返回结构

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "request_id": "sync-20260730-001",
    "received": 100,
    "created": 20,
    "updated": 78,
    "disabled": 2,
    "failed": 0,
    "errors": []
  }
}
```

错误项包含数组下标、教师编号、字段和错误信息，不返回服务器异常堆栈。

### 4.6 主动拉取

后台“同步教师”调用同步服务，按游标请求教务系统：

```http
GET {configured_url}/open-api/teachers?updated_after={time}&cursor={cursor}&limit=500
```

教务系统返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "items": [],
    "next_cursor": "",
    "has_more": false
  }
}
```

主动拉取和开放推送复用同一个同步 Service 和 Model 写入方法。Controller 只处理请求、鉴权和响应，不直接查询数据库。

## 5. PC 公共交互

### 5.1 基地筛选和编辑

- 基地列表第一排显示关键词、学院、专业、基地性质和状态。
- 更多筛选显示基地类别、基地等级、合作单位和申报年份。
- 学院、专业使用可搜索级联下拉。
- 学院管理员和专业管理员默认选中并限制本人数据范围。
- 基地列表不显示年级或毕业届次筛选。
- 基地编辑中的学院、服务专业使用下拉选择。
- 校内指导教师从教师档案搜索选择，可触发教务同步后刷新选项。
- 企业指导教师继续手工维护。

### 5.2 公共弹窗

新增公共 `AppModalWindow`：

- 支持普通、放大、最大化、恢复和关闭。
- 普通状态支持拖动改变尺寸。
- 双击标题或点击图标最大化。
- 最大化范围避开 PC 顶部栏和底部任务栏。
- 标题和底部操作区固定，内容区独立滚动。
- 保存期间禁止重复提交和误关闭。

本次将现有使用 `operation-mask`、`operation-dialog` 的 PC 业务弹窗统一到该组件，不在模块内重复实现窗口状态。桌面窗口、启动台和系统原生确认框不属于业务弹窗，不套用该组件。

### 5.3 模块布局和列表

- 公共模块左侧菜单支持折叠；折叠后显示图标，右侧内容自动扩宽。
- 折叠状态按用户和模块保存到 `localStorage`。
- 公共列表右上角增加“显示字段”下拉复选。
- 主标识列和操作列不可隐藏。
- 字段选择按“用户 ID + 模块 + 列表”保存到 `localStorage`。
- 页面刷新后恢复选择，不增加数据库表。

### 5.4 Tab

- 基地详情及同类页面使用公共 Tab 样式。
- 默认状态为普通文字；激活状态使用主题色、适当字重和底部指示线。
- 不使用整块按钮边框或卡片背景。
- 数量作为紧凑文字徽标显示，不改变 Tab 高度。

### 5.5 性别下拉修复

现有原生输入框 CSS 命中了 Element Plus 下拉框内部输入元素，导致性别下拉出现双层白色输入框。原生表单样式限制为直接子元素，Element Plus 组件内部样式由组件自身控制。该修复应用于所有同类动态表单。

## 6. 权限和日志

- 年级、毕业届次和实习类别维护仅允许超级管理员及具备对应权限的学校管理员操作。
- 基地录入和导入允许学校管理员、学院管理员和专业管理员操作，并继续应用组织数据范围。
- 教师主动同步仅允许学校管理员和超级管理员触发。
- 开放推送接口使用独立应用凭据，不使用用户登录令牌。
- 导入、同步、类别变更、当前年级和当前毕业届次切换写入全局操作日志。
- 日志操作名称来自 Controller 和 Service 方法用途注释及明确的操作代码。

## 7. 代码边界

- 后端代码放在 `server`，PC 前端代码放在 `fontend/pc`。
- 不修改 Webman 框架代码和自定义路由配置，使用默认路由。
- Controller 不直接编写数据库查询。
- 所有查询条件和写入方法封装在对应 Model 中。
- 教师同步、基地导入和时间维度校验分别由独立 Service 负责。
- Excel 解析复用现有 PhpSpreadsheet 依赖和导入模式。
- 前端复用公共筛选、列表、Tab、弹窗和模块布局组件。
