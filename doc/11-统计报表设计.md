# 统计报表设计

## 1. 统计维度（三模块通用）

```
实习/实训/实验 统计：
  ├── 人员维度
  │   ├── 参与人数统计（按学院/专业/班级）
  │   ├── 申请通过率
  │   └── 完成率
  │
  ├── 成绩维度
  │   ├── 成绩分布（按分数段）
  │   ├── 平均分（按学院/专业/班级）
  │   └── 教师评分汇总
  │
  ├── 过程维度
  │   ├── 签到率（仅实习，按日/周/月）
  │   ├── 日志完成率（仅实习）
  │   └── 预约使用率（实训/实验）
  │
  └── 时间维度
      ├── 按学期
      ├── 按学年
      └── 自定义时间段
```

## 2. 数据模型

```
stat_cache（统计缓存，避免实时查询慢）
  - id
  - type（如 internship_score_stat）
  - params（JSON，统计参数）
  - data（JSON，统计结果）
  - expired_at（过期时间；访问时若已过期则异步刷新，当前请求返回旧数据）
  - created_at, updated_at, deleted_at
```

**缓存刷新策略：**

| 统计类型 | 刷新周期 | 触发方式 |
|---|---|---|
| 成绩统计 | 每日 06:00 | 定时任务全量刷新 |
| 签到率统计 | 每小时 | 定时任务增量刷新 |
| 预约使用率 | 每小时 | 定时任务增量刷新 |
| 综合概览 | 每日 06:00 | 定时任务全量刷新 |
| 自定义时间范围 | 按需，expired_at=now+10min | 首次查询时生成缓存，10 分钟后过期 |

```
export_task（导出任务，通用异步任务追踪）
  - id, uuid, user_id
  - type（见下方类型定义）
  - file_name（下载时显示的文件名）
  - params（JSON，导出筛选条件或文件 ID 列表等）
  - status: pending / processing / completed / failed / timeout
  - progress（0-100 百分比）
  - total_rows（总行数，报表类填入）
  - file_id（关联 file 表，完成后填入）
  - error_message（失败原因，用户可读）
  - error_trace（堆栈摘要，前 500 字符，管理员排查用）
  - created_at, updated_at, deleted_at
```

### type 取值

| type | 说明 | 输出格式 |
|---|---|---|
| report_internship_score | 实习成绩报表 | xlsx |
| report_training_score | 实训成绩报表 | xlsx |
| report_lab_score | 实验成绩报表 | xlsx |
| report_sign_in | 签到统计报表 | xlsx |
| report_overview | 综合统计报表 | xlsx |
| export_student_files | 学生上传文件打包下载 | zip |
| export_student_profile | 学生资料导出 | docx / pdf |
| export_student_report | 学生实习/实训/实验报告批量导出 | pdf |

## 3. 导出流程

所有导出统一走异步队列，不阻塞接口响应。

```
用户点击导出
  → 创建 export_task 记录（status=pending）
  → 任务入 Redis 队列
  → 前端提示"导出任务已创建，请稍候"
  → 用户可关闭页面，任务在后台继续

Redis Worker 处理：
  → 更新 status=processing, progress=0
  → 分批查询数据（报表类）或收集文件（打包类）或渲染文档（文档类），每步更新 progress
  → 生成文件写入 public/files/{block}/{school_code}/{type}/{yyyymmdd}/{uuid}.{ext}
  → 写入 file 表记录（is_temporary=1）
  → 更新 status=completed, file_id=xxx, progress=100, total_rows
  → 写入 message 表通知用户下载

失败处理：
  → 任何步骤抛出异常 → status=failed
  → error_message 记录具体失败原因（如"第 3 批数据查询超时"、"磁盘空间不足"）
  → error_trace 记录堆栈摘要（前 500 字符），便于管理员排查
  → 部分产物文件（如有）清理
  → 写入 message 表通知用户"导出失败，点击查看原因"

超时处理：
  → 单个导出任务最长执行 30 分钟
  → 超时自动标记 status=timeout, error_message="导出超时，请缩小筛选范围后重试"
  → 超时任务的临时文件清理
```

### 3.1 导出任务列表

PC 端"导出任务"菜单，表格展示：

| 列 | 说明 |
|---|---|
| 导出类型 | 实习成绩/实训成绩/学生列表/签到统计等 |
| 文件名 | 完成后显示 file_name |
| 状态 | pending / processing / completed / failed / timeout |
| 进度 | 进度条（processing 时显示） |
| 行数 | 完成后显示 total_rows |
| 创建时间 | 任务提交时间 |
| 操作 | 下载（completed）/ 失败原因（failed/timeout）/ 等待中... |

- 仅显示当前用户的任务
- 按创建时间倒序
- processing 中的任务前端每 3 秒轮询刷新状态
- 点击"失败原因"弹出详情弹窗，展示 `error_message` + `error_trace`

### 3.2 失败原因展示

用户点击"失败原因"时弹窗显示：

```
导出失败

任务：实习成绩_2026-05-27.xlsx
失败原因：第 3 批数据查询超时（已处理 1200/3500 行）
时间：2026-05-27 14:32:15

[重试导出]  [关闭]
```

点击"重试导出"使用相同筛选条件创建新的 export_task，原失败记录保留。

### 3.3 跨页面通知

导出完成/失败时写入 message 表通知用户：

```
完成："导出任务完成：实习成绩_2026-05-27.xlsx，点击下载"
失败："导出任务失败：实习成绩_2026-05-27.xlsx，点击查看原因"
```

用户在任何页面都能通过消息红点感知结果，点击消息直接跳转到导出任务列表对应任务。

## 4. 文件存储与下载

### 4.1 存储路径

导出文件存储在 `public/files/` 下，按学校/类型/日期分层：

```
public/files/{block}/{school_code}/{type}/{yyyymmdd}/{uuid}.{ext}

示例：
  public/files/b1/2/report_internship_score/20260527/a3f2b8c1.xlsx
  public/files/b1/2/export_student_files/20260527/b4e3c9d2.zip
  public/files/b1/2/export_student_profile/20260527/c5d4e6f3.docx
```

分层的好处：便于按学校隔离、按类型清理、按日期归档。

### 4.2 Nginx 直接下载

下载走统一接口 `/api/file/download/{uuid}`，PHP 仅做路径解析并设置 `X-Accel-Redirect`，实际文件传输由 nginx 接管，PHP 进程立即释放。浏览器收到的文件名由 `Content-Disposition` 头控制，显示为中文文件名。

详见 `06-文件管理服务设计.md` 第 5 节。

### 4.3 清理策略

- 导出文件写入 file 表（disk=public），统一走文件管理服务
- file_retention_days 配置项控制保留天数（默认 7 天）
- 定时任务清理过期导出文件 + 对应 file 表记录

## 5. Agent 查询接口（预留）

### 5.1 设计原则

报表和统计数据通过统一的服务接口暴露，后续 Agent 可直接调用，无需二次改造。

### 5.2 StatQueryService

`app/server/agent/StatQueryService.php`，实现 `AgentQueryable` 接口：

```
queryPersonStat(int $databaseId, string $module, array $filters): array
  → 人员维度统计：参与人数、通过率、完成率
  → filters: college_id / major_id / class_id / date_range

queryScoreStat(int $databaseId, string $module, array $filters): array
  → 成绩维度统计：分布、平均分、教师评分汇总

queryProcessStat(int $databaseId, string $module, array $filters): array
  → 过程维度统计：签到率、日志完成率、预约使用率
```

返回格式统一：

```json
{
  "title": "实习成绩统计 - 2026年春季学期",
  "summary": {"total": 200, "avg_score": 85.3},
  "distribution": [
    {"range": "90-100", "count": 45},
    {"range": "80-89", "count": 98}
  ],
  "by_college": [...],
  "generated_at": "2026-05-27 10:30:00"
}
```

每个方法返回固定结构，Agent 不需要理解业务细节即可输出可读结果。
