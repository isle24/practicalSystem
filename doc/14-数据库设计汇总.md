# 数据库设计汇总

## 1. 数据库架构

```
practical_master（主库，1 个）
  ├── schools           学校信息
  ├── databases         数据库连接配置
  └── authorizations    域名-学校-数据库绑定

practical_template（模板库，1 个）
  └── 完整表结构 + 种子数据，新建学校时复制

学校业务库（N 个，库名由 databases.database_db 指定，命名建议 practical_{school_code}）
  └── 完整业务表结构，物理隔离
```

## 4. 全局约定

| 规则 | 说明 |
|---|---|
| 主键 | 统一使用自增 `id`，特殊情况用业务主键（如 students.student_id） |
| 软删除 | 学校业务主表默认包含 `deleted_at`，使用 Laravel SoftDeletes；主库元数据、日志分表、归档表和纯关联表按表定义处理 |
| 时间戳 | 业务表默认包含 `created_at`、`updated_at`；日志/归档/关联表按写入场景保留必要时间字段 |
| 工作流状态 | 业务实体统一：`draft` / `wait` / `accept` / `modify` |
| 启用状态 | 基础档案表（department、grade_list、profession、class、companies、template_*）：`flag: on/off`（匹配论文系统）。账号、角色、设备等启用禁用类状态使用 `status: enabled/disabled`；工作流、签署、归档等业务状态按各表定义 |
| 学校隔离 | 独立数据库，表中不设 school_id 字段 |
| UUID | 对外作为路径参数、详情页、编辑页、审核页标识的实体均需有 `uuid` 字段；兼容论文系统的业务主键仅内部使用 |
| 多态关联 | 三模块复用的表（sign_in、journal、pair）通过 `entity_type` + `entity_id` 区分 |
| 关系存储 | 关系型数据一律使用中间表，禁用 JSON 字段存储关联 ID；表单结构、配置、归档快照可使用 JSON |
| ID 暴露 | API 对外使用 UUID，内部使用自增 ID，通过 UuidService 双向转换 |

## 5. 索引策略

以下为通用规则，具体索引在各表定义时细化：

- 所有主键自动建立聚簇索引
- 所有外键字段建立普通索引
- `uuid` 字段建立唯一索引
- `status` + `created_at` 建立联合索引（高频筛选）
- 多态字段 `entity_type` + `entity_id` 建立联合索引
- 软删除查询需包含 `deleted_at IS NULL`，相关索引根据实际查询模式添加
- 关联表中 `(entity_type, entity_id)` 建立联合索引
- 按月分表（operation_log）的查询始终带时间范围，按时间分区即可

### 5.1 并发安全唯一约束

以下唯一约束用于保证并发写入时的数据正确性，与 Redis 分布式锁形成双重保障：

| 表 | 唯一约束 | 目的 |
|---|---|---|
| pair | `(student_id, type, arrangement_id, active_flag)` | 防止同一学生在同一安排下被重复 active 配对，允许 removed 后重新建立 |
| sys_organization | `(account_id, role_id, scope_key, enabled_flag)` | 防止同一账号角色重复配置启用中的相同数据范围 |
| base_profession_direction | `(base_id, profession_id, direction_id)` | 防止基地重复配置相同专业方向 |
| training_booking | `(room_id, date, start_time, end_time)` | 防止同一实训室同一时段被重复预约 |
| lab_booking | `(room_id, date, start_time, end_time)` | 防止同一实验室同一时段被重复预约 |
| file_blob | `(md5)` | 防止并发上传相同文件产生重复 blob 记录 |
| grade_teacher_guide | `(teacher_id, grade_id, dep_id, semester)` | 防止同一教师重复容量配置 |

生成列约定：

- `pair.active_flag`：`TINYINT GENERATED ALWAYS AS (CASE WHEN status = 'active' AND deleted_at IS NULL THEN 1 ELSE NULL END) STORED`
- `sys_organization.scope_key`：按 `dep_id/profession_id/class_id/company_id/cate_id` 的 `COALESCE(..., 0)` 组合生成
- `sys_organization.enabled_flag`：`disabled='false' AND deleted_at IS NULL` 时为 1，否则为 NULL

## 6. migration 管理

- 使用 `robmorgan/phinx` 管理数据库迁移（已安装）
- phinx 配置文件：`config/plugin/webman/database/phinx.php`
- migration 文件放在 `database/migrations/`（phinx 默认路径）
- 命名：`YYYYMMDDHHMMSS_{description}.php`（phinx 格式）
- 模板库 `practical_template` 始终保持最新 DDL，新建学校时直接复制
- 主库 migration 和学校业务库 migration 通过 `phinx.yml` 的 `environments` 分开管理
- 所有 migration 必须可逆（含 `down()` 方法）
- 命令：`php webman phinx:migrate -e master` / `php webman phinx:migrate -e school`
