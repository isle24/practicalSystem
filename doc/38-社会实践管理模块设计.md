# 社会实践管理模块设计

## 1. 目标与范围

社会实践作为独立业务模块建设，不并入实习管理或实验实训管理。模块后端位于 `server`，PC 前端位于 `fontend/pc`，H5 前端位于 `fontend/h5`。

核心范围：

- 社会实践计划支持教务系统同步、Excel 导入和后台新增。
- 所有计划按年级组织，不使用学期、学年或毕业届次。
- 同一计划可同时包含集中实践项目和分散实践申报。
- 集中实践支持一名负责人、多名指导教师和多名学生。
- 分散实践支持个人申报和团队申报。
- 签到、安全材料、成果材料、成绩、审核及归档形成完整时间线。
- 所有列表和接口按学校业务库、组织范围及业务关系隔离数据。

不在本模块范围内：

- 社会实践日志。
- 社会实践中期汇报。
- 将家长知情书作为强制流程条件。
- 修改 Webman 框架、默认路由机制或公共组件底层行为。

正式流程见 [社会实践管理流程图.html](./社会实践管理流程图.html)。

## 2. 核心业务决策

| 决策项 | 设计结果 |
|---|---|
| 模块边界 | 独立社会实践模块，复用公共底层能力 |
| 计划归属 | 必须选择年级，可面向全校、学院、专业或班级 |
| 实践模式 | 同一计划可同时存在集中实践和分散实践 |
| 计划来源 | 教务同步、Excel 导入、后台新增 |
| 外部数据处理 | 同步或导入后只生成草稿，管理员确认后发布 |
| 集中实践教师 | 一名负责人和多名指导教师，每名学生绑定一名具体指导教师 |
| 分散实践教师 | 默认学生选择、教师确认，管理员可直接分配或调整 |
| 团队申报 | 支持个人和多人团队申报，成员必须确认加入 |
| 团队材料 | 支持共同或分别提交，默认分别提交，由学院配置 |
| 参与方式 | 全员参与或自愿报名 |
| 审批节点 | 按计划选择审批流程，教务处节点可审批退回或自动备案 |
| 家长知情书 | 仅作可选附件，不拦截实施、评分或归档 |
| 成绩规则 | 集中和分散分别配置评分项，权重合计必须为 100% |

## 3. 模块边界

### 3.1 后端分层

- `SocialPracticeController`：接收请求、调用服务并返回统一响应，不拼接查询条件。
- `SocialPracticeService`：处理计划发布、项目分配、申报、审核、材料、成绩和归档。
- `SocialPracticeRecord` 等 Model：封装所有列表、详情、范围、锁定和统计查询。
- 公共服务：复用文件、消息、待办、审核意见、操作日志、Redis 锁、幂等提交和异步导出。

所有学校业务数据写入当前学校业务库，不设置 `school_id`。Controller 和 Service 不直接使用 `DB::table()`、`Model::query()` 或拼接查询条件。

### 3.2 前端边界

- PC：独立桌面模块，面向管理员、专业负责人和指导教师提供管理列表及审批窗口。
- H5：按学生、教师、管理员角色提供不同页面，不在学生端展示全校筛选列表。
- 通用列表、筛选、分页、导出、详情、审核、时间线和弹窗复用现有组件。

## 4. 数据模型

### 4.1 社会实践计划

`social_practice_plan`：

- `id`、`uuid`。
- `source_type`：`edu_system` / `excel` / `manual`。
- `source_key`：外部来源唯一编号，用于幂等同步和导入去重。
- `plan_code`、`title`、`description`。
- `grade_id`：必填，关联年级。
- `organizer_dep_id`：组织学院，可为空表示校级计划。
- `credit`：认定学分。
- `participation_mode`：`mandatory` / `voluntary`。
- `teacher_match_mode`：`student_choose` / `admin_assign` / `mixed`，默认 `mixed`。
- `teacher_confirm_hours`：教师确认时限。
- `max_reselect_count`：学生重新选择教师次数。
- `default_team_submit_mode`：`individual` / `shared`，默认 `individual`。
- `register_start_at`、`register_end_at`。
- `practice_start_at`、`practice_end_at`。
- `result_deadline_at`、`score_deadline_at`。
- `approval_flow_id`：关联审批流程。
- `status`：计划审核状态。
- `phase`：计划执行阶段。
- `submitter_id`、`created_at`、`updated_at`、`deleted_at`。

计划不保存学期、学年和毕业届次字段。

`social_practice_plan_scope`：

- `plan_id`、`scope_type`、`dep_id`、`profession_id`、`class_id`。
- 一行表示一个有效适用范围，允许学院、专业和班级逐层限定。
- 关系数据不写入 JSON。
- 使用范围字段生成 `scope_key`，并通过 `(plan_id, scope_key, active_flag)` 唯一约束防止有效范围重复。

### 4.2 审批流程

`social_practice_approval_flow`：保存审批流程名称、适用范围、启用状态和版本。

`social_practice_approval_node`：

- `flow_id`、`node_code`、`node_name`、`sort`。
- `scope_type`：学校、学院、专业或指定权限。
- `permission_code`：处理节点所需权限。
- `node_type`：`review` / `filing`。
- `can_return`：是否允许退回。
- `auto_pass`：是否自动备案。

默认流程为专业负责人审核、学院审批、教务处备案。教务处节点默认允许通过或退回，也可配置为自动备案。

### 4.3 计划要求

`social_practice_requirement`：

- `plan_id`、`practice_mode`：`centralized` / `distributed` / `all`。
- `requirement_type`：签到、拍照、安全协议、保险、应急预案、实践证明、实践报告或其他材料。
- `required_flag`：是否必填。
- `submit_scope`：`student` / `team` / `project`。
- `deadline_at`。
- `config_json`：只保存定位半径、签到频率、文件格式和数量等规则快照，不保存关联 ID。

家长知情书可作为 `other` 类型可选附件，但 `required_flag` 必须为否，且不得参与流程条件判断。

### 4.4 项目、教师和学生

`social_practice_project`：

- `plan_id`、`practice_mode`。
- `source_type`：`admin_created` / `student_declared`。
- `source_declaration_id`：分散实践申报通过后回写来源。
- `project_code`、`title`、`content`、`objective`。
- `location`、`start_at`、`end_at`。
- `capacity`、`status`、`phase`。
- `created_by`、`created_at`、`updated_at`、`deleted_at`。

`social_practice_project_teacher`：

- `project_id`、`teacher_id`。
- `teacher_role`：`leader` / `guide`。
- `capacity`。
- `status`：`active` / `removed`。
- 同一项目只能有一名有效负责人，同一教师不能重复绑定。
- 已分配人数从有效参与记录实时统计，不在教师关系表冗余保存。

`social_practice_participant`：

- `plan_id`、`project_id`、`student_id`、`teacher_id`。
- `practice_mode`、`join_source`、`status`。
- `active_flag`：用于保证同一学生在同一计划内只有一条有效参与记录。
- `remove_reason`、`created_at`、`updated_at`、`deleted_at`。

全员参与计划发布后按适用范围生成参与名单；自愿报名计划只为有效报名或申报生成参与记录。集中实践由管理员分配项目和教师，分散实践在申报通过后生成项目及参与记录。

`social_practice_implementation_application`：

- `project_id`、`applicant_id`。
- `title`、`content`。
- `budget_amount`、`material_requirement`、`venue_requirement`。
- `approval_flow_id`、`current_node_id`。
- `status`、`submitted_at`、`created_at`、`updated_at`、`deleted_at`。

集中项目必须提交实施申请并完成专业负责人、学院和教务处节点后，才能进入安全条件检查。实施申请的每次提交和审批统一写入 `social_practice_recording` 与 `review_opinion`。

### 4.5 分散实践申报

`social_practice_declaration`：

- `plan_id`、`applicant_student_id`。
- `declaration_type`：`individual` / `team`。
- `team_submit_mode`：`individual` / `shared`。
- `title`、`content`、`objective`、`expected_duration`、`expected_result`。
- `location`、`selected_teacher_id`、`assigned_teacher_id`。
- `teacher_confirm_deadline_at`、`teacher_confirm_status`。
- `status`、`accepted_project_id`。
- `created_at`、`updated_at`、`deleted_at`。

`social_practice_declaration_member`：

- `declaration_id`、`student_id`。
- `member_role`：`leader` / `member`。
- `confirm_status`：`pending` / `accepted` / `refused`。
- `confirmed_at`。

团队申报提交前，所有有效成员必须确认加入。同一学生不能同时加入同一计划下的其他有效申报或项目。

团队申报以整个团队选择一名指导教师。教师确认时按团队全部成员占用容量；申报通过后，团队成员分别生成参与记录并绑定该教师。

### 4.6 材料、成绩和归档

`social_practice_material`：

- `plan_id`、`project_id`、`declaration_id`、`student_id`。
- `material_type`、`submit_scope`、`version`。
- `title`、`content`、`status`、`submitted_at`。
- 文件通过 `file_relation` 关联，不在业务表保存文件 ID 数组。

共同提交时 `student_id` 为空并绑定项目或申报；分别提交时必须记录 `student_id`。默认材料：

- 集中实践：实践报告、实践照片。
- 分散实践：实践证明、实践照片、社会实践报告。

`social_practice_score_rule`：

- `plan_id`、`practice_mode`。
- `item_code`、`item_name`、`weight`、`max_score`、`sort`。
- 同一计划同一模式的有效权重合计必须为 100%。

默认规则：

- 集中实践：签到 20%、实践表现 30%、实践报告 50%。
- 分散实践：实践态度 20%、实践成果 30%、社会实践报告 50%。

`social_practice_score`：保存计划、项目、学生、指导教师、最终成绩、学分认定、评语和审核状态。

`social_practice_score_detail`：保存每个评分项的分数、权重和加权分，禁止使用 JSON 保存评分明细。

`social_practice_archive`：保存计划、项目、学生、教师、材料、成绩、审核意见、归档版本、打印文件和归档状态快照。归档记录不可覆盖，通过后修改时生成新版本。

### 4.7 公共记录

新增 `social_practice_recording`，通过 `entity_type`、`entity_id` 记录计划、项目、申报、成员、材料、补签、成绩和归档的操作时间线。

继续复用：

- `pair`：扩展 `type=social_practice`，记录学生和具体指导教师关系。
- `sign_in`：扩展 `entity_type=social_practice`。
- `review_opinion`、`review_opinion_draft`。
- `file`、`file_relation`。
- 消息、待办、操作日志和导出任务。

## 5. 计划来源与发布

### 5.1 教务系统同步

按开放接口接收计划来源编号、课程代码、课程名称、年级、学院、专业、学分和计划说明。`source_key` 作为同一来源的幂等键。同步只新增或更新可编辑草稿，不覆盖已发布计划。

### 5.2 Excel 导入

提供模板下载、上传解析、字段匹配、重复检查、预览确认和生成草稿。年级、学院、专业或课程无法匹配时整行拒绝导入，并在预览中明确提示。

### 5.3 后台新增

管理员手工填写计划基本信息、适用范围、参与方式、时间窗口、审批流程、计划要求和成绩规则。计划保存草稿不发送消息，发布后才通知适用学生和相关教师。

## 6. 业务流程

### 6.1 计划流程

```text
草稿 -> 提交确认 -> 审核通过 -> 发布 -> 报名/分配 -> 实施中 -> 成绩审核 -> 归档
```

计划发布后锁定年级和适用范围。需要调整时必须执行“通过后修改”，填写理由并保留原版本记录。

计划审核状态使用 `status`：

- `draft`：草稿。
- `wait`：待审核。
- `accept`：审核通过。
- `modify`：需修改。
- `refuse`：终止。

计划执行阶段使用 `phase`：

- `ready`：待发布。
- `enrolling`：报名或分配中。
- `active`：实施中。
- `scoring`：评分和成绩审核中。
- `archived`：已归档。

审核状态和执行阶段分开保存，避免用一个字段混合表达审核结果和业务进度。

### 6.2 集中实践

```text
创建项目
-> 配置负责人和指导教师
-> 分配学生并绑定具体教师
-> 提交实施申请
-> 专业负责人审核
-> 学院审批
-> 教务处备案
-> 安全条件检查
-> 开始实践
-> 签到及异常补签
-> 提交实践报告和照片
-> 材料完整性检查
-> 指导教师评分
-> 学院审核
-> 学分认定
-> 归档
```

教务处节点按计划选择的审批流程决定是否人工审批、允许退回或自动备案。安全必填项未完成时不得开始实践。

### 6.3 分散实践

```text
开放申报窗口
-> 个人或团队申报
-> 团队成员确认
-> 学生选择教师或管理员分配
-> 教师确认容量
-> 教师审核项目可行性
-> 安全条件检查
-> 开始实践
-> 签到及异常补签
-> 提交实践证明、照片和报告
-> 材料完整性检查
-> 指导教师评分
-> 学院审核
-> 学分认定
-> 归档
```

教师拒绝后学生可在计划限制次数内重新选择。教师超时未处理时发送提醒，超过确认时限后由管理员介入。项目不通过可终止，退回修改则允许重新提交并生成新记录。

### 6.4 补签到

学生提交补签到申请，填写日期、原因和证明材料。指导教师只能处理本人指导学生的申请。通过后生成补签记录并保留原异常状态、申请和审核意见。

社会实践不设置日志和中期汇报节点。

## 7. 状态与并发规则

工作流实体统一使用：

- `draft`：草稿。
- `wait`：待处理。
- `accept`：已通过。
- `modify`：需修改。
- `refuse`：已退回终止。

执行实体可使用：

- `active`：实施中。
- `completed`：已完成。
- `archived`：已归档。
- `removed`：已解除。

所有提交、审核、退回、重新提交和通过后修改写入 `social_practice_recording`。审核意见写入 `review_opinion`，审核草稿只写入 `review_opinion_draft`，不改变主表状态，不发送消息或待办。

写操作使用：

- 数据库事务和行锁。
- Redis 业务锁。
- `X-Request-Token` 幂等校验。
- 前端提交按钮禁用和超时恢复。
- UUID 或更新时间并发校验。

## 8. 业务校验

- 同一学生在同一计划内只能有一条有效参与记录。
- 团队成员不能重复加入同一计划的其他有效申报。
- 团队所有成员确认后才能提交申报。
- 教师确认或管理员分配时必须在事务中校验容量。
- 团队申报确认教师时必须一次性校验全部成员容量，不允许部分成员成功。
- 一名学生在一个项目内只绑定一名具体指导教师。
- 计划发布后不得直接修改年级和适用范围。
- 实施开始后不得切换集中或分散模式。
- 安全必填项未完成时不得开始实践。
- 必交成果材料不完整时不得提交评分。
- 同一模式成绩权重合计必须为 100%。
- 学院审核后成绩锁定，修改必须填写理由并重新审核。
- 教师、成员和项目变更必须记录原值、目标值、原因和操作人。

## 9. 权限与数据范围

建议权限码：

- `social_practice:view`
- `social_practice:plan:manage`
- `social_practice:project:manage`
- `social_practice:declare`
- `social_practice:teacher:confirm`
- `social_practice:approve`
- `social_practice:attendance:manage`
- `social_practice:material:manage`
- `social_practice:score:manage`
- `social_practice:score:approve`
- `social_practice:archive`
- `social_practice:config:manage`
- `social_practice:export`

数据范围：

- 超级管理员、学校管理员：当前学校全部社会实践数据。
- 教务处管理员：校级计划、备案、成绩、归档和统计数据。
- 学院管理员：本人授权学院数据。
- 专业管理员：本人授权专业数据。
- 项目负责人：本人负责项目、指导教师和参与学生。
- 指导教师：本人绑定项目和学生。
- 学生：本人可参与计划、申报、签到、材料、成绩和流程记录。

学院、专业管理员查询时默认选中并限制授权范围。指导教师和学生的数据范围由实际业务关系校验，接口参数不能扩大范围。

- `social_practice_result_due`

- `social_practice_patch_sign_result`

## 11. 接口边界

使用 Webman 默认路由提供社会实践接口，Controller 只调用 Service。接口按以下资源分组：

- 概况与选项：总览、年级、组织范围、教师容量、审批流程和材料规则。
- 计划：列表、详情、保存草稿、提交、审核、发布、关闭和通过后修改。
- 集中项目：列表、详情、保存、教师配置、学生分配和实施申请。
- 分散申报：列表、详情、成员确认、教师选择、管理员分配、教师确认和项目审核。
- 安全与签到：安全条件、学生确认、签到、签到异常和补签到审核。
- 成果材料：材料清单、提交、查看、补交、评阅和版本记录。
- 成绩：成绩规则、评分、学院审核、通过后修改和学分认定。
- 归档与报表：归档检查、生成归档、版本查看、打印和异步导出。
- 外部同步：教务计划推送、Excel 模板下载、导入预览和确认导入。

对外实体使用 UUID，内部自增 ID 不作为路径参数暴露。所有写接口执行权限、数据范围、幂等令牌和并发状态校验。

## 12. PC 页面

社会实践作为独立桌面模块，启动台可添加到桌面。模块侧栏：

1. 总览
2. 计划管理
3. 集中实践
4. 分散实践
5. 指导教师
6. 安全材料
7. 签到与补签
8. 成果材料
9. 成绩管理
10. 归档管理
11. 统计报表

页面规则：

- 列表第一筛选项为年级，随后为学院、专业和班级。
- 第一排之外的筛选条件通过“显示更多”展开。
- 所有列表显示跨页连续序号，操作列固定在右侧。
- 新增、编辑、审核使用可缩放、可最大化弹窗。
- 详情使用标签页展示基本信息、成员、教师、材料、成绩和流程记录。
- 审核、退回、补签、评分和归档操作均二次确认。

## 13. H5 页面

学生端：

- 首页显示当前计划、流程阶段、截止时间和待办。
- 集中实践显示本人项目、负责人、指导教师和材料入口。
- 分散实践支持个人或团队申报、成员确认和教师选择。
- 提供安全材料、签到、补签、成果材料、成绩和流程记录。

教师端：

- 待确认学生、待审核申报、本人项目和学生。
- 补签到审核、成果评阅、成绩录入。
- 不显示全校学院、专业和班级筛选。

管理员端：

- 计划、项目、申报、学生分配、材料和成绩列表。
- 以数据查看、审批、异常处理和统计为主。

## 14. 统计与导出

统计报表：

- 年级、学院、专业、班级参与率和完成率。
- 集中、分散项目数量及学生分布。
- 教师容量、已分配人数和超限情况。
- 安全材料完成率。
- 签到率和异常补签统计。
- 成果材料完整率。
- 成绩分布和学分认定情况。
- 归档完成率。

报表支持筛选、分页、Excel 导出、打印和异步大数据导出。大数据导出复用 `export_task` 和现有队列。

## 15. 归档规则

归档快照必须包含：

- 计划及适用范围。
- 集中或分散项目。
- 学生和指导教师关系。
- 安全材料和签到记录。
- 实践证明、照片、报告及其他成果。
- 成绩明细、总成绩、评语和学分认定。
- 审核意见和流程记录。
- 打印文件及文件版本。

归档记录不可覆盖。通过后修改时新增归档版本，旧版本保留并可查看。删除业务数据只允许软删除，不删除已归档文件和流程记录。

## 16. 实施约束

- 使用 PHP 8.4 和 Webman 默认路由。
- 所有查询封装在 Model 方法中，Controller 和 Service 不直接拼接查询。
- 复用现有文件、消息、待办、审核、日志、导出和通用前端组件。
- 不将社会实践加入现有 `PracticeService` 的 `lab` / `training` 类型判断。
- 不将社会实践数据写入实习计划、实习任务或实验实训项目表。
- 前端编译产物同步到 `server/public/pc` 和 `server/public/h5`。
- 实现前需同步更新总体架构、数据库汇总、权限、消息、统计和 API 文档。
