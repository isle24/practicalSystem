# 个人记事本设计

日期：2026-09-10。状态：已确认，进入开发。

## 范围

记事本用于当前账号保存个人备忘录，数据保存在当前学校业务库。PC 和 H5 使用同一套接口；不支持账号之间共享，不支持全校发布，不与文档中心的学校资料混用。

## 功能

- 新建、编辑、保存和删除多篇笔记。
- 笔记包含标题和 Markdown 正文，保存 Markdown 原文；前端实时预览渲染结果。
- 按标题和正文搜索，按最近修改时间排序。
- 删除进入个人回收站，可恢复；永久删除需要二次确认。
- 展示创建时间、修改时间和字数。
- PC 作为桌面模块，支持独立窗口和多窗口；H5 作为页面入口，适配移动端编辑和预览。
- 自动保存只保存当前编辑内容，不新增版本表；正式保存仍由用户点击保存按钮完成。

## 权限

- 查询、新增、修改、恢复和删除均限制在当前学校和当前账号。
- 后端以当前登录上下文的 `account_id`、`user_id` 为查询条件，不接收客户端传入的归属账号作为权限依据。
- 普通用户不能读取其他账号的笔记；管理员也不增加跨账号查看入口。
- 删除采用软删除。永久删除仅允许当前笔记所有者操作，并同步清理关联文件；首版没有附件，因此只处理记录。

## 数据结构

建议新增学校业务库表 `user_note`：

| 字段 | 用途 |
| --- | --- |
| `id`、`uuid` | 主键和业务标识 |
| `account_id`、`user_id` | 当前账号和用户归属 |
| `title` | 笔记标题 |
| `content_md` | Markdown 原文 |
| `status` | `enabled` 或 `deleted` |
| `created_at`、`updated_at`、`deleted_at` | 生命周期时间 |

增加 `(account_id, status, updated_at)`、`(account_id, title)` 索引。标题和正文的搜索先使用业务库兼容的模糊查询；数据量明显增大后再评估全文索引，不在首版引入搜索引擎。

## 后端分层

- `app/model/channel/NoteRecord.php` 封装分页、详情、保存、软删除、恢复和永久删除查询。
- `app/server/note/NoteService.php` 负责标题/正文长度校验、账号范围、保存事务和删除规则。
- `app/controller/Api/NoteController.php` 只负责请求参数、调用 Service、统一响应和操作日志。
- 使用现有 Webman 默认路由和认证中间件，不修改框架或 vendor 代码。
- 所有接口增加用途注释和 `OperationLog`，日志只记录操作名称、笔记 ID 和结果，不记录 Markdown 正文。

## 前端交互

- PC 记事本采用左侧笔记列表、右侧编辑区的布局；顶部提供搜索、新建、保存和回收站入口。
- 编辑区提供标题输入和 Markdown 编辑区；预览区显示安全渲染结果，过滤脚本、事件属性和危险链接协议。
- 未保存内容关闭、切换笔记或打开其他窗口时提示保存；请求进行中禁止重复提交。
- H5 默认先显示笔记列表，点击进入编辑页；保存、返回和删除按钮适配底部安全区域。
- 空列表显示新建入口；删除、恢复和永久删除均二次确认。
- 记事本不进入全校启动台共享收藏，不显示学校管理员配置入口。

- 富文本工具栏和 Markdown 文件导入导出。
