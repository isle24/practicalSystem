# 权限系统设计

## 1. 模型总览

三层权限体系：

```
1. 认证层 — 你是谁（企业微信 OAuth / 账号密码）
2. 授权层 — 你能做什么（RBAC：菜单 / 按钮 / 接口）
3. 数据层 — 你能看哪些数据（组织范围 or 业务关系）
```

```
┌─────────────────────────────────────────────────┐
│                  权限体系                         │
│                                                   │
│  ┌──────────┐    ┌──────────┐    ┌────────────┐  │
│  │ 用户      │───▶│ 角色      │───▶│ 权限        │  │
│  │ User     │    │ Role     │    │ Permission │  │
│  └──────────┘    └──────────┘    └────────────┘  │
│       │                                  │         │
│       │                            ┌─────┴─────┐  │
│       │                            │ 菜单权限    │  │
│       │                            │ 按钮权限    │  │
│       │                            │ 接口权限    │  │
│       │                            └───────────┘  │
│       │                                           │
│  ┌────┴──────────┐                                │
│  │ 所属学校       │ ── 组织层级过滤（管理员）       │
│  │ 所属学院       │                                │
│  └───────────────┘                                │
│                                                   │
│  ┌──────────────┐                                 │
│  │ 业务关系       │ ── 业务关系过滤（教师）         │
│  │ (指导关系等)   │                                │
│  └──────────────┘                                 │
└─────────────────────────────────────────────────┘
```

核心逻辑：
- 认证和授权与业务无关，由权限系统统一处理
- 数据可见性不与角色绑定，由组织属性和业务关系动态推导
- 权限系统不存储"谁能看到哪个学生"这类业务数据

## 2. 菜单/按钮/接口权限

### 角色表

角色表位于学校业务库内，不放入主库。主库仅保存租户信息。

```
role
  - id
  - code: super_admin / school_admin / college_admin / profession_admin / teacher / student / enterprise
  - name（角色名称）
  - role_type（角色类型，同 code，用于数据范围判断）
  - sort, status
  - created_at, updated_at, deleted_at
```

账号-角色关联：

```
user_role
  - id
  - account_id（关联 account.id）
  - role_id（关联 role.id）
  - is_primary: false / true
  - created_at, updated_at, deleted_at
```

角色数据范围：

```
sys_organization
  - organization_id（PK，自增）
  - account_id（关联 account.id）
  - user_id（关联 users.id，兼容论文系统字段）
  - role_id（关联 role.id）
  - dep_id（院系 ID，可为空）
  - profession_id（专业 ID，可为空）
  - class_id（班级 ID，可为空）
  - company_id（企业 ID，可为空）
  - cate_id（分类 ID，可为空，预留）
  - scope_key（生成列：dep/profession/class/company/cate 组合键）
  - enabled_flag（生成列：未禁用且未删除时为 1，否则为 NULL）
  - disabled: false / true
  - created_at, updated_at, deleted_at
```

`sys_organization` 一行表示一个可管理范围。一个账号角色可配置多行，用于支持“多个学院”“多个专业”“多个企业”的管理或访问权限。

**唯一约束与索引：**

```
scope_key = CONCAT_WS(':',
  COALESCE(dep_id, 0),
  COALESCE(profession_id, 0),
  COALESCE(class_id, 0),
  COALESCE(company_id, 0),
  COALESCE(cate_id, 0)
)

enabled_flag = CASE WHEN disabled = 'false' AND deleted_at IS NULL THEN 1 ELSE NULL END

UNIQUE(account_id, role_id, scope_key, enabled_flag)
INDEX(role_id, disabled)
INDEX(dep_id, disabled)
INDEX(profession_id, disabled)
INDEX(class_id, disabled)
INDEX(company_id, disabled)
```

已删除或禁用的历史范围 `enabled_flag=NULL`，允许重新配置；启用中的同一账号角色范围不允许重复。

### 菜单权限

菜单按平台和角色分别配置，树形结构。

菜单表结构：

| 字段 | 说明 |
|---|---|
| id, parent_id | 树形结构 |
| name, code, path/url | 名称、标识、路径 |
| platform | h5 / pc / both |
| type | directory / menu / button |
| sort, icon, visible, status | 排序、图标、是否可见、状态 |

角色-菜单关联：role_menu（role_id + menu_id，可存菜单节点和按钮节点）。

### 按钮权限

按钮作为菜单的子节点挂在同一张表中（type=button），用 code 标识：

```
菜单:
  - id=10, 实习审核 (menu)
  - id=11, 通过按钮 (button, code="internship:approve")
  - id=12, 驳回按钮 (button, code="internship:reject")
  - id=13, 批量导出 (button, code="internship:export")
```

前端指令控制：

```vue
<el-button v-permission="'internship:approve'" @click="approve">通过</el-button>
<van-button v-permission="'internship:approve'" @click="approve">通过</van-button>
```

分两级控制：
- `v-permission="'code'"` 控制显隐
- `:disabled="!hasPermission('code')"` 控制只读

返回前端格式：

```json
{
  "menus": ["树形菜单"],
  "permissions": ["internship:approve", "internship:reject", "internship:export"]
}
```

### 接口权限

接口权限不存储数据库，通过中间件 + 配置文件定义：

```
POST /api/internship/applications/{uuid}/approve  → require: internship:approve
GET  /api/internship/applications                 → require: internship:view
```

中间件校验流程：
1. 从 JWT 解析 current_role_id
2. 从 Redis 读取角色权限集合（首次从 DB 加载后缓存）
3. 匹配接口所需权限 code
4. 通过则放行，不通过返回 403

### 权限缓存策略

```
DB（权限定义） → 变更时清除 Redis 缓存
Redis（角色-权限映射，Hash）→ 接口中间件读取，高频访问
前端（菜单树 + permissions 数组）→ 登录/切换角色时下发
```

## 3. 数据过滤策略

权限系统校验完菜单/按钮/接口后，到达数据层，由统一的数据范围服务提供过滤条件。

```
┌──────────────────────────────────────────────┐
│         数据可见性过滤器                       │
│                                                │
│  当前角色类型：                                │
│                                                │
│  超级管理员  → 当前学校库内不限制                     │
│  学校管理员  → 本校数据（库边界天然隔离）              │
│  学院管理员  → sys_organization.dep_id（可多学院）     │
│  专业管理员  → sys_organization.profession_id（可多专业）│
│  教师        → 指导关系（pair 表）                    │
│                （自己指导学生，跨学院可见）              │
│  学生        → 自身数据                               │
│  企业用户    → sys_organization.company_id（可多企业） │
└──────────────────────────────────────────────────────┘
```

数据隔离由独立数据库保证。库内按学院/指导关系做逻辑过滤。

实现方式：

```php
// DataScopeService — 从 CurrentContext 自动获取当前用户信息，无需传参
public function getFilter(string $business): array
{
    $roleType = CurrentContext::roleType();
    $userId   = CurrentContext::userId();

    return match ($roleType) {
        'super_admin'     => [],                                             // 当前租户内无限制
        'school_admin'    => [],                                             // 库边界天然隔离
        'college_admin'   => ['dep_id'        => $this->getOrgDepIds()],
        'profession_admin'=> ['profession_id' => $this->getOrgProfessionIds()],
        'teacher'         => ['student_id'   => $this->getGuidedStudentIds($userId)],
        'student'         => ['student_id'   => CurrentContext::student()['student_id']],
        'enterprise'      => ['company_id'    => $this->getOrgCompanyIds()],
    };
}
```

数据范围过滤在中间件层统一处理，业务 service 从请求上下文获取过滤条件，无需判断角色。

### 关键规则

- 数据隔离由独立数据库保证，库内不设 school_id 字段
- super_admin：学校库内最高权限，管理当前学校库内菜单、角色、权限、配置
- school_admin：学校级，管理本校基础数据和业务审核
- college_admin：学院级，按 `sys_organization.dep_id` 可看一个或多个学院数据
- 专业管理员（profession_admin）：专业级，按 `sys_organization.profession_id` 可看一个或多个专业数据
- 教师：看自己指导学生（pair 表），跨学院可见
- 企业用户：按 `sys_organization.company_id` 可看一个或多个企业相关数据
- 各过滤线独立，不互相影响
