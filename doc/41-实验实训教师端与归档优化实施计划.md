# 实验实训教师端与归档优化实施计划

## 1. 实施目标

按 `40-实验实训教师端与归档优化设计.md` 完成实验实训模块调整：

- 将教学计划明确为课程开课任务，支持课程负责人和多名任课教师。
- 学生按项目提交项目报告，报告包含反思小结。
- 项目发布后同步动态成绩评分项。
- 教师工作区区分教学准备、材料提交和学生材料评阅。
- 增加按开课任务检查和生成版本快照的归档中心。
- 按分项权重和项目权重计算项目成绩及课程汇总成绩。
- 归档成功后生成正式 ZIP 归档包并支持下载。
- H5 学生流程节点可直接切换对应功能。
- PC 与 H5 使用相同后端接口和权限规则。

## 2. 文件边界

  - 增加 `practice_plan` 课程负责人字段。
  - 增加 `practice_plan_teacher`、`practice_archive`。

  - 增加增量字段和索引升级。

  - 项目保存后同步评分项。

  - 把归档快照生成 ZIP，复用统一文件服务登记正式文件。
- `server/app/controller/Api/PracticeController.php`

- `server/app/controller/Api/Concerns/PracticeEntityNames.php`

## 3. 后端接口

新增接口：

```text
GET  /api/practice/plan-teachers
POST /api/practice/save-plan-teachers
GET  /api/practice/archive-check
POST /api/practice/archive
GET  /api/practice/archive-list
GET  /api/practice/archive-detail
GET  /api/practice/course-scores
GET  /api/practice/archive-download
```

方法签名：

```php
PracticeService::planTeachers(Request $request): array
PracticeService::savePlanTeachers(Request $request): array
PracticeService::archiveCheck(Request $request): array
PracticeService::archive(Request $request): array
PracticeService::archiveList(Request $request): array
PracticeService::archiveDetail(Request $request): array
PracticeService::courseScores(Request $request): array
PracticeService::archiveDownload(Request $request): array
```

所有 SQL 条件位于 `PracticeRecord` 静态方法中，控制器和服务不拼接查询构造器。

## 5. 验证命令

不创建测试文件，执行以下现有验证：

```bash
php -l server/database/init.php
php -l server/app/model/channel/PracticeRecord.php
php -l server/app/server/practice/PracticeService.php
php -l server/app/controller/Api/PracticeController.php
php server/database/init.php
npm --prefix fontend/pc run build
npm --prefix fontend/h5 run build
curl -I http://127.0.0.1:8787/pc/index.html
curl -I http://127.0.0.1:8787/h5/index.html
```

使用已存在的多角色账号验证：

- 学生只看到本人项目报告、签到和成绩。
- 任课教师看到本人开课任务、项目报告评阅、成绩和课程反思。
- 课程负责人可维护大纲、考核计划和评分方案。
- 学院或专业管理员只能审核数据范围内且非本人提交的材料。
- 学校管理员和超级管理员可跨范围审核并留痕。
