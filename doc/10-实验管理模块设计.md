# 实验管理模块设计

## 1. 差异说明

| | 实习 | 实训 | 实验 |
|---|---|---|---|
| 场所 | 校外基地 | 校内实训室 | 实验室 |
| 组织方式 | 个人申请 | 按班级/项目 | 按课程/项目 |
| 特有功能 | 签到/日志 | 实训室预约 | 实验课表/仪器管理 |
| 复用能力 | — | 签到日志复用实习 | 预约逻辑复用实训 |

## 2. 数据模型

> 所有表位于所属学校数据库中，无需 school_id 字段。

```
lab_room（实验室）
  - id, uuid
  - name, location, capacity
  - equipment（设备/仪器配置描述）
  - status: available / maintenance / disabled
  - created_at, updated_at, deleted_at

lab_course（实验课程）
  - id, uuid
  - name, description
  - teacher_id（课程负责人）
  - start_date, end_date
  - status
  - created_at, updated_at, deleted_at

lab_course_class（实验课程-班级关联，中间表）
  - id, course_id, class_id
  - created_at, updated_at, deleted_at

lab_project（实验项目）
  - id, uuid, course_id
  - name, description
  - teacher_id（项目负责人）
  - status: draft / wait / accept / modify
  - created_at, updated_at, deleted_at

lab_project_member（实验项目-成员关联，中间表）
  - id, project_id, student_id
  - role: leader / member
  - created_at, updated_at, deleted_at

lab_booking（实验预约）
  - id, uuid, room_id, project_id
  - user_id（预约人）
  - date, start_time, end_time
  - status: draft / wait / accept / modify
  - remark
  - created_at, updated_at, deleted_at

lab_material（实验材料/指导书）
  - id, uuid, project_id, student_id
  - title, content
  - template_id
  - files（关联 file_relation）
  - status: draft / wait / accept / modify
  - teacher_id（最近评阅教师，快捷引用；详细记录见 review_opinion）
  - created_at, updated_at, deleted_at

lab_report（实验报告）
  - id, uuid, project_id, student_id
  - title, content, template_id
  - attachments（关联 file_relation）
  - status: draft / wait / accept / modify
  - teacher_id（最近评阅教师，快捷引用；详细记录见 review_opinion）
  - created_at, updated_at, deleted_at

lab_score（实验成绩）
  - id, uuid, project_id, student_id
  - material_score, report_score
  - material_weight, report_weight
  - final_score, teacher_id, comment
  - created_at, updated_at, deleted_at
```

**说明：** 实验模块不需要独立建签到表和日志表。签到和日志统一使用 `sign_in` 和 `journal` 表，通过 `entity_type='lab'` + `entity_id`（指向 `lab_project.id`）关联。指导教师-学生配对复用 `pair` 表，`type='lab'`，`arrangement_id` 指向 `lab_project.id`。

## 3. 实验预约

复用实训室预约逻辑，增加课程排课概念：

- 时间冲突检测 + 实验室容量校验（同实训，含并发控制：Redis 锁 + DB 唯一约束）
- `lab_booking` 表增加唯一约束 `(room_id, date, start_time, end_time)`
- 支持按课程排课生成预约时段，学生选时段预约
- 教师可查看本课程所有预约，统一管理

## 4. 实验项目

- 项目挂课程下，状态流转遵循全局约定：draft → wait → accept（通过）或 wait → modify（退回修改）
- 课程负责人可指派项目负责人
- 项目成员从课程班级学生中选择，通过 lab_project_member 中间表管理，支持 leader / member 角色区分
