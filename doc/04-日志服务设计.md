# 日志服务设计

## 1. 数据模型

按月分表，表名格式：`operation_log_YYYYMM`。

```
operation_log_202605
  - id, user_id, username
  - module: internship / training / lab / system / ...
  - action: login / create / edit / delete / approve / export / ...
  - target: 操作对象描述
  - ip, user_agent
  - request_data: JSON
  - response_data: JSON
  - created_at, updated_at, deleted_at
```

## 2. 分表策略

### 2.1 自动建表

`app/server/log/LogTableManager.php`，定时任务每月 25 号检查并创建下月表：

```
当前月 2026-05 → 检查 operation_log_202606 是否存在
  → 不存在 → CREATE TABLE operation_log_202606 LIKE operation_log_template
  → 模板表 operation_log_template 仅定义结构，不存数据
```

### 2.2 写入路由

`OperationLogService` 封装表名计算：

```php
// 写入自动路由到当月表
OperationLogService::write($data);
// → INSERT INTO operation_log_202605 ...

// 查询自动跨表
OperationLogService::query(['date_from' => '2026-03', 'date_to' => '2026-05']);
// → 自动 UNION ALL operation_log_202603, _202604, _202605
```

### 2.3 保留策略

默认不自动清理日志。仅超级管理员可手动删除指定时间段的日志。

## 3. 记录方式

全局中间件拦截，自动记录：

```php
// OperationLogMiddleware
// after 响应后异步写入：
//   - 从 request 提取 module/action/target（由路由注解或配置文件定义）
//   - 保存 request params + response body
//   - 自动脱敏：password、token、secret、api_key、id_card、phone 等字段值替换为 "***"
//   - JSON 递归扫描，嵌套字段同样脱敏
//   - 通过 Redis 队列异步写入 DB，不阻塞接口响应
```

**脱敏规则：**

| 字段名匹配 | 脱敏方式 | 示例 |
|---|---|---|
| password, pwd, pass | 完全替换 | `"***"` |
| token, secret, api_key, push_secret | 保留前 4 位 | `"abcd***"` |
| phone, mobile, cellphone | 保留前 3 后 4 | `"138****5678"` |
| id_card, id_number | 保留前 3 后 4 | `"310****1234"` |
| email | 保留首字符和域名 | `"j***@example.com"` |

## 4. 日志查看（PC 端）

- 列表：按用户/模块/操作/时间筛选
- 列表显示字段：用户、模块、操作、目标、时间
- 详情弹窗：可查看完整 request_data 和 response_data（仅排查时使用）

## 5. 路由配置示例

```php
// 在路由配置中声明日志元信息
Route::post('/api/internship/applications/{uuid}/approve', [ApplicationController::class, 'approve'])
    ->setLog('internship', 'approve', '实习申请审核');
```

中间件自动从路由配置读取 module/action/target。
