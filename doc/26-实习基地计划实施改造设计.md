# 实习基地、计划、任务与实施改造设计

## 1. 范围与原则

本设计用于实习管理的基地建设、教学计划同步、计划表、实习任务、实习实施、Excel 导入、Word/PDF 导出和公共列表交互改造。

- 所有业务数据位于学校业务库，不增加学校租户字段。
- 保留 MVC 分层，控制器只负责参数接收和调用服务，查询和数据组装由 Model 完成。
- 计划表、实习任务和实习实施使用独立菜单，数据层保留 `internship_plan -> arrangement -> pair` 关系。
- 不删除已有数据和历史记录，优先通过兼容字段和迁移保持旧数据可读。
- 当前基地保存后直接生效，不设置线上审核流程。
- 学期和学年不作为业务筛选维度；毕业实习使用毕业届次，其他实习使用年级。

## 2. 基地建设

### 2.1 基地类型

基地分为长期基地和临时基地。

长期基地按照 `doc/实习基地申请表.docx` 维护完整申报资料。临时基地只要求基地名称、基地所在位置、服务专业、服务课程和基地负责人。基地名称允许为空，未填写时按“位置－负责人－临时基地”生成显示名称。

### 2.2 长期基地字段

长期基地包含以下信息组：

1. 申报学院、合作单位、基地名称、基地负责人、联系电话。
2. 基地位置、占地面积、服务专业、年招生数、在校生数、服务课程、基地类别。
3. 基地负责人姓名、性别、出生年月、职务职称、学历、手机号、主要职责。
4. 校内教师和企业导师动态列表。
5. 相关专业已有校外实习基地名称及合作情况。
6. 合作单位全称、注册资金、主营业务、员工人数、近三年年均接待实习生人数、高级职称人数。
7. 建设方案富文本内容。
8. 经费预算项目、具体内容、预算金额和备注。

重复信息使用子表维护，建设方案按可维护的内容组保存。服务专业使用基地与专业关联表。服务课程允许选择已有课程，也允许录入未建档课程。

### 2.3 人员与权限

基地负责人、校内教师和企业导师支持关联已有人员或手工录入。关联人员时保存姓名、联系方式等申报快照，避免人员资料后续变化影响历史申报书。

超级管理员、学校管理员、学院管理员和专业管理员可以录入基地。学院管理员只能处理本学院范围，专业管理员只能处理自身专业范围。基地保存后直接生效，保留创建人、修改人、时间和操作记录。

## 3. 计划表

### 3.1 数据关系

一条计划对应一个实习类别、一个归属范围、学院、专业和课程。毕业实习关联毕业届次，其他实习关联年级，两个归属字段互斥。一个计划可拆分多个实习任务，每个任务有唯一任课教师，并可绑定多个班级和学生。

计划主表不保存学生人数。人数通过实习任务、班级绑定和学生绑定统计。

界面将“计划表”和“实习任务”拆分为两个独立菜单。计划详情可查看关联任务摘要，任务创建、绑定和审核在“实习任务”中处理。

### 3.2 计划字段

计划表不使用学期字段作为业务筛选维度。主要字段包括课程代码、课程名称、课程类别、实习类别、开课院系、归属年级或毕业届次、专业、总学分、实习学分、总学时、实习学时、原始教师、原始时间、原始地点和备注。

教师、时间、地点存在多个值时，先保存原始导入内容，不自动推断三者对应关系。管理员在实习任务中明确任务教师、时间、地点、批次、班级和学生。

`internship_plan` 增加 `source_type`、`source_plan_id`、`source_version` 和 `source_last_synced_at`。`source_type` 区分手工新增、Excel 导入和教务同步。

### 3.3 计划来源与状态

计划支持手工新增、Excel 导入和教务同步三种来源。手工新增和导入计划直接生成本系统草稿。教务同步数据先进入待接收区，由有权限的管理员确认后生成本系统草稿。

同步确认只表示接收教务数据，不代表业务审核通过。确认生成的计划状态为 `draft`，管理员补充或修正后再提交现有计划审核流程。计划审核通过后才允许创建实习任务。

### 3.4 Excel 导入

系统提供标准模板下载。模板字段为：序号、课程代码、课程名称、课程类别、实习类别、开课院系、归属年级/毕业届次、授课对象专业、总学分、实习学分、总学时、实习学时、授课教师、实习时间、实习地点、备注。

模板要求一行只对应一个实习类别、归属范围、学院、专业和课程。普通实习在归属列填写年级，毕业实习填写毕业届次。同一课程服务多个专业时，应拆分为多行。历史模板中同一单元格存在多个专业时，导入预览自动拆分为多条计划草稿供确认。

导入流程为上传、解析、业务类型确认、字段校验、重复检查、预览确认和生成草稿。模板中存在实验、实训、毕业论文、社会实践等记录时，预览中必须逐行确认业务归属为实习、实训、实验、社会实践或忽略。

计划重复判断优先使用“实习类别 + 实际归属范围 + 学院 + 专业 + 课程代码”，课程代码为空时使用“实习类别 + 实际归属范围 + 学院 + 专业 + 课程名称”。实际归属范围按类别取年级或毕业届次。草稿或需修改数据允许选择更新；已提交或已生效数据禁止覆盖；默认跳过重复数据并显示原因。

### 3.5 教务计划同步暂存

新增 `internship_plan_sync_inbox` 保存教务计划待接收数据。主要字段包含：

1. 教务计划唯一 ID、计划版本、课程唯一 ID。
2. 年级、学院、专业代码及名称，培养层次、方案名称和方案版本。
3. 课程代码、课程名称、课程类别、课程性质、学分、周学时、总学时。
4. 理论、实验、实践、上机和其他学时。
5. 教务来源学期或学年信息，仅作为来源记录，不作为本系统业务筛选维度。
6. 原始数据、与本地计划的差异数据、同步批次号和接收时间。
7. 状态：`pending`、`generated`、`ignored`、`change_pending`、`mapping_failed`。
8. 生成的本地计划 ID、确认人、确认时间和忽略原因。

学院、专业和年级按代码匹配。匹配失败时记录为 `mapping_failed`，不自动创建基础档案。

### 3.6 主动拉取与变更保护

当前只实现后台主动拉取，不提供教务系统主动推送接口。教务接口未配置时，同步按钮不可用并提示“尚未配置教务系统接口”。接口配置后按更新时间和游标增量拉取。

同步适配器只负责请求教务系统和解析响应，统一同步 Service 负责校验、映射、差异和入库。后续需要推送时只增加同步适配器，不修改待接收和正式计划流程。

以“教务计划 ID + 版本号”保证幂等：

1. 同一版本重复拉取不重复生成。
2. 待确认数据再次同步时更新暂存记录。
3. 已生成正式计划但尚未创建任务时，新版本生成差异，管理员确认后更新。
4. 已创建任务、实施表或过程数据时，不自动覆盖正式计划，只生成 `change_pending` 差异记录。
5. 教务来源计划删除或停用时只标记来源状态，不删除本地业务数据。

### 3.7 同步确认交互

“计划表”下使用“正式计划”和“待接收计划”文字 Tab。待接收列表显示来源、版本、接收时间、映射状态和差异。

主动拉取前通过弹窗选择更新时间范围。同步过程中按钮置灰，完成后显示新增、更新、重复和映射失败数量。

“确认生成”“确认更新”“忽略计划”和批量操作均使用二次确认弹窗。确认弹窗明确显示影响数量、生成后状态和不会生成教师、班级或学生任务绑定。忽略计划必须填写原因。操作提交后按钮置灰，接口返回或超时后恢复。

### 3.8 同步权限

- 超级管理员和学校管理员可查看、同步和确认全校计划。
- 学院管理员只能查看和确认本学院计划。
- 专业管理员只能查看和确认本专业计划。
- 教师和学生不参与教务计划同步和确认。

## 4. 实习任务

学院管理员或具备任务管理权限的管理员从已审核计划创建实习任务。一条计划可拆分多个任务，每个任务必须指定一名任课老师，并可绑定多个班级和学生。

任务字段包含任务名称、计划 ID、任课教师、批次、起止日期、地点、基地、组织方式、班级和学生范围。任务人数通过实际学生绑定自动统计，不允许手工修改。班级人数只保存快照，学生绑定为最终人数口径。

同一任务内不允许重复绑定同一学生。同一计划下学生可参与多个任务，成绩按任务分别记录。

任务使用 `draft -> wait -> accept/modify -> wait` 状态流转。时间、地点、任课教师和学生范围完整后才允许提交审核。任务所属学院范围内任一有权限的管理员可审核，审核通过后任课老师才能填写实施表。

`arrangement_recording` 保存每次任务提交内容，`review_opinion` 保存审核意见。任务变更继续通过 `arrangement_change` 和 `arrangement_change_recording` 留痕。

## 5. 实习实施

实习实施以已审核任务为上下文。每个任务对应一张当前实施表，`implementation_sheet.arrangement_id` 使用唯一约束。历史提交内容保存在 `implementation_sheet_recording`，不通过复制主表生成多份当前实施表。

课程、学分、学院、专业、年级或毕业届次、任课老师、学生人数、时间、地点、基地和组织安排由计划、任务和学生绑定自动带出。任课老师填写经费明细、附件、备注和必要说明。

实施表使用 `draft -> wait -> accept/modify -> wait` 状态流转。任务所属学院范围内任一有权限的管理员可审核。教师提交审核后发送待办和消息；保存草稿时不发送通知。

已通过实施表不能再次通过或退回，只能执行“通过后修改”。通过后修改必须填写理由，新增审核记录并将当前状态改为 `modify`。教师重新提交时新增 `implementation_sheet_recording`，不覆盖旧记录。

每次提交、审核、退回和通过后修改均写入 `implementation_sheet_recording` 和 `review_opinion`。审核意见按模块配置校验最少和最多字数。状态只能通过业务按钮改变，不在表单中直接编辑。

提交、审核和通过后修改使用 Redis 锁和数据库事务。前端按钮在接口返回或超时前保持禁用，所有关键状态变更均通过二次确认弹窗执行。

## 6. 导出

### 6.1 基地 Word

基地 Word 导出使用现有《实习基地申请表.docx》的页面结构和表格布局。学院意见和学校意见两个区域均保留为空，供线下签字盖章。教师、企业导师、已有基地和预算项目按照动态行写入，建设方案写入对应内容区域。

### 6.2 实习实施 PDF

实习实施 PDF 按提供的两页《教学实习实施(经费)表》结构生成，包含申请内容、实习组织安排、经费明细、总金额、附件、备注和审批区域。金额自动生成中文大写，组织安排和经费明细支持动态多行。审批区域按实际审核记录输出，不伪造处理人、意见或签名。

导出使用模板填充方式，避免使用普通 HTML 表格造成版式偏差。没有审批记录的节点保持空白。

## 7. 公共列表与弹窗

所有 PC 列表通过公共列表组件处理筛选条件：默认显示第一排，超过一排时显示“显示更多”，展开后显示全部条件，收起不清空已选值。实习类别决定显示年级或毕业届次筛选，学院、专业等默认筛选和角色数据范围继续生效。

包含长文本、富文本、附件或复杂 JSON 的列表统一显示摘要，并提供“查看”按钮。实习报告、实习日志、基地申报、建设方案、实施表和教师工作报告使用统一详情弹窗查看完整内容。

新增、编辑、差异查看和审核使用统一业务弹窗，支持拖动、改变大小、放大、最大化和恢复。弹窗标题和底部操作区固定，内容区独立滚动，底部按钮不被导航栏遮挡。

## 8. MVC、权限与日志

- Controller 只负责参数接收、权限校验、调用 Service 和返回响应。
- Model 封装全部查询、分页、关联查询、重复判断和写入方法；Controller 和 Service 不直接调用 `query()` 或拼接查询条件。
- `EducationPlanSyncService` 负责同步批次、字段映射、差异比较、事务和状态流转。
- PC 和 H5 使用相同的后端接口和数据权限。学生只能查看本人任务及过程数据，教师只能查看本人任务和实施表，管理员按学院或专业范围查看数据。
- 同步、查看差异、确认生成、忽略、确认更新、提交审核、审核通过、退回和通过后修改均写入全局日志。
- 全局日志同时保存接口地址、操作编码、可读操作名称、模块、业务类型、业务 ID、操作人和结果。

## 9. 兼容与记录

基地、计划、同步暂存、任务、绑定、变更、实施表和导入任务保留创建人、修改人、原始数据和业务记录。导入文件通过文件管理模块保存，并记录上传人、上传时间、客户端和导入结果。

已有 `internship_plan`、`arrangement`、`base`、`base_application` 和 `implementation_sheet` 数据不得删除。旧数据通过兼容读取显示，新的结构化字段逐步补齐。

4. 完成正式计划、待接收计划、实习任务和实习实施独立界面。
5. 完成任务审核、实施表审核、Redis 锁、事务、记录和通知。
6. 更新 H5 教师和管理员的任务、实施和审核入口。
7. 完成 Word/PDF 模板导出和公共列表交互。
8. 重新编译 PC 和 H5 前端，更新 `server/public/pc` 和 `server/public/h5`，完成语法检查和运行验证。
