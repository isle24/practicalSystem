# 实习管理性能与基地走访实施计划

**目标：** 降低实习管理菜单切换延迟，并将基地走访升级为多人员、时间冲突校验、企业微信提醒和可持续编辑的访后管理。

**架构：** 前端复用当前实习模块状态，在会话内缓存总览和筛选选项并合并并发初始化请求；后端保持 Webman MVC 路由，将走访计划、走访人员、访后记录和提醒分别放在现有服务、模型和定时任务中。数据库通过增量升级 SQL 增加走访人员关联和联系人/主管院长快照字段，保留旧字段兼容已有数据。

**技术栈：** PHP 8.4、Webman、Illuminate Query Builder、MySQL、Vue 3、Element Plus、现有消息服务与企业微信队列。

## 全局约束

- 后端代码放在 `server`，PC 前端代码放在 `fontend/pc`。
- 使用现有 Webman 路由和 MVC 分层。
- 不新增第三方依赖，不生成测试代码。
- 走访预约使用日期、开始时间、结束时间；同一走访人员重叠时间直接拒绝。
- 基地资料自动带入并只读；联系人姓名和电话属于本次走访，可修改。
- 走访人员可选教师和管理员；主管院长从现有用户/管理员中选择。
- 企业微信提醒发送给走访人员、主管院长和已绑定的联系人账号。
- 访后记录允许多次编辑，保存最新文本和附件。

**接口：**
- `options()` 返回基地、可选走访人员、可选主管院长/联系人账号和学院选项。
- `assign()` 接收 `base_id`、联系人账号/姓名/电话、主管院长账号、走访人员账号数组和备注；基地字段全部从数据库重新读取并快照。
- `schedule()` 接收 `visit_date`、`start_time`、`end_time`、版本号和计划 ID。
- `detail()` 与 `page()` 返回联系人、主管院长、走访人员及冲突信息。
- `saveRecord()` 继续接收文本和附件 ID，允许更新已有记录。

**步骤：**

- [ ] 将可见范围从单一 `teacher_id` 扩展到参与人员账号，同时保留历史教师字段的回退判断。

- [ ] 时间校验改为必须有日期、开始时间、结束时间，结束时间晚于开始时间；不再要求上午/下午字段。
