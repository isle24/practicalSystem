## 4. B：企业微信扫码绑定

### 已查证的故障链路

- `AuthMiddleware` 对不满足学校绑定策略的账号返回 `40310`。
- `WechatBindingService::begin()` 只允许企业微信浏览器启动授权。
- PC 共用绑定页面只提供复制学校网址，缺少扫码会话。
- 客户端网关只允许学校同源跳转，不能直接把客户端 API 请求重定向到企业微信 OAuth。

### 交互与校验

1. PC 或客户端登录成功但尚未完成绑定时，显示绑定面板和二维码。
2. 已登录 PC 创建 5 分钟有效的一次性会话，服务端绑定学校、用户、账号和当前设备会话。
3. 二维码使用学校 HTTPS 域名，只包含随机会话票据，不包含 JWT、密码或个人信息。
4. 手机企业微信扫码后完成现有 OAuth 授权，页面展示目标系统账号和企业微信身份，用户点击确认后执行绑定。
5. 校验学校 CorpId、目标账号状态、身份匹配和现有绑定唯一性；已绑定其他系统用户时拒绝覆盖。
6. PC 轮询自己创建的会话状态，完成后重新获取身份上下文和权限，恢复业务页面；过期提供刷新二维码。
7. 关闭绑定页、切换账号或退出登录使当前票据失效；确认采用一次性消费和锁，拒绝重复消费。

新增创建/轮询接口属于“已登录但可未绑定”白名单；手机扫码/OAuth 入口由一次性票据和 OAuth state 校验，不放宽业务接口权限。二维码确认过程不依赖手机预先登录与 PC 相同的账号。

管理员用户列表、绑定详情和登录拦截统一采用同一有效绑定判断，包含 CorpId 和失效状态，避免“显示已绑定但仍拦截”。既有强制绑定学校配置保持有效。

主要复用 `WechatBindingController`、`WechatBindingService`、`UserWechat`、`fontend/shared/useWechatBinding.js` 和 `WechatBindingGate.vue`；H5 增加手机确认页面。

## 5. C：壁纸库与默认壁纸

- 个人设置中提供“学校默认”“我的上传”“壁纸库”三个选择入口。
- 上传提示推荐 `1920 × 1080 px` 或更高、16:9 横图、最大 8 MB；桌面按比例铺满并居中裁切。
- 新增学校库中的壁纸记录，包含文件 ID、上传人、名称、是否共享、创建时间及软删除时间；文件保存复用 `FileService`。
- 上传默认私有，每张本人上传的壁纸都有“分享到壁纸库”开关；开启后仅对本校已登录用户可见。
- 本人上传的壁纸可反复选择。壁纸库支持分页、预览与“一键应用”，应用操作立即保存个人选择。
- 分享关闭后从公共库隐藏；已选择这张图的其他用户在重新加载设置时回到学校默认，不继续获取已转为私有的文件。
- 壁纸文件访问按所有者、共享状态和学校默认引用校验，不把私有壁纸作为匿名公开素材。
- 学校默认壁纸在“学校设置”维护，可上传新图或选择共享图；普通用户只能选择“使用学校默认”，不能修改默认来源。
- 管理员选定的默认图由学校文件引用保留；原上传者关闭分享不破坏全校默认配置。
- 更换学校默认仅影响选择“学校默认”的用户，不覆盖用户自行选择的其他壁纸。
- 升级时将每个账号当前有效的壁纸纳入“我的上传”。更早文件若只有混用的 `profile` 分类，不能可靠区分头像和壁纸，不将这些文件自动公开；可在本人文件中选择图片加入壁纸库。
- 个人选择保存壁纸 ID/模式，兼容已有 `layout_json` 字段。上传和分享使用独立接口，避免保存个人资料时丢失配置。

新增壁纸 Controller、Service、Model 与 PC 壁纸选择组件；App.vue 只保留入口和主题应用。文件隐私规则同步到 `ProtectedFiles`/文件服务。

## 6. D：实习计划与关联任务软删除

- 计划列表增加删除操作，权限沿用实习计划管理和当前数据范围。
- 删除影响查询返回计划名称、活动任务数量、任务列表及已有历史记录的提示。
- 无任务时确认删除计划；存在任务时提示“一并删除关联的 N 个实习任务”，提供“一并删除”和“取消”，不制造活动任务引用已删除计划的状态。
- 服务端在事务中锁定计划并重新检查关联任务；若预览后关联关系变化，返回数据已变化并要求重新确认。
- 删除以同一时间写入计划和关联任务的 `deleted_at`，重复提交保持幂等；不硬删除计划、任务、学生过程材料、附件、审核记录或签名快照。
- 删除任务退出活动任务、待办、下拉选项、统计和可写入口；历史材料仍保留原关联，用于有权限的历史查询与追溯。
- 通用工作流接入后，同一事务取消该计划和任务未完成的审批任务，避免删除后仍能审核。
- 关联查询严格使用 `arrangement.plan_id` 和当前学校连接，不涉及 `practice_plan` 或 `practice_schedule`。

主要改动 `InternshipController`、`InternshipService`、`InternshipRecord`、PC 计划列表和 `api/system.js`；新增显式删除影响查询与软删除路由。

## 7. E：通用审批与消息服务

### 方案比较

| 方案 | 复用方式 | 代价 |
| --- | --- | --- |
| 推荐：抽取现有审批能力为通用服务 | 复用社会实践节点推进、现有事务/锁、权限、消息队列和记录 | 需逐个接入既有模块，保持历史流程兼容 |
| 引入 Symfony Workflow | 提供状态机、流转条件和事件能力，PHP 8.4 可用 | 审批人、节点配置、记录、通知和持久化仍需自行实现 |
| 引入 Laravel Workflow | 持久工作流运行时和任务编排 | 直接依赖 Laravel Framework，与现有 Webman 集成成本高 |

已读取 GitHub 上 Symfony Workflow 8.0 和 Laravel Workflow 的 Composer 依赖声明。前者仅要求 PHP >= 8.4；后者依赖 `laravel/framework`。本批次采用第一种方案，状态流转约束参考成熟组件，复用现有数据与运行环境。

- Symfony Workflow：<https://github.com/symfony/workflow>
- Laravel Workflow：<https://github.com/laravel-workflow/laravel-workflow>

### 服务边界

- `WorkflowService` 只负责定义、实例、节点任务、流转、幂等、审计与阶段事件；不直接计算经费、创建基地或处理课程数据。
- 各模块通过注册的适配器提供实体权限、显示信息、状态读写和通过后的必要回调；不允许请求参数指定任意类名或数据库表。
- 新增学校库中的流程定义/版本、节点、实例、审批任务、操作记录、通知待投递记录。
- 提交时保存流程版本、节点配置、候选审批人和业务资料版本快照。后续编辑流程配置不改变已运行实例。
- 状态兼容现有 `draft / wait / accept / modify`，取消任务记录明确的取消原因，退回修改后提交开启新审批轮次，历史轮次可查看。

### 节点与审批人

- 学校管理员维护流程，可按模块和学院选择适用流程。
- 串行节点支持指定账号、指定角色并限定学院范围；多人节点支持或签和会签。无需增加脚本表达式或任意代码执行能力。
- 抄送为独立通知节点，不计入审批完成条件。
- 默认经费流程为“直接上级 → 教务处审批 → 教务处领导 → 抄送”；管理员可增加学院教务、学院院长等节点，以适配 PDF 中不同学院的流程。
- 直接上级没有可靠现成组织关系时，管理员配置学院对应的审批账号。流程发布前必须解析到有效审批人；缺人时阻止发布/提交并提示具体节点，不自动跳过。
- 提交人只能查看审批链，不能删减审核人或抄送人。
- 只有当前节点的有效审批人可处理。或签首次通过后取消同节点其他待办；会签全部通过再推进；任何审批人退回则本轮退回申请人。
- 每次审批同时校验实例版本、活动节点、审批任务与实体可写状态；重复操作不得重复推进或发消息。

### 既有模块接入

- 经费申请和基地申报首先使用统一实例与节点模型。
- 实习计划五级审核、实习其他审核、实验实训、社会实践的审批入口统一调用通用服务，经各自适配器保留原权限和状态规则。
- 已运行旧流程按原节点与记录继续运行；由兼容适配器提供统一入口和记录读取，不重启原流程、不补发历史通知。
- 新增模块调用同一服务，不再复制每套业务的锁、节点推进和通知逻辑。

### 阶段消息

- 每个节点配置“是否发送消息”、消息模板及允许渠道。关闭时仍产生待办/审批记录，但不主动投递消息。
- 收件人由当前审批任务或抄送节点解析，禁止把全部管理员作为默认收件人。
- 实际渠道为节点渠道、学校启用渠道、模板配置、个人接收偏好的交集；沿用企业微信允许时段和绑定有效性检查。
- 站内、企业微信复用现有 `MessageService`、模板、日志、Redis 队列和重试。短信新增业务通知驱动，独立于验证码发送，不将验证码接口当成业务短信接口。
- 学校设置配置短信业务网关和模板；仅在配置完整且个人允许接收时启用。缺配置时显示不可用并记明原因，不返回虚假的发送成功。
- 流程状态与通知待投递记录同事务提交；通知异步执行，失败可重试，不回滚已完成的审批。
- 同一流转、收件人、渠道使用稳定去重键；日志保留发送状态与失败原因。

## 8. F：电子签名

- 个人设置新增签名预览、手机扫码签名和重新签名；H5“我的”提供直接手写入口。
- 手机页面提供手写画布、清空、重写、保存；空白签名不可保存，输出透明 PNG，裁去多余空白并保留合理边距。
- PC 创建 5 分钟有效的一次性签名会话；H5 必须验证为同一系统用户后才能保存，学校和用户不同则拒绝。
- 签名文件按用户私有保存，每次修改产生新版本。二维码中不包含签名图片、JWT 或密码。
- 审批节点可配置是否需要电子签名。审批人处理时确认使用自己的签名，审批记录保存文件 ID、版本、摘要、签署人和时间。
- 修改个人签名不覆盖历史文件；历史导出仅引用当次审批签名快照。
- 未签名的历史记录继续展示原姓名、意见、日期，不用当前签名补写历史审批。
- 公共导出签名组件供 PHPWord、HTML/PDF 和表格导出复用；各模板只在对应签名位置按比例嵌入签名，并显示审核日期。
- 本次接通基地申报、经费申请、实习实施表及已有审批记录导出中明确的签名位置；通用导出统一读取审批快照。
- 原 `safety_letter_sign.signature_file_id` 是签字定稿文件，继续保留其原用途。

主要增加签名 Controller、Service、Model、H5 手写组件及 PC 签名设置组件；复用文件和异步导出基础设施。

## 9. G：经费管理

- 新增独立“经费管理”模块，首个业务入口为“基地建设费用申请”。
- 提供申请列表、我的申请、待我审批、申请详情、流程记录与导出；权限独立定义，并采用当前学校/学院/本人数据范围。
- 使用现有 `base_expense` 作为申请主体，补充字段与子表；保留历史记录 ID，旧审批通过记录不会被转换为新待审记录。

### 表单字段

| 字段 | 行为 |
| --- | --- |
| 审批编号、申请人、提交时间、审批状态 | 系统生成和维护 |
| 表格类型 | 基地建设费用申请中的“经费表” |
| 单位名称 | 从允许访问的学院/组织选项选择 |
| 学年学期 | 复用已有学年学期选项 |
| 基地名称 | 选择当前范围内有效基地 |
| 基地类型、基地类别 | 从现有基地资料带出并形成提交快照；不把“核心基地”和“长期/临时”混为同一枚举 |
| 费用明细 | 每行“建设项目、项目金额”，支持新增、复制、删除 |
| 总项目金额及大写 | 前端即时计算，后端使用两位小数的精确金额重新汇总 |
| 附件 | 多文件，复用文件服务并校验权限和正式引用 |
| 备注 | 文本输入 |
| 审批流程 | 提交前展示学校配置的完整节点，不允许申请人删改 |

建设项目初始选项按附件：基地基础建设、企业导师队伍建设、校内教师实践、校企课程开发、教赛结合、评估激励、资料完善及成果打造。

金额必须为正且最多两位小数，明细至少一项，拒绝超出存储精度的数值；允许同一项目存在多条明细。后台不接受客户端自报总额作为入库依据。

### 审批与导出

- 草稿和退回状态可编辑，提交后冻结该轮业务快照；审批中修改申请须退回后重新提交。
- 审批节点按 E 执行，意见、时间和签名按 F 留存。
- Word/PDF 使用相同申请和审批快照，包含申请信息、费用明细、金额合计/大写、附件名称、备注与审批过程。
- 导出通过 `ExportTaskService` 排队生成；费用行、较长基地名称、较长意见及多页审批记录允许换行和分页，不截断内容。
- 旧 `base_expense` 历史记录按现有金额和内容显示“历史记录”，不伪造项目明细或签名。

主要增加 `ExpenseController`、`ExpenseService`、相应 Model、PC 独立表单/列表组件和 H5 审批页面；扩展 `InternshipDocumentExporter` 或注册独立费用导出处理器。

## 10. H：数据库、验证与发版

- 新结构同时维护初始化定义、可重复执行的增量迁移、SQL 说明和数据库结构基准。已有学校库使用增量迁移，不重跑初始化。
- 移动配置入口保留原配置；新增表均使用学校连接并遵循现有软删除/文件引用规则。
- PHP 文件执行语法检查，PC/H5 执行生产构建，客户端执行锁定依赖的编译检查，Git 差异执行空白和冲突检查。
- 实际核对登录 Logo 和 Hover、学校/个人设置权限、两种桌面风格的最大化与还原、壁纸分享范围、未绑定账号扫码、计划删除影响、各审批节点、金额汇总、签名版本和导出排版。

- 全部功能可用后更新客户端版本及各锁文件、服务端发布说明和数据库升级清单。版本号基于发布时现有最新版本递增。

- 三个平台构建成功后校验安装包、升级签名、版本清单和 SHA256，再正式发布客户端。
