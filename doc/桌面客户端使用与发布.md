# 桌面客户端使用与发布

## 安装与连接

1. macOS 打开 DMG，把 `Practical System.app` 拖到“应用程序”。通用包支持 Apple Silicon 和 Intel，最低 macOS 12。
2. Windows 运行 NSIS `.exe` 安装程序。使用系统 WebView2；设备缺少 WebView2 时，安装器需要联网获取运行时。
3. Linux 使用 `.deb` 安装，或给 `.AppImage` 添加可执行权限后运行。AppImage 设备需具备 FUSE 运行条件；没有 FUSE 时可使用 `.deb`。
4. 启动客户端，在“学校域名”填写学校提供的地址，例如 `sx.2iwm.com`。可包含 `https://` 和端口；不填写接口路径或账号密码。
5. 点击“连接学校”，客户端读取该域名对应的学校名称，进入内置 PC 登录页。账号、密码、角色和业务权限与学校网页版本相同。
6. 通过应用菜单“连接设置”更换学校。已有学校窗口时需确认切换；确认前保存正在填写的内容。

`127.0.0.1:8787`、`localhost:8787` 和 `[::1]:8787` 会使用本机 HTTP。其他学校地址必须支持有效 HTTPS，客户端不提供关闭证书校验的选项。服务器仍按请求域名识别学校，应在学校配置中维护实际访问域名。

## 文件与窗口

- 页面使用现有 PC 前端，支持原生窗口的最小化、最大化、全屏及尺寸调整。
- “窗口”菜单提供前进、后退、重新加载、页面缩放和下载文件夹入口。
- 学校附件使用客户端当前登录会话。预览和打印在关联窗口打开；Word、Excel、压缩包等文件下载后使用系统“另存为”选择保存位置。
- 文件上传继续使用现有页面的上传按钮和系统文件选择器。
- 收藏夹支持独立客户端窗口或系统默认浏览器打开；外部窗口的原生菜单提供复制网址与浏览器打开。
- 复制给其他人的一键登录链接使用学校服务器地址；不会包含本机内部通信端口。
- 退出登录、关闭学校窗口或结束客户端进程会结束本次会话。学校地址会保留，JWT 不写入本机配置文件。

## 本机配置

连接配置文件名为 `schools.json`，保存学校域名、学校名称及本机通信端口，不保存账号密码。

| 系统 | 默认目录 |
| --- | --- |
| macOS | `~/Library/Application Support/com.2iwm.practical.desktop/` |
| Windows | `%APPDATA%\com.2iwm.practical.desktop\` |
| Linux | `$XDG_CONFIG_HOME/com.2iwm.practical.desktop/`，未配置时使用 `~/.config/` |

接口通道仅监听回环地址，并校验本机会话及请求来源。不同学校使用独立 Cookie 容器及页面存储来源。用户不应把客户端内部的 `127.0.0.1` 地址提供给其他设备访问。

## 开发与构建

安装包统一由 GitHub Actions 构建，包括 Mac 通用、Windows x64 和 Linux x64。本机仅进行前端编译与 Rust 代码检查：

```sh
npm ci --prefix fontend/pc
npm ci --prefix fontend/desktop
npm run build --prefix fontend/desktop
cd fontend/desktop/src-tauri
cargo check --locked
cargo clippy --locked -- -D warnings
```

客户端构建复用同一份 PC 源码，产物写入 `fontend/desktop/dist`，不覆盖 `server/public/pc`。本次源代码版本为 0.2.0；正式安装文件以 GitHub Release 中实际发布的版本为准。

## GitHub Actions

构建仓库：`https://github.com/isle24/practicalSystem`。

工作流 `.github/workflows/desktop-build.yml` 目前只在 GitHub 收到 `v*` 标签推送，或在 Actions 中手动选择 `Desktop installers` 时运行。推送 Gitea `master` 不会同步 GitHub；只推送 GitHub `main` 也不会启动构建。发布前先同步公开客户端快照，再推送与客户端版本一致的标签。

Mac 产出 Apple 芯片（ARM）、Intel 芯片和通用版 DMG。两种芯片均使用同一份签名升级包。Windows x64 产出 NSIS 安装程序，Linux x64 产出 DEB 和 AppImage。手动运行未开启 publish 时只提供 Artifacts。推送版本标签或在手动运行时开启 publish，所有平台成功后会发布到 GitHub Release。学校可从 GitHub 导入已发布安装包。

0.2.0 对应的[成功构建与发布记录](https://github.com/isle24/practicalSystem/actions/runs/34456473667)使用客户端提交 `29061843921f1095718022dbd3d873bdc3089d3a`。Mac、Windows、Linux 均由 Actions 编译和签名，三个平台及发布任务全部通过。收集时统一文件名，发布前复核 GitHub 实际保存的名称、数量、大小和 SHA256，全部一致后公开 Release。

Gitea 保存完整项目；GitHub 保存构建所需的 PC 前端与桌面客户端，不复制后端、数据库或学校业务文档。同步时在单独 GitHub checkout 中更新以下目录：

- `fontend/pc/`
- `fontend/desktop/`
- `fontend/shared/`
- `.github/workflows/desktop-build.yml`
- 本文、两份桌面客户端设计与实施文档、对应版本的桌面客户端发布说明。

先提交 Gitea 项目的修改，再从该提交导出上述文件，提交到 GitHub `main`。不要用 Gitea 分支强推覆盖 GitHub 独立历史。

## 更新与分发

客户端内置 PC UI，因此前端改动需要重新生成安装包。服务端接口更新需考虑已安装版本的兼容性。0.2.0 增加学校管理员控制的更新服务；导入只生成草稿，学校手动发布后客户端才提示升级。签名校验通过并经用户确认后覆盖安装，保留学校连接设置。0.1.0 用户需手动覆盖安装一次新版。

从 0.3.29 起，macOS 构建默认对应用及 Node 辅助进程执行完整 ad-hoc 签名，包含 Node 所需 JIT 权限；这不等于 Apple Developer ID 签名或 Apple 公证。当前未配置 Apple 公证和 Windows 代码签名证书，组织分发可使用自己的签名凭据。Tauri 自动更新签名与操作系统代码签名分别管理。

0.1.0 的 macOS 已实际核对学校连接、教师及学生登录、带鉴权的 PDF 预览、Word 文件下载及系统另存为。Windows/Linux 安装包由 Actions 构建，尚未进行这两个平台的实机操作验收；Intel Mac 启动、文件上传和实际打印也尚未完成实机核对。

0.2.0 已完成三端云端构建与 GitHub 发布，全部上传产物的名称、大小和摘要校验通过。Mac 更新包与 Windows 安装程序另经本地实际下载校验，SHA256 及 Tauri 签名通过；其余安装包未完成本地下载复核。本版各平台实际安装、原生窗口操作及自动更新的实机验收尚未完成；云端构建成功不能替代这些操作验证。

鸿蒙下载入口显示「适配中」。当前发布工作流产出 macOS、Windows 和 Linux 安装包。

0.2.0 的数据库升级、签名 Secrets、只读 GitHub 令牌和学校发布步骤见 [桌面工具与版本发布部署](桌面工具与版本发布部署.md)。

## 更新说明字段

用户可见的功能、界面和使用变化写入 `notes_html`。更新程序范围、服务器路径、数据库字段、SQL、迁移命令、重启及部署顺序写入 `upgrade_notes_html`，由具有现行版本维护权限的管理员查看和编辑。

服务端 `server/resource/releases/<version>.json` 可以同时包含两个字段；客户端公开的 `fontend/desktop/releases/<version>.md`、`desktop-release.json.notes` 及 GitHub Release 正文只包含用户说明。不要将管理员事项拼接到公共正文末尾。

学校发布只复制用户正文到 `published_notes_html`。普通更新列表、更新提示和安装包更新清单不返回管理员字段。保存说明不执行 SQL 或生产部署。

本轮字段升级及历史正文分离流程见 [更新说明、本地预览与用户筛选](2026-10-14-更新说明与本地预览及用户筛选.md)。旧库须执行对应升级脚本，既有公开 GitHub 历史不会因本地修改而改变。
