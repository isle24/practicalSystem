# 桌面客户端使用与发布

## 安装与连接

1. macOS 打开 DMG，把 `Practical System.app` 拖到“应用程序”。通用包支持 Apple Silicon 和 Intel，最低 macOS 12。
2. Windows 运行 NSIS `.exe` 安装程序。使用系统 WebView2；设备缺少 WebView2 时，安装器需要联网获取运行时。
3. Linux 使用 `.deb` 安装，或给 `.AppImage` 添加可执行权限后运行。AppImage 设备需具备 FUSE 运行条件；没有 FUSE 时可使用 `.deb`。
4. 启动客户端，在“学校域名”填写学校提供的地址，例如 `sx.2iwm.com`。可包含 `https://` 和端口；不填写接口路径或账号密码。
5. 点击“连接学校”，客户端读取该域名对应的学校名称，进入内置 PC 登录页。账号、密码、角色和业务权限与学校网页版本相同。
6. 通过应用菜单“连接设置”更换学校。已有学校窗口时需确认切换；确认前保存正在填写的内容。

`127.0.0.1:8787`、`localhost:8787` 和 `[::1]:8787` 会使用本机 HTTP。其他学校地址必须支持有效 HTTPS，客户端不提供关闭证书校验的选项。服务器仍按请求域名识别学校，应在学校配置中维护实际访问域名。

## 文件与窗口

- 页面使用现有 PC 前端，支持原生窗口的最小化、最大化、全屏及尺寸调整。
- “窗口”菜单提供前进、后退、重新加载、页面缩放和下载文件夹入口。
- 学校附件使用客户端当前登录会话。预览和打印在关联窗口打开；Word、Excel、压缩包等文件下载后使用系统“另存为”选择保存位置。
- 文件上传继续使用现有页面的上传按钮和系统文件选择器。
- 收藏夹等外部网页交给系统默认浏览器打开。
- 复制给其他人的一键登录链接使用学校服务器地址；不会包含本机内部通信端口。
- 退出登录、关闭学校窗口或结束客户端进程会结束本次会话。学校地址会保留，JWT 不写入本机配置文件。

## 本机配置

连接配置文件名为 `schools.json`，保存学校域名、学校名称及本机通信端口，不保存账号密码。

| 系统 | 默认目录 |
| --- | --- |
| macOS | `~/Library/Application Support/com.2iwm.practical.desktop/` |
| Windows | `%APPDATA%\com.2iwm.practical.desktop\` |
| Linux | `$XDG_CONFIG_HOME/com.2iwm.practical.desktop/`，未配置时使用 `~/.config/` |

接口通道仅监听回环地址，并校验本机会话及请求来源。不同学校使用独立 Cookie 容器及页面存储来源。用户不应把客户端内部的 `127.0.0.1` 地址提供给其他设备访问。

## 本机编译

安装 Node.js 22、Rust stable 和对应平台的原生工具链。Mac 桌面构建使用 Xcode Command Line Tools 即可；Intel/Apple Silicon 通用构建需安装两个 Rust target。

在项目根目录执行：

```sh
npm ci --prefix fontend/pc
npm ci --prefix fontend/desktop
```

Apple Silicon 包：

```sh
cd fontend/desktop
npm run bundle:mac
```

Mac 通用包：

```sh
rustup target add aarch64-apple-darwin x86_64-apple-darwin
cd fontend/desktop
npm run bundle:mac:universal
```

输出目录分别为 `fontend/desktop/src-tauri/target/aarch64-apple-darwin/release/bundle/` 和 `fontend/desktop/src-tauri/target/universal-apple-darwin/release/bundle/`。

上述 Mac 脚本使用 `CI=true`，跳过 DMG 的 Finder AppleScript 外观设置，避免 Finder AppleEvent 超时；应用和安装镜像照常生成，不修改系统安全设置。

首版通用安装包为 `fontend/desktop/src-tauri/target/universal-apple-darwin/release/bundle/dmg/Practical System_0.1.0_universal.dmg`。已确认包含 `x86_64` 与 `arm64`，DMG 完整性校验通过。

仅构建前端执行 `npm run build --prefix fontend/desktop`；运行开发客户端执行 `npm run dev --prefix fontend/desktop`。两者均先编译同一份 `fontend/pc` 源码，桌面产物写入 `fontend/desktop/dist`，不覆盖 `server/public/pc`。

## 下载安装包

[GitHub Release v0.1.0](https://github.com/isle24/practicalSystem/releases/tag/v0.1.0) 提供 Mac 通用包、Mac Apple Silicon 包、Windows x64 安装程序、Linux x64 deb/AppImage 及 `SHA256SUMS.txt`。在 Assets 中选择对应安装包，不要下载 Source code。仓库为私有仓库，需要登录有仓库权限的 GitHub 账号。

各安装包适用设备及安装方式见 [桌面客户端发布说明 v0.1.0](桌面客户端发布说明-v0.1.0.md)。已发布安装包保存在 Release 中，不受 Actions Artifacts 保留期限影响。

## GitHub Actions

构建仓库：`https://github.com/isle24/practicalSystem`。

工作流 `.github/workflows/desktop-build.yml` 在 `main`/`master` 收到客户端、PC 前端或工作流变更时运行，也可以在 GitHub 的 Actions 中手动选择 `Desktop installers` 运行。

Windows x64 产出 NSIS 安装程序；Linux x64 产出 deb 和 AppImage。进入相应运行记录，在 Artifacts 下载。仓库为私有仓库，下载需要 GitHub 仓库访问权限。工作流不自动创建公开 Release。

0.1.0 对应的[成功构建记录](https://github.com/isle24/practicalSystem/actions/runs/34323364792)使用客户端提交 `99395a0`，包含 `windows-x64-nsis`、`linux-amd64-deb`、`linux-amd64-appimage` 三个下载项。Artifacts 有保留期限，过期后重新运行工作流生成安装包。

Gitea 保存完整项目；GitHub 保存构建所需的 PC 前端与桌面客户端，不复制后端、数据库或学校业务文档。同步时在单独 GitHub checkout 中更新以下目录：

- `fontend/pc/`
- `fontend/desktop/`
- `.github/workflows/desktop-build.yml`
- 本文、两份桌面客户端设计与实施文档、对应版本的桌面客户端发布说明。

先提交 Gitea 项目的修改，再从该提交导出上述文件，提交到 GitHub `main`。不要用 Gitea 分支强推覆盖 GitHub 独立历史。

## 更新与分发

客户端内置 PC UI，因此前端改动需要重新生成安装包。服务端接口更新需考虑已安装版本的兼容性。当前没有配置自动更新服务或下载后自动安装。

当前构建未配置 Apple Developer 签名、公证和 Windows 签名证书。Mac 产物只具有编译器生成的 ad-hoc 签名，不能视为已公证的正式分发包。组织正式分发前需配置自己的签名凭据。

macOS 已实际核对学校连接、教师及学生登录、带鉴权的 PDF 预览、Word 文件下载及系统另存为。Windows/Linux 安装包由 Actions 构建，尚未进行这两个平台的实机操作验收；Intel Mac 启动、文件上传和实际打印也尚未完成实机核对。

鸿蒙 NEXT 不属于 Tauri 官方支持平台。本工程不生成鸿蒙原生包；其客户端需要独立的 ArkTS/ArkWeb 工程。Android APK 也不能替代 HarmonyOS NEXT 原生包。
