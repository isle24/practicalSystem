# 实习档案材料改造设计

## 1. 范围与口径

本次改造以 `doc/实习档案清单及附件` 中的 12 类材料为档案清单，不使用学年和学期筛选。毕业实习档案使用毕业届次，其他实习档案使用年级，并继承所属计划的实际归属范围。教学实习实施表以已确认的新版实施（经费）表为唯一生效版式，目录中的旧版实施表仅用于历史字段兼容。

原始模板只读保留。系统生成的文件、用户上传的定稿件和历史版本通过现有文件系统管理。

## 2. 档案清单与材料层级

| 类型编码 | 材料 | 材料层级 | 主要来源 |
| --- | --- | --- | --- |
| `plan` | 实习计划 | 计划 | 实习计划表 |
| `implementation_sheet` | 教学实习实施表 | 任务 | 实习实施 |
| `syllabus` | 实习教学大纲 | 计划 | 大纲结构化内容或定稿件 |
| `guide` | 实习指导书 | 计划 | 指导书结构化内容或定稿件 |
| `registration` | 实习情况登记表 | 任务 | 任务、学生绑定和实施数据生成 |
| `teacher_work_report` | 指导教师工作报告 | 任务 | 教师填报内容和附件 |
| `journal` | 实习周（日）志 | 学生任务 | 学生分次提交 |
| `report` | 实习/实训报告 | 学生任务 | 学生普通实习报告 |
| `graduation_report` | 毕业实习报告 | 学生任务 | 学生毕业实习报告 |
| `graduation_appraisal` | 毕业实习成绩鉴定表 | 学生任务 | 过程管理、实习单位、校内指导教师评分和定稿件 |
| `score_register` | 成绩登记表 | 计划班级 | 学生任务成绩生成 |
| `safety_commitment` | 学生实习安全承诺书 | 学生任务 | 学生签署定稿件 |

保险记录和抽查记录属于合规附加材料，继续管理和展示，不冒充上述 12 类档案。

## 3. 数据模型

### 3.1 统一档案实例

新增 `internship_archive_material` 作为材料实例和快照索引，不取代实习计划、日志、报告、成绩等现有业务表。

主要字段：

- `material_type`：12 类材料编码。
- `scope_type`：`plan`、`arrangement`、`student_task`、`plan_class`。
- `plan_id`、`arrangement_id`、`student_id`、`class_id`：层级主键。
- `template_id`、`template_version`：生成时使用的模板快照。
- `source_entity_type`、`source_entity_id`：现有业务数据来源。
- `content_json`：结构化表单快照。
- `generated_file_id`：系统生成件。
- `signed_file_id`：用户上传的签字或盖章定稿件。
- `recording_id`：对应本次提交记录。
- `archive_version`：档案版本号。
- `status`：`draft`、`submitted`、`archived`、`replaced`。
- `archived_at`、`created_by`、`updated_by`、`created_at`、`updated_at`、`deleted_at`。

同一层级、同一材料类型可以有多个历史版本，但只有一个未替换的当前版本。重新生成或重新提交时，旧版本标记为 `replaced`，不覆盖历史文件。

首版草稿提交时更新当前首版；当前版本已经为 `submitted` 或 `archived` 后再次保存、提交、生成或上传定稿件时，旧版本改为 `replaced`，新建递增版本。新版本只关联本次操作明确提交的文件，不沿用旧版本生成件或签章件。

### 3.2 现有业务表扩展

- `internship_syllabus_guide` 增加 `document_type`，取值 `syllabus` 或 `guide`，大纲和指导书分开维护。
- `internship_report` 增加 `report_type`，取值 `general` 或 `graduation`，并增加 `form_data`。
- 新增 `internship_graduation_appraisal`，保存过程管理得分（50 分）、实习单位评分（30 分）、校内指导教师评分（20 分）、评语、五级制结果、签字盖章件和提交状态。
- 模板表增加 `business_code`、`material_type`、`scope_type`、`practice_types`，模板分类不再代替业务语义。

## 4. 归档判定

归档以 `internship_archive_material.status = archived` 且存在可访问的生成件或签章定稿件为准，不再仅根据源表有数据或状态值推断。

- 实习计划、实施表、登记表和成绩登记表必须生成并冻结文件快照。
- 大纲、指导书和教师工作报告必须存在生成件或定稿上传件。
- 日志必须满足任务配置的应交数量，且每份均已通过，才能生成日志合集并归档。
- 普通报告与毕业报告分别判定，不相互代替。
- 毕业实习鉴定表必须有独立鉴定数据和定稿件，不使用“报告已通过 + 有成绩”替代。
- 安全承诺书必须存在学生签署文件，仅有签署时间不算归档。
- 保险合规状态必须同时满足保单附件存在、保险期限覆盖任务时间。

列表先按计划展示公共材料完成度，再下钻任务、班级和学生，不将公共材料在每个学生行重复统计。

保险和抽查作为合规附加材料显示在任务和学生档案详情中，不计入 12 类档案完成度。校外任务按学生校验保单附件有效性及保险起止日期对任务起止日期的完整覆盖；任务层显示保险覆盖人数和抽查总数，学生层显示本人保险状态、抽查次数和最近结果。

## 5. 提交、审核与并发

结构化表单保存草稿时只更新业务主表和材料草稿，不发待办和消息。提交时使用现有 recording 机制生成新记录，通过消息模板 code 发送待办和消息。审核意见使用现有 review_opinion 机制，审核草稿使用 review_opinion_draft。

保存、提交、审核、通过后修改、生成和归档都使用学校库事务和现有 Redis 工作流锁。前端提交期间禁用按钮，接口返回或超时后恢复。

## 6. 文件与模板

模板库初始化“实习档案”分类和 12 类模板元数据。模板原文件通过文件系统入库，模板记录只保存 `file_id`。生成结果使用 `FileService::storeGeneratedFile()` 入库，用 `FileService::attach()` 建立业务关联。

系统优先保留 Word/Excel 原模板版式。不能可靠填充的旧 `doc` 文件先转换为可维护的 `docx` 模板，不使用手写 HTML 假装 Word 模板。

## 7. PC 与 H5

PC 端归档材料改为“计划 -> 任务 -> 班级/学生”下钻查看，提供生成、上传定稿件、查看、下载、历史版本和归档操作。表单和详情继续使用弹窗，列表只显示摘要。

H5 端学生只显示本人当前任务需要提交的日志、普通报告、毕业报告和安全承诺书；指导教师查看自己任务的教师工作报告和待审材料。不在 H5 显示全校归档管理列表。

## 8. 兼容

已有大纲指导书记录默认标记为 `syllabus`，已有报告默认标记为 `general`。旧归档页保留查看能力，但不再使用旧的状态推断结果作为“已归档”。历史数据需通过生成或上传定稿件补齐新档案实例。
