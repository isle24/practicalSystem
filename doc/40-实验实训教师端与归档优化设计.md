# 实验实训教师端与归档优化设计

## 1. 目标

根据学校实验实训课程资料归档要求，统一实验和实训的课程执行入口，明确学生、任课教师、课程负责人和审核人员的工作边界：

- 学生按参与项目分别提交项目报告，报告内包含反思小结。
- 教师批阅学生项目报告、签到等执行材料，并录入项目成绩。
- 课程负责人维护本次开课任务的大纲、考核计划、项目配置和课程教学反思总结。
- 学院管理员、专业管理员按数据范围审核；学校管理员和超级管理员可跨范围审核；提交人不能审核自己提交的材料。
- 课程结束后由系统汇总材料并形成归档包，完成条件不满足时明确显示缺失项和未通过项。

本文中的“教学计划”指一次具体的课程开课任务，不是抽象课程字典。例如同一门课程被两个专业采用时，两个专业分别建立开课任务，学生、课表、项目、教师和归档独立管理。

## 2. 入口与业务名称

### 2.1 学生端

实验实训模块只保留以下入口：

1. 我的课程：查看本人参与的开课任务和项目。
2. 项目报告：按项目提交报告，每个项目最多一个当前有效报告；报告表单内包含“反思小结”。
3. 签到记录：查看本人签到记录。
4. 成绩：查看项目成绩和课程汇总成绩。

取消学生端“过程日志”和“总结报告”两个入口。历史日志保留在记录中，迁移后在对应项目报告详情的历史记录中可查看，不删除原始内容。

### 2.2 教师端

教师端按操作性质分成两个区域：

#### 教学准备与提交

- 我的开课任务。
- 编写教案：任课教师可用，必须关联已通过的大纲。
- 课程教学反思：课程负责人或被授权的任课教师可用，内容为整门课程课后总结，不属于学生材料。
- 成绩管理：课程负责人维护成绩比例，任课教师录入项目成绩。

#### 教学实施与评阅

- 项目与任务：查看课程负责人发布的项目和本人的执行任务。
- 项目报告评阅：查看绑定到本人任务的学生项目报告并处理审核。
- 签到记录：查看本人负责项目的签到记录。
- 成绩管理：录入并提交本人负责项目的学生成绩。
- 归档中心：查看课程材料完成情况和归档版本。

大纲和考核计划只在课程负责人工作区显示提交入口。普通任课教师不显示大纲审核或提交入口。审核人员在独立的待审核视图中查看“大纲审核”“教案审核”“课程教学反思审核”，不使用“待审”作为普通教师的提交入口名称。

### 2.3 管理端

管理端保留统一的实验实训模块和以下功能：

- 开课任务。
- 课表安排。
- 项目管理。
- 项目报告审核。
- 成绩管理。
- 归档中心。
- 场地管理。

管理端流程图节点与上述入口一一对应，点击节点打开对应窗口。流程图只作为导航，不再重复渲染一套相同列表。

## 3. 角色与数据权限

### 3.1 课程角色

`practice_plan` 代表一次开课任务，新增字段：

- `course_leader_id`：课程负责人，关联教师。
- `course_leader_account_id`：课程负责人账号快照，可选，用于账号解绑后的审计留底。

一个开课任务可关联多个任课教师，新增中间表 `practice_plan_teacher`：

- `module_type`：`training` 或 `lab`。
- `plan_id`：开课任务 ID。
- `teacher_id`：任课教师 ID。
- `teacher_role`：`leader` 或 `teacher`。
- `sort`、`status`、`created_at`、`updated_at`、`deleted_at`。

课程负责人也写入关联表，`teacher_role=leader`，并与 `practice_plan.course_leader_id` 保持一致。课程负责人字段用于快速查询和约束，关联表用于多教师范围和审计。

### 3.2 权限规则

| 角色 | 可见和可操作范围 |
|---|---|
| 学生 | 本人参与的开课任务、项目报告、签到和成绩 |
| 任课教师 | 关联到本人任课关系的开课任务及项目；批阅本人任务下学生材料；录入本人任务成绩 |
| 课程负责人 | 任课教师权限；提交本开课任务大纲、考核计划和课程教学反思；维护项目评分比例 |
| 专业管理员 | 本专业数据；可审核本专业范围内由其他账号提交的材料 |
| 学院管理员 | 本学院数据；可审核本学院范围内由其他账号提交的材料 |
| 学校管理员 | 全校数据和审核权限 |
| 超级管理员 | 全校数据和审核权限 |

审核统一执行以下约束：

- 数据范围由服务端 Model 查询方法统一限制，前端筛选不能扩大范围。
- 提交人不能审核自己提交的材料。
- 学校管理员和超级管理员不受相邻或互斥审核节点限制，但仍记录 `reviewer_id`、账号、角色、意见、时间和请求来源。
- 已通过只能执行“通过后修改”；退回后必须由提交人重新提交，状态变为待审核后才能再次审核。

## 4. 数据模型调整

### 4.1 项目报告

现有统一 `report` 表继续作为执行材料表，新增：

- `practice_project_id`：关联 `practice_project.id` 的业务关联字段，兼容已有 `entity_type`、`entity_id`。
- `reflection_summary`：学生在项目报告中的反思小结。
- `report_type`：固定为 `project_report`，历史记录为空时按项目关联和模块类别兼容识别。

`journal` 不再作为学生端主入口，但保留查询和历史流程记录。已有实训日志按 `entity_type` 和 `entity_id` 映射到项目；无法唯一映射的记录只在管理员历史记录中展示，不自动篡改归属。

### 4.2 动态成绩方案

继续复用 `practice_grade_rule` 的 `ratio_json`，规范 JSON 结构：

```json
{
  "attendance_weight": 20,
  "operation_weight": 70,
  "report_weight": 10,
  "projects": [
    {"project_id": 101, "weight": 50},
    {"project_id": 102, "weight": 50}
  ]
}
```

规则约束：

- 默认考勤与课堂表现 `20%`、项目实操 `70%`、课程报告 `10%`。
- 三项一级权重合计必须为 `100%`。
- 项目实操下的项目权重合计必须为 `100%`。
- 新增项目自动进入评分方案；已有项目权重按剩余项目均分，课程负责人可调整。
- 删除或停用项目时保留历史权重，不删除已产生的成绩。
- 成绩录入页面根据当前开课任务的项目列表动态生成项目评分项，不再显示固定“项目1至项目12”。

### 4.3 课程归档

新增 `practice_archive`：

- `module_type`、`plan_id`、`version_no`。
- `status`：`ready`、`archived`、`invalidated`。
- `snapshot_json`：归档时的开课任务、项目、教师、学生、成绩和材料清单快照。
- `missing_items_json`、`pending_items_json`：生成归档检查结果。
- `archive_file_id`：打包文件关联 ID，可为空，支持异步生成。
- `created_by`、`created_at`、`invalidated_by`、`invalidated_at`、`invalidate_reason`。

归档不复制业务表数据，业务表保留当前状态；归档表保存版本快照和打包文件引用。

## 5. 业务流程

### 5.1 开课任务与项目

```text
教学计划同步或手工创建
  -> 设置年级、学院、专业、课程负责人
  -> 关联一个或多个任课教师
  -> 课程负责人提交大纲、考核计划
  -> 审核通过后安排课表
  -> 发布项目并关联项目执行教师
  -> 绑定项目学生
  -> 开始签到和项目执行
```

项目发布后，服务端在同一事务内调用成绩规则同步方法，将项目加入 `practice_grade_rule.ratio_json`。项目保存失败或评分规则同步失败时整体回滚。

### 5.2 项目报告与教学反思

```text
学生选择本人参与项目
  -> 填写项目报告和反思小结
  -> 保存草稿或提交审核
  -> 任课教师在项目报告评阅中查看完整报告
  -> 通过 / 修改
  -> 修改后学生重新提交新 recording 版本
课程结束
  -> 课程负责人撰写课程教学反思总结
  -> 按管理员数据范围审核
```

每次提交写入新的 `recording`，主表保留当前状态；审核意见只写入 `review_opinion`，流程详情按“提交内容主线 + 审核意见支线”展示。

### 5.3 成绩管理

```text
课程负责人确认成绩比例
  -> 系统根据项目动态生成评分项
  -> 任课教师按项目和学生录入成绩
  -> 系统按权重计算课程汇总成绩
  -> 教师提交成绩
  -> 管理员或课程负责人按权限核定
```

成绩草稿不发消息、不进入审核人的待办；提交后状态变为待审核并通知对应处理人。成绩修改走已有通过后修改流程，生成新记录并留痕。

### 5.4 归档中心

归档中心按开课任务展示：

- 教学计划。
- 大纲。
- 考核计划和成绩比例。
- 课表与签到记录。
- 教案。
- 项目清单。
- 学生项目报告及反思小结。
- 成绩明细与课程汇总成绩。
- 课程教学反思总结。

每项显示 `已提交`、`待提交`、`审核中`、`已通过`、`需修改`。材料可随时预览和下载；只有必交材料齐全且需审核材料全部通过时，才允许正式归档。归档前返回缺失项和未通过项，不生成归档版本。正式归档生成递增版本快照和归档包；通过后修改产生新提交，归档中心标记原版本为失效并允许生成下一版本。

## 6. 接口契约

继续使用 `/api/practice/*` 默认路由，新增接口保持控制器薄、查询封装在 Model：

| 方法 | 用途 |
|---|---|
| `GET /practice/plan-teachers` | 查询开课任务课程负责人和任课教师 |
| `POST /practice/save-plan-teachers` | 保存课程负责人和任课教师关系 |
| `GET /practice/archive-check` | 返回归档清单、缺失项和未通过项 |
| `POST /practice/archive` | 校验通过后生成归档版本 |
| `GET /practice/archive-list` | 分页查询归档版本 |
| `GET /practice/archive-detail` | 查看归档快照和材料清单 |

现有 `/practice/journals` 保留用于历史查询；新前端不再把它显示为学生主入口。现有 `/practice/reports` 的新增和编辑请求统一写入 `report_type=project_report`、`practice_project_id` 和 `reflection_summary`。

## 7. 前端调整

### 7.1 PC

- 教师工作台使用“教学准备与提交”“教学实施与评阅”两个分区。
- 流程节点可点击并调用现有窗口切换方法。
- 学生显示“项目报告”，隐藏“过程日志”和“总结报告”。
- 教师显示“项目报告评阅”和“课程教学反思”，不显示学生日志提交入口。
- 成绩管理合并“成绩比例”和“成绩评定”，内部用两个页签切换。
- 增加“归档中心”列表和归档详情弹窗。

### 7.2 H5

- 学生卡片入口改为“项目报告”，报告表单增加反思小结。
- 教师首页分为“待处理评阅”和“教学准备”，课程教学反思归入教学准备。
- 成绩管理按开课任务展示项目评分卡和动态权重。
- 归档中心使用按材料类型分组的卡片，不在移动端显示大表格。

## 8. 迁移与兼容

1. 增量初始化为 `practice_plan` 增加负责人字段和教师关系表。
2. 为 `report` 增加项目报告字段；历史报告保留原数据。
3. 为 `practice_grade_rule` 初始化默认三项权重，按现有项目同步子项。
4. 初始化归档表和归档菜单。
5. 旧菜单软删除或改名，不删除业务数据和接口方法。
6. 前端构建产物同步到 `server/public/pc` 和 `server/public/h5`。

## 9. 并发与审计

- 保存、提交、审核、通过后修改和归档均使用现有 Redis 锁与数据库事务。
- 按开课任务、项目或材料 ID 加锁，防止教师和审核人同时更新。
- 所有状态变化写入 `recording`；审核处理写入 `review_opinion`；操作日志记录业务动作名称、接口、账号、角色和数据 ID。
- 审核人执行范围由服务端 Model 方法判定，任何前端隐藏都不作为权限依据。
