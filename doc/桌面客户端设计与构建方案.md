# 桌面客户端设计与构建方案

日期：2026-09-09

## 接入方式

采用 Tauri 2 + Rust，新增独立目录 `fontend/desktop`。按用户确认的方向，把 `fontend/pc` 的同一份 Vue 源码编译进客户端，接口调用用户所填学校服务器。启动时提供学校域名输入，默认建议为 `sx.2iwm.com`，成功连接后记住地址；可从连接设置选择其他学校。

保留当前 PHP/Webman 默认路由、学校域名识别、Cookie 登录、角色权限和文件授权。用户使用现有账号登录；服务器不可达时提供重新连接和连接设置入口。首版需要网络，不提供离线业务提交。

服务器当前将 JWT 和刷新令牌写入 HttpOnly、SameSite=Lax 的 Cookie，登录接口并不把 JWT 返回给 Vue。客户端由 Rust 的 reqwest Cookie 容器管理每所学校的登录会话，通过仅监听 `127.0.0.1` 的本机通道转发 `/api/` 与 `/files/`。安装包中的 Vue 页面、图片和附件使用同源地址，避免修改服务器 Cookie/CORS 或把令牌交给前端脚本。

本机通道使用随机会话密钥、HttpOnly Cookie、Host 校验和 Origin 校验，不接受其他网页的跨站访问，不监听局域网；请求固定转发到用户选择的学校，不提供任意网址代理。学校 JWT 不落盘，关闭学校窗口或退出应用后结束该会话，重新打开需要登录。每所学校记录独立本机端口，端口占用时自动选择可用端口。学校域名、学校名称和端口保存在本机配置文件中。

客户端不保存数据库、Redis 或服务端密钥，不实现额外业务逻辑。PC UI 更新需要重新构建客户端；服务器接口更新应保持对已发布客户端版本的兼容性。

## 客户端能力

- 使用系统原生窗口，支持调整大小、最大化、最小化、关闭和缩放。
- 提供重新加载、前进、后退、连接设置和版本信息。
- 普通窗口跳转限于当前学校和本机会话地址，站外 HTTP/HTTPS 链接使用系统浏览器打开。
- 学校附件、新窗口预览和打印窗口沿用客户端登录会话；不把需要鉴权的站内文件直接交给未登录的系统浏览器。
- 文件下载使用独立临时缓存，完成后弹出系统“另存为”选择目录及文件名；同一窗口同一文件在下载期间禁止重复发起。保存或取消后自动释放本次生成的缓存，保留网页现有上传入口。
- 剪贴板和打印优先使用 WebView/系统现有能力；不向远程业务页面开放任意文件读写、命令执行或 Rust 调用权限。
- 连接设置保存在本机应用配置目录，仅记录学校访问地址等客户端设置。
- 切换学校前确认并关闭当前学校窗口，避免在两个学校间误操作。每次学校连接新建独立 Rust Cookie 容器。
- 默认使用 HTTPS；HTTP 仅用于本机开发地址。生产环境不跳过证书校验。

## 构建产物

| 平台 | 构建位置 | 产物 |
| --- | --- | --- |
| macOS Apple Silicon | 当前 Mac | `.app`、`.dmg` |
| macOS Intel / Apple Silicon 通用 | 当前 Mac | 双架构 `.app`、通用 `.dmg` |
| Windows x64 | GitHub Actions | NSIS `.exe` 安装程序 |
| Linux x64 | GitHub Actions | `.deb`、`.AppImage` |

Windows 使用 WebView2，Linux 使用 WebKitGTK，macOS 使用系统 WKWebView。Windows/Linux 的构建产物放在 GitHub Actions Artifacts，不默认创建公开 Release。

GitHub 构建仓库由用户指定为 `https://github.com/isle24/practicalSystem`，使用私有仓库。Gitea `origin` 继续保存完整项目；GitHub `main` 仅同步 PC 前端、客户端、相关说明和构建工作流，不复制后端、学校业务文档或项目历史。

首版可以先生成未签名安装包。正式对外分发的 Apple Developer 签名/公证及 Windows 签名证书需要另行配置，未提供证书时不宣称安装包已签名。

## 鸿蒙边界

Tauri 官方目前支持 macOS、Windows、Linux、Android 和 iOS，不包含 HarmonyOS NEXT。原生鸿蒙客户端需要独立的 ArkTS + ArkWeb 工程，适合复用当前 H5 页面，不能把 Android APK 作为 HarmonyOS NEXT 原生包交付。本次先完成三种桌面平台的代码和构建配置。

## 交付方式

源码、锁文件、构建工作流和使用说明提交到项目主分支；Rust `target`、本机配置和安装包不放入 Git。Mac 安装包提供本机文件路径；Windows/Linux 仅在 GitHub 工作流实际运行成功后提供已完成产物。

构建及运行核对覆盖窗口启动、学校登录页面、连接失败反馈、窗口导航、文件预览/下载和打印兼容性。尚未实际完成的跨平台运行、账号登录或签名环节在交付时明确列出。
