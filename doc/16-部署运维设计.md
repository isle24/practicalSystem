# 部署运维设计

## 1. 部署架构

```
                              ┌──────────────┐
                              │   CDN / DNS   │
                              └──────┬───────┘
                                     │
                              ┌──────▼───────┐
                              │    Nginx      │
                              │  (反向代理)    │
                              └──────┬───────┘
                                     │
              ┌──────────────────────┼──────────────────────┐
              │                      │                      │
     ┌───────▼───────┐    ┌────────▼────────┐    ┌────────▼────────┐
     │  Webman 8080  │    │  Webman 8081     │    │  Webman 8082     │
     │  (worker×N)   │    │  (worker×N)      │    │  (worker×N)      │
     └───────┬───────┘    └────────┬────────┘    └────────┬────────┘
              │                      │                      │
              └──────────────────────┼──────────────────────┘
                                     │
                    ┌────────────────┼────────────────┐
                    │                │                │
           ┌───────▼───────┐ ┌──────▼──────┐ ┌───────▼───────┐
           │  MySQL 3306   │ │  Redis 6379 │ │  public/files  │
           │  (主库+N租户)  │ │  (缓存+队列) │ │  (Nginx 直链)  │
           └───────────────┘ └─────────────┘ └───────────────┘

  N = CPU 核数 × 2~4，默认可设为 cpu cores × 2
```

## 3. Nginx 配置

### 3.1 反向代理

```nginx
upstream webman {
    # 单实例部署只保留 8080；多实例部署时再增加 8081/8082
    server 127.0.0.1:8080;
    # server 127.0.0.1:8081;
    # server 127.0.0.1:8082;
    # 多实例时每个实例需使用独立端口和独立 worker 数配置
    # server 127.0.0.1:8083;
    # ...
    keepalive 64;
}

server {
    listen 443 ssl http2;
    server_name ~^(?<subdomain>.+)\.practical\.com$ practical.com;

    ssl_certificate     /etc/nginx/ssl/practical.crt;
    ssl_certificate_key /etc/nginx/ssl/practical.key;

    root /path/to/server/public;

    # H5 / PC 静态资源
    location /h5/ {
        try_files $uri /h5/index.html;
        expires 7d;
    }
    location /pc/ {
        try_files $uri /pc/index.html;
        expires 7d;
    }

    # 上传/导出文件 — 支持多盘扩容
    location /files/ {
        alias /mnt/disk1/public/files/;
        try_files $uri @disk2;
        expires 1h;
    }
    location @disk2 {
        alias /mnt/disk2/public/files/;
        expires 1h;
    }

    # API 路由 → Webman
    location /api/ {
        proxy_pass http://webman;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 默认跳转（UA 判断由 Webman 处理）
    location / {
        proxy_pass http://webman;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### 3.2 静态资源配置（直接 URL 下载 + 改名下载）

## 4. Webman 进程管理

### 4.1 启动命令

```bash
# 启动（debug 模式）
php start.php start

# 生产环境（daemon）
php start.php start -d

# 重启
php start.php restart -d

# 平滑重启（不中断服务）
php start.php reload
```

### 4.2 进程配置（config/process.php）

```php
return [
    'count' => cpu_count() * 4,  // webman 默认配置，16 核 → 64 worker
    'max_request' => 0,           // 不限制请求数（常驻进程）
];
```

**worker 数选择：**

| 服务器核数 | worker 建议范围 | 适用场景 |
|---|---|---|
| 4 核 | 8-16 | 小型部署（< 5 个学校） |
| 8 核 | 16-32 | 中型部署（5-20 个学校） |
| 16 核 | 32-64 | 大型部署（> 20 个学校） |

**worker 数与 MySQL 连接容量联动：** worker 数越多，每个 worker 的租户连接管理器 `globalMaxSize` 自动调小（由公式 `max(3, floor(mysql_max_connections × 0.7 / worker_count) - 1)` 计算），确保总连接数不超出 MySQL 上限。多实例部署时 `worker_count` 必须按所有实例 worker 总数计算。详见 `00-总体架构设计.md` 3.4 节。

环境变量：

```bash
# server/.env（部署时从 .env.example 复制）

# === 数据库 ===
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASS=
DB_NAME=practical_master

# === Redis ===
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASS=

# === 租户连接管理 ===
SERVER_WORKER_COUNT=64      # webman worker 数（由 config/process.php 的 cpu_count()*4 自动计算，此处仅用于 TenantConnectionManager 公式）
DB_MAX_CONNECTIONS=500     # MySQL max_connections 配置值

# === 加密密钥（用于敏感配置加密存储，AES-256-GCM）===
# 生成方式：php -r "echo bin2hex(random_bytes(32));"
APP_CONFIG_KEY=            # 64 字符 hex，部署时必须手动设置

# === 应用 ===
APP_DEBUG=false
APP_URL=https://xxx.com

# === 企业微信 ===
WECHAT_CORP_ID=
WECHAT_AGENT_ID=
WECHAT_SECRET=
WECHAT_TOKEN=
WECHAT_AES_KEY=

# === JWT（配置在 config/plugin/tinywan/jwt/app.php，不在 .env）===
# 部署时修改插件配置文件中的 secret、ttl 等参数

# === 文件存储 ===
FILE_BLOCK=b1               # 存储块标识
FILE_SECURE_LINK_SECRET=    # Nginx secure_link 密钥，部署时生成
```

### 4.3 端口分配

| 端口 | worker 数 | 用途 |
|---|---|---|
| 8080 | 按 config/process.php | 默认 HTTP 服务 |
| 8081 | 独立实例配置 | 备选（多端口部署，nginx upstream） |
| 8082 | 独立实例配置 | 备选 |

### 4.4 健康检查

```
GET /api/health
→ 200 { "status": "ok", "time": "2026-05-27 10:00:00" }
```

Nginx 健康检查配置：

```nginx
upstream webman {
    server 127.0.0.1:8080 max_fails=3 fail_timeout=30s;
    # server 127.0.0.1:8081 max_fails=3 fail_timeout=30s;
    # server 127.0.0.1:8082 max_fails=3 fail_timeout=30s;
}
```

**worker 数：** `config/process.php` 中 `count = cpu_count() * 4`。16 核服务器自动生成 64 个 worker，无需手动修改。该值也会被 `TenantConnectionManager` 用于 `globalMaxSize` 计算。多实例部署时需降低单实例 count，避免总 worker 数和 MySQL 连接数超出容量。

## 6. 日志管理

### 6.1 Webman 运行日志

```
server/runtime/logs/
  ├── webman.log      框架运行日志
  ├── error.log        错误日志
  └── access.log       访问日志
```

### 6.2 日志轮转（logrotate）

```
/path/to/server/runtime/logs/*.log {
    daily
    rotate 30
    compress
    delaycompress
    missingok
    notifempty
    create 0644 www-data www-data
}
```

### 6.3 业务操作日志

按月分表（operation_log_YYYYMM），不自动清理。仅超级管理员可手动删除指定时间段日志。

## 7. 监控告警

### 7.1 监控指标

| 指标 | 工具 | 告警阈值 |
|---|---|---|
| Webman 进程存活 | systemd / supervisor | 进程退出 |
| HTTP 响应时间 | Nginx 日志分析 | > 3s |
| 错误率 | Nginx 5xx 比率 | > 1% |
| MySQL 连接数 | SHOW PROCESSLIST | > 80% 上限 |
| Redis 内存 | INFO memory | > 80% maxmemory |
| 磁盘使用率 | df -h | > 85% |
| JWT 异常失败率 | 业务日志统计 | 单 IP > 50/min |

### 7.2 告警通知

- 关键告警（进程退出、DB 不可用）→ 企业微信通知超级管理员
- 非关键告警 → 邮件通知
- 告警收敛：相同告警 5 分钟内不重复发送

## 8. 新建学校流程

```
1. 超级管理员 PC 端操作
2. 填写学校信息 → 写入主库 schools
3. 配置数据库连接 → 写入主库 databases
4. 点击"创建学校"
   → CREATE DATABASE {databases.database_db}
   → 从 practical_template 导出结构与种子数据后导入新库，或执行租户 migration + seed
   → 校验表结构版本、默认角色、默认菜单、默认配置项完整
5. 配置域名绑定 → 写入主库 authorizations
6. 清除 Redis tenant:domain:{domain} 缓存
7. 学校管理员即可登录
```
