# 教师导入与账号开通

## 已确认规则

- 教师模板沿用附件的 39 列，支持 xls、xlsx；工号作为登录名，新账号初始密码为工号加 `666`。
- 教务学生档案增加“一键导入用户”，管理员填写本批新账号统一初始密码。
- 关联现有学生和教师档案，不重复创建档案；已有账号保留密码、绑定、启停状态。编号、角色或归属冲突单独报告。
- 仅超级管理员、学校管理员可批量开通账号；学院和专业管理员不扩展账号写权限。
- 企业微信“允许未绑定登录”默认关闭，教师和学生须绑定当前企业后才能访问业务；管理员豁免。
- 账号密码验证后允许进入受限绑定会话，避免无法登录就无法绑定。普通网页和客户端引导在企业微信里登录同一账号绑定，回原端重新检查。
- 附件只作为模板依据，不自动将其中的真实教师写入业务库。

## 实施

- [x] `TeacherImportReader`：分块读取、校验原表头、保留工号前导零、生成空白模板。
- [x] `ProfileAccountRecord`：锁定现有档案，复用用户、账号和角色底层方法，创建或关联账号。
- [x] `AccountImportRecord`、`AccountImportService`、`AccountImportController`：预览、排队、任务查询与重试。学生任务固定源数据编号，初始密码只保存 bcrypt 散列，不写入队列、日志或响应，完成后清除任务中的散列。
- [x] `AccountImportConsumer`：每批最多 25 条，任务进度与账号写入同事务，重复消费不重复开通；单行冲突不中止其他行。
- [x] `account_import_task` 纳入学校初始化、升级 SQL 和数据库结构基准。
- [x] PC 用户管理增加教师导入、学生开通入口；教务学生数据页增加一键导入用户，展示数量、任务进度和错误。
- [x] 企业微信配置、服务端中间件和 PC/H5 绑定弹层使用同一策略；允许未绑定时仍提供主动绑定入口。
- [x] PHP 语法、前端构建、模板只读解析与页面入口核验；未写入实际教师/学生数据。

## 数据映射

工号、姓名、部门、性别、出生日期、职称、学历、联系电话、邮箱、教职工类别映射至现有教师档案。手机号码优先于联系电话。原表“专业名称”是教师个人专业信息，不作为系统按年级划分的任教专业。其他列保留在受权限保护的原始导入文件中，不修改现有组织档案。

部门必须与学校已有部门名称对应；错误行给出行号和字段原因。批量结果最多返回 50 条错误明细。

## 接口

统一使用 `/api/account-import/` 显式路由：`tasks`、`detail`、`teacher-template` 为 GET；`teacher-preview`、`teacher-start`、`student-preview`、`student-start`、`retry` 为 POST。任务队列只携带学校数据库编号和任务编号。

## 使用入口

1. 用户管理 → 导入教师：下载空模板或上传现有 39 列教师表，预览无格式、重复工号及学院错误后确认排队。
2. 用户管理 → 学生导入用户，或教务数据 → 学生数据 → 一键导入用户：检查全校已发布有效学生数量，填写统一初始密码，确认排队。登录名为学号。
3. 企业微信配置 → 允许未绑定企业微信登录：默认关闭，仅学校管理员和超级管理员可修改。

最近 30 次任务可查看新增、关联、更新、跳过和失败数量。执行失败或超过 5 分钟未推进可重新排队，按已提交进度继续。已完成但存在行冲突的任务，修正数据后重新导入；不重置已有密码。

## 部署

拉取代码后，先在系统配置的数据库结构检查中比较学校库，生成并审阅升级 SQL；本次新增 `account_import_task`，已包含在完整结构基准。也可单独执行 `server/database/updates/20260923-account-import.sql`。本次未自动修改实际学校库。

升级后重启 Webman 及 Redis 队列消费者，使显式路由、新的 `account_import` 消费者和企业微信访问策略生效。PC/H5 使用本次构建产物。未重新发布客户端安装包或修改 v0.3.6 标签。

结构基准在独立本机 MySQL 8.4 中生成，包含主库 3 表、学校库 194 表，生成后停止该临时实例。
