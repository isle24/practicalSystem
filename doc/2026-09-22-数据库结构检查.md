# 数据库结构检查

- [x] 建立当前代码的结构基准：使用本机隔离 MySQL 空库复用初始化定义，补齐运行时定义，记录来源文件摘要；月份日志和年份归档采用表族模板。
- [x] 实现只读结构读取与比较：查询 MySQL 元数据，比较表、字段和索引；生成新增语句，将定义变更和唯一约束语句列为人工审核项，不删除额外对象。
- [x] 增加框架路由及管理员接口：学校管理员检查当前学校库，超级管理员可额外检查主库；校验 `config:manage`，拒绝任意连接参数。
- [x] 增加“系统配置 → 数据库结构”：检查、差异列表、SQL 预览和下载，切换学校、账号或角色后清除结果。

后端位于 `server/app/server/database`、`server/app/controller/Api/DatabaseSchemaController.php`；前端位于 `fontend/pc/src/components/DatabaseSchemaPanel.vue`。

后台不运行初始化、迁移或升级 SQL。生成的 SQL 仅针对本次检查的数据库结构；数据修复和历史数据迁移仍按版本升级说明执行。

## 使用

管理员进入“系统配置 → 数据库结构”，选择范围后点击“检查结构”。报告可预览和下载 SQL。应用此功能无需先执行迁移，部署代码后重载 Webman 并刷新 PC 页面即可。

- “可新增”：缺表、允许空值或具有默认值的普通字段、普通索引。
- “需人工确认”：已有字段定义变更、必填且无默认值的字段、唯一/主键约束、索引替换和表默认规则。SQL 已注释，审核数据后逐项处理。
- “保留现状”：额外表、字段、索引和约束，不生成删除语句。仅索引名称不同但定义等价时视为一致。

执行 SQL 前备份目标库；执行后重新检查。文件中的 `USE` 已指定本次检查的数据库，不能直接用于其他学校。字段顺序、注释、自增计数不参与比较；历史数据内容、视图、触发器和存储过程不在检查范围内。当前基准面向无表前缀的 MySQL 8.0 及以上数据库。

接口为 `GET /api/config/database-schema/options`、`POST /api/config/database-schema/check`，请求体为 `{"target":"school"}` 或 `{"target":"master"}`。身份和范围仅从服务端登录上下文确定。检查请求跳过认证过程中的消息结构初始化；审计仅写入已存在的日志表，不创建月表。登录过期时需重新登录，不在检查请求中自动刷新会话。

## 基准维护

`server/database/schema-baseline.json` 随代码部署，包含主库 3 张表、学校库 191 张表和 2 个日期表族。结构来自初始化及其复用的模型 DDL；`recording_archive_YYYY` 以初始化定义为准，历史变体的字段差异进入人工审核。表默认排序规则由 MySQL 8.4 生成，当前为 `utf8mb4_0900_ai_ci`。

修改初始化、结构模型、升级 SQL 或迁移后，开发阶段使用专用本机 MySQL 8.4 实例重新构建基准并一同提交。构建器不加载业务 `.env`，只接受本机地址，创建随机命名的空库并在结束后清理；不要把端口指向业务库或业务库隧道。

在已启动的本机临时实例上，从仓库根目录运行：

```sh
SCHEMA_BUILD_HOST=127.0.0.1 SCHEMA_BUILD_PORT=33384 SCHEMA_BUILD_USER=root SCHEMA_BUILD_PASS='' php server/database/build-schema-baseline.php
```

检查接口会核对来源摘要，发现缺文件、来源变更或新增升级文件时拒绝比较，避免使用过期基准。它不会读取可能同样漏升级的学校模板库作为标准。
