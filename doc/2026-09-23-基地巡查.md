# 基地巡查

## 字段与流程

按《实习基地走访时间安排》保留负责人、联系电话、所在部门、基地学院、基地名称、地址、类型、位置、走访日期、上午/下午、开始及可选结束时间。填写时间由系统记录。附件报表作为字段参考，不自动导入其中的人员和安排。

管理员指定基地、负责教师和走访事项，教师填写时间；状态为待填时间、已安排、已完成、已取消。同校同一天同一上午或下午存在其他安排时提示重复，仍允许保存。时段按开始时间归类，结束时间可跨午，不作为精确时间重叠检测。负责人可修改尚未完成的时间，管理员可取消未完成安排。

每个安排关联一份走访记录，保存实际时间、参加人员、接待人员、走访内容、问题、后续措施和附件。保存记录后安排变为已完成，记录允许原负责人和范围内管理员修订；操作日志保留变更行为。

## 接入与边界

- PC：基地管理 → 基地巡查，教师另有独立基地巡查入口；手机端：首页常用服务 → 基地走访。
- 教师仅查询和填写本人安排；学校管理员管理本学校，学院/专业管理员沿用已授权组织范围。学生和企业角色不可访问。
- 独立 `base_visit_plan`、`base_visit_record`，不复用学生材料抽检的 `inspection_record`。
- 复用学校数据库、教师档案、基地档案、附件权限和操作日志；框架显式路由提供列表、选项、详情、安排、时间、记录及取消接口。
- 修改时使用版本号和事务行锁，防止覆盖他人已保存的内容；已完成安排不再修改负责人及计划时间。
- 新表纳入初始化、独立升级 SQL 和数据库结构基准。后台缺表时提示先升级，不在页面请求中自动建表。

## 实施

1. 后端：`BaseVisitRecord`、`BaseVisitService`、`BaseVisitController` 和学校库 DDL。
2. PC：独立 `BaseVisitPanel.vue`，复用列表、弹窗和附件接口。
3. H5：独立 `BaseVisitPanel.vue`，提供本人列表、时间填写、记录录入和详情。
4. 更新数据库结构基准，完成 PHP 语法、PC/H5 构建及页面核验后提交。

## 部署

1. 更新代码和 `server/public/pc`、`server/public/h5` 发布产物。
2. 管理员进入“系统配置 → 数据库结构”，选择学校数据库，检查并生成升级 SQL，由维护人员执行确认后的 SQL。
3. 本次新增结构见 `server/database/updates/20260923-base-visit.sql`，仅作用于学校业务库。也可在 `server` 目录按学校数据库编号执行 `php database/migrations/20260923_base_visit.php 编号`；编号来自学校数据库配置，不是学院编号。
4. 重载 Webman，刷新 PC、H5 页面。管理员新增安排并指定已有基地和教师，教师在本人入口填写时间，走访后填写记录。

本轮未执行业务库升级，未导入附件报表的实际数据。现有学校库需完成第 2 或第 3 步后才能保存安排。
