# 配置模块设计

## 1. 数据模型

```
config_group（配置分组，树形层级）
  - id, parent_id
  - code（唯一标识，如 internship）
  - name（如"实习管理"）
  - sort, status
  - created_at, updated_at, deleted_at

config_item（配置项，三级覆盖）
  - id, group_id
  - key（如 sign_in_radius）
  - value（JSON，支持字符串/数组/对象）
  - college_id（0=全局，>0=学院级）
  - user_id（0=全局，>0=个人级，关联 users.id）
  - description（配置说明，管理界面作为 tooltip 展示）
  - sort, status
  - created_at, updated_at, deleted_at
```

**敏感配置存储：** 含 `_key`、`_secret`、`_pwd` 后缀的配置项（企业微信 secret、教务 API key、AI api_key 等）以明文存储，由管理员在配置界面维护。安全依赖数据库访问控制与租户库物理隔离，应用层不做加解密。

## 2. 三级层级覆盖

优先级：**个人 > 学院 > 系统默认**

```
ConfigService::get('group.key', $collegeId = 0, $userId = 0)

查找顺序：
  1. user_id=$userId, college_id=0  → 个人覆盖
  2. college_id=$collegeId, user_id=0  → 学院覆盖
  3. college_id=0, user_id=0  → 系统默认
  4. 都没查到 → null
```

强制读取某一级：

```php
ConfigService::get('group.key', force: 'system')   // 只看系统默认
ConfigService::get('group.key', force: 'college')  // 只看学院级
ConfigService::get('group.key', force: 'user')     // 只看个人级
```

## 3. 查询与缓存

### 3.1 单次查询（避免逐级查库）

三级覆盖通过一条 SQL 完成，按优先级排序取第一条：

```sql
SELECT value FROM config_item
WHERE group_id = ? AND key = ?
  AND (college_id = ? OR college_id = 0)
  AND (user_id = ? OR user_id = 0)
ORDER BY user_id DESC, college_id DESC
LIMIT 1
```

优先级顺序由 `ORDER BY user_id DESC, college_id DESC` 保证：非零值排前面，user 优先于 college，college 优先于 school。

### 3.2 三级缓存策略

```
L1 — 进程内存（webman 常驻进程，无需每次读 Redis）
    Key: config:{database_id}:{college_id}:{user_id}
    Value: 该上下文下所有配置项的 Hash
    生命周期：进程重启或主动刷新

L2 — Redis Hash
    Key: config:ctx:{database_id}:{college_id}:{user_id}
    Field: {group}.{key}
    Value: JSON
    TTL: 3600（1小时）

L3 — DB
    上述单次 SQL 查询
```

### 3.3 缓存流程

```
ConfigService::get('internship.sign_in_radius', $databaseId, $collegeId, $userId)

  1. 查 L1 内存 → 命中且未过期（TTL 30s）→ 直接返回
  2. 查 L2 Redis Hash → 命中写入 L1（含过期时间戳）并返回
  3. 查 DB（单次 SQL）→ 写入 L2 + L1 → 返回
```

**L1 一致性保证：** L1 内存缓存设置 30 秒短 TTL，过期后自动回源 L2 Redis 校验。配置变更时清除 L2 Redis 即可，无需依赖进程间广播。最坏情况下配置变更后 30 秒内部分进程读到旧值，对于配置类数据可接受。若需即时生效，可结合 Redis pub/sub 广播清除 L1，但 L1 TTL 作为兜底保障。

### 3.4 上下文批量预热

用户登录后，异步预加载该用户所在上下文的所有配置到 Redis：

```
POST /api/user/profile 返回后
  → 入 Redis 队列
  → ConfigService::warmUp($databaseId, $collegeId, $userId)
  → 一次 SQL 查出该上下文所有配置（含继承值）
  → 批量写入 Redis Hash
```

首次页面加载即可命中缓存，后续请求走 L1 内存。

### 3.5 缓存失效

```
配置变更时：
  1. 清除受影响的 L2 Redis key
     config:ctx:{database_id}:*:*            （系统默认变更时）
     config:ctx:{database_id}:{college_id}:* （学院级变更时）
     config:ctx:{database_id}:*:{user_id}    （个人级变更时）
  2. L1 内存缓存最长 30 秒后自动过期回源，无需手动清除
  3. 可选：通过 Redis pub/sub 广播清除 L1，实现即时生效
```

## 4. 适用场景

| 层级 | 示例 |
|---|---|
| 系统默认 | sign_in_radius=500 |
| 学院级 | 计算机学院 sign_in_radius=200 |
| 个人级 | 教师张三 max_student_count=5 |

个人级典型用途：
- 某教师的最大指导学生数不同于学院默认
- 某学生的签到免审（特殊需求学生）
- 个人通知偏好（是否接收企微推送）

## 5. 预期配置项

```
internship:
  ├── material_type         实习材料类型（数组）
  ├── pair_mode             配对模式（admin_assign / student_choose / teacher_enroll）
  ├── selection_start       选导师开始时间
  ├── selection_end         选导师截止时间
  ├── teacher_review_timeout 教师审核超时（小时，默认 48）
  ├── max_volunteers        学生最大志愿数（默认 3）
  ├── sign_in_radius        GPS签到半径（米）
  ├── sign_in_time_range    签到时间段
  ├── journal_frequency     日志频率（daily/weekly）
  ├── qrcode_expire         二维码有效期（秒）
  ├── report_deadline       报告截止时间
  ├── sign_in_weight        签到成绩权重（默认值）
  ├── journal_weight        日志成绩权重
  ├── report_weight         报告成绩权重
  └── max_student_count     教师最大指导学生数（系统/学院级默认值）

training:
  ├── booking_max_days      最长预约天数
  └── room_capacity_alert   容量预警阈值

lab:
  ├── booking_max_days      最长预约天数
  └── project_status_flow   项目状态流转配置

system:
  ├── theme                 默认主题
  ├── font_size             默认字体
  ├── file_retention_days   导出文件保留天数
  ├── file_block            存储块标识（默认 b1，多盘扩容时修改）
  └── impersonate_ttl       模拟登录链接有效期（秒，默认 300）

file:
  └── instant_upload_enabled 秒传开关（默认 false，管理员开启后 /api/file/check 生效）

edu:
  ├── adapter               适配器（zhengfang / qiangzhi / custom）
  ├── api_base_url          教务系统 API 地址
  ├── api_key               API 密钥
  ├── auth_enabled          是否启用教务统一登录（默认 false）
  ├── sync_mode             同步模式（pull 定时拉取 / push 对方推送）
  ├── sync_interval         定时拉取间隔（小时，0=仅手动）
  ├── sync_entities         同步实体范围
  └── push_secret           推送验证密钥（push 模式用）

ai:
  ├── provider              LLM 服务商（openai / qwen / deepseek / local）
  ├── api_base_url          API 地址
  ├── api_key               API 密钥
  ├── model                 模型名称（如 gpt-4o / qwen-max）
  ├── system_prompt         系统提示词（审核评阅场景）
  ├── max_tokens            最大输出 token
  └── temperature            温度参数（0-1，默认 0.3，偏严谨）

user:
  ├── wechat_notify         是否接收企微推送（个人级）
  ├── sign_in_exempt        签到免审标记（个人级）
  ├── api_key_enabled       是否允许创建 API Key（个人级，默认 false，管理员开启）
  └── max_student_count     最大指导学生数（教师个人级覆盖，优先级高于 internship.max_student_count）
```

> **max_student_count 与 grade_teacher_guide 的关系：** `internship.max_student_count` 为系统/学院级默认上限，`user.max_student_count` 为教师个人级覆盖（三级覆盖机制）。`grade_teacher_guide.max_choose_number` 是实际控制教师在某年级/院系下可指导人数的运行时字段，其初始值取配置项的最终解析值。配置项定义上限，grade_teacher_guide 执行限额。

## 6. 管理界面（PC 端）

- 分组管理：树形列表，增删改查
- 配置项管理：按分组查看，三级覆盖值并列显示
  - 系统默认值编辑（超级管理员）
  - 学院覆盖值编辑（学院管理员，可 override 系统默认）
  - 个人覆盖值编辑（管理员对特定用户设置例外）
- 每个覆盖层级独立开关：开启则覆盖上级，关闭则继承上级
- 导入/导出

### 6.1 配置项 Tooltip

每个配置项名称右侧显示 `?` 图标，鼠标悬停弹出 tooltip 展示 `description` 字段内容：

```
┌──────────────────────────────────────────────────────┐
│  签到半径  ?   [500] 米                               │
│            ┌─────────────────────────────────┐       │
│            │ 学生 GPS 签到时，距离实习基地的    │       │
│            │ 最大允许距离（米）。超出此范围签   │       │
│            │ 到将标记为异常签到。              │       │
│            └─────────────────────────────────┘       │
│                                                      │
│  二维码有效期  ?   [300] 秒                            │
│            ┌─────────────────────────────────┐       │
│            │ 签到二维码的有效时间。过期后需    │       │
│            │ 教师/管理员重新生成。默认 5 分钟  │       │
│            └─────────────────────────────────┘       │
└──────────────────────────────────────────────────────┘
```

- tooltip 内容从 `config_item.description` 字段读取
- 新增/编辑配置项时必须填写 description
- 系统预置配置项附带默认 description，管理员可修改
